# 사용 시나리오

소프트웨어 프로젝트 계획 수립 및 제어 시뮬레이터(Electron 로컬 앱)의 사용 시나리오.
근거 문서: `docs/ref` (Madachy, *Software Process Dynamics*, 2008).

## 1. 대상 사용자(액터)

| 액터 | 설명 | 주요 목적 |
|---|---|---|
| 프로젝트 관리자(PM) | 일정·비용·인력을 계획하고 수행 중 통제하는 사람 | 계획 수립, 정책 비교, 진척 통제 |
| 프로세스/품질 담당자 | 프로세스 개선, 인스펙션 등 품질 활동을 설계하는 사람 | 프로세스 정책의 효과 분석 |
| 교육 대상자/학습자 | SD와 프로젝트 역학(Brooks 법칙 등)을 학습하는 사람 | 예제 모델 실행과 실험 |
| 모델러(후순위) | 조직 데이터로 모델을 보정·확장하는 사람 | 모델 구조·파라미터 편집, 검증 |

## 2. 범위 단계

기능 단계는 [02.기능목록.md](02.기능목록.md)의 MVP / 2차 / 3차 / 4차와 같다. 각 시나리오에 해당 단계를 표시한다.

## 4. 시나리오 상세

### SC-01. 새 프로젝트를 만들고 초기 계획을 시뮬레이션한다 (MVP)

- **액터**: PM
- **사전 조건**: 앱 설치 완료. 프로젝트 파일이 없어도 된다.
- **기본 흐름**
  1. 홈 화면에서 "새 프로젝트"를 선택한다.
  2. 프로젝트 설정 화면에서 규모(태스크 수 또는 SLOC), 목표 일정, 예산, 가용 인력을 입력한다.
  3. 프로세스 옵션(인스펙션 사용 여부, 재사용 비율, 요구사항 변동률)과 조직 특성(신입/숙련 비율, 이직률, 채용 지연)을 설정한다. 입력하지 않은 항목은 기본값을 쓴다.
  4. 모델로 "통합 프로젝트 모델"을 선택한다.
  5. "실행"을 누르면 시뮬레이션이 진행되고 주요 변수(인력, 잔여 태스크, 누적 공수, 결함)가 실시간 그래프로 표시된다.
  6. 종료 후 예상 완료일, 총 공수, 결함 수, 목표 대비 편차 요약이 표시된다.
  7. 프로젝트를 파일로 저장한다.
- **대안 흐름**
  - 3a. 입력값이 허용 범위를 벗어나면 필드에 오류를 표시하고 실행을 막는다.
  - 5a. 사용자가 일시정지, 스텝, 리셋을 사용한다.
- **사후 조건**: 입력값과 결과가 프로젝트 파일에 저장된다.

### SC-02. Brooks 법칙 예제로 늦은 인력 투입 효과를 학습한다 (MVP)

- **액터**: 학습자, PM
- **기본 흐름**
  1. 홈 화면의 예제 목록에서 "Brooks 법칙"을 연다.
  2. 인력 추가 시점과 추가 인원 수를 조절한다.
  3. 실행하면 인력 추가 없는 경우와 추가한 경우의 완료 시점이 같은 그래프에 겹쳐 표시된다.
  4. 사용자는 늦게 투입할수록 일정이 오히려 늘어나는 구간(교육·소통 오버헤드)을 확인한다.
- **사후 조건**: 예제는 읽기 전용 원본으로 유지되고, 변경은 복사본에 저장한다.

### SC-03. 시뮬레이션 결과를 확인하고 내보낸다 (MVP)

- **액터**: PM
- **기본 흐름**
  1. 결과 뷰어에서 변수를 선택해 시계열 그래프로 본다.
  2. 여러 변수를 겹쳐 보고 확대·구간 선택을 한다.
  3. 데이터 표로 전환해 값을 확인한다.
  4. CSV 또는 이미지로 내보낸다.
- **대안 흐름**: 기준 행동(Reference behavior) 데이터를 가져와 함께 표시한다.

### SC-04. 정책 대안을 시나리오로 비교한다 (2차)

- **액터**: PM, 프로세스 담당자
- **사전 조건**: 기준 시나리오가 한 번 이상 실행된 프로젝트.
- **기본 흐름**
  1. 기준 시나리오를 복제해 "인스펙션 도입", "야근 상한 제한", "인력 조기 투입" 같은 대안을 만든다.
  2. 대안별로 변경한 파라미터만 수정한다.
  3. 각 시나리오를 실행한다.
  4. 비교 화면에서 일정, 비용, 품질(잔존 결함), 위험 지표를 표와 차트로 나란히 본다.
  5. 선택한 시나리오를 "채택 계획"으로 지정한다.
- **사후 조건**: 채택 계획이 이후 통제(SC-05)의 기준선(PV)이 된다. PV는 채택한 시나리오의 시뮬레이션 곡선이며, 채택 시점에 스냅샷으로 저장되어 이후 시나리오를 고쳐도 바뀌지 않는다. 실제 계획 곡선(CSV)을 PV로 쓰는 것은 후속이다.

### SC-05. 수행 중 실적을 입력해 Earned Value로 통제한다 (2차)

- **액터**: PM
- **사전 조건**: 채택 계획이 지정되어 있다.
- **기본 흐름**
  1. 제어 화면에서 보고일마다 단계별 누적 완료 태스크와 누적 투입 공수를 입력한다(투입 인원, 누적 발견 결함은 선택).
  2. 대시보드가 PV, EV, AC 곡선과 CPI, SPI, 일정·비용 편차를 갱신한다.
  3. 임계값(예: SPI < 0.9)을 넘으면 경고가 표시된다.
- **대안 흐름**
  - 실적 CSV를 일괄 가져온다.
  - 과거 보고일을 골라 그 시점의 지표를 본다(추세의 기울기 읽기).

### SC-06. 실적 기반 재예측과 시정 조치 효과를 시험한다 (2차)

- **액터**: PM
- **사전 조건**: SC-05에서 실적이 일부 입력된 상태.
- **기본 흐름**
  1. "재예측"을 선택하면 현재 실적으로 모델 상태를 보정해 완료일과 비용(EAC, ETC)을 다시 계산한다. 결과는 "추정"과 범위로 표시한다.
  2. 일정 지연이 예상되면 시정 조치 후보(인력 보강, 야근 허용 확대, QA 축소)를 선택한다. 범위 축소는 후속이다.
  3. 각 후보를 현재 시점부터 시뮬레이션해 완료일·비용·품질 변화를 비교한다.
  4. 조치를 선택하고 사유를 입력하면 계획 개정본이 새 기준선이 되고 이력이 남는다. 이전 기준선은 보존된다.

### SC-07. 파라미터 불확실성을 Monte Carlo로 분석한다 (3차)

- **액터**: PM
- **기본 흐름**
  1. 분석 화면에서 불확실한 파라미터(생산성, 요구사항 변동률, 이직률 등)를 선택하고 분포(삼각, 정규 등)를 지정한다.
  2. 실행 횟수 N을 정하고 시작한다.
  3. 진행률이 표시되며, 완료 후 일정·비용 분포, 신뢰구간, "목표 일정 내 완료 확률"이 표시된다.
  4. 민감도 분석에서는 파라미터별 영향도를 토네이도 차트로 확인한다(한 번에 하나씩 바꾼 결과와 Monte Carlo 순위상관 두 가지).
  5. 반복 수가 충분한지 수렴 곡선과 필요한 반복 수로 확인한다.
  6. 시나리오 둘 이상을 같은 난수로 실행해 "A가 B보다 빠를 확률"로 정책 결론이 불확실성에도 유지되는지 본다.
- **대안 흐름**: 사용자가 중간에 취소하면 그때까지의 결과를 유지한다. 입력 분포가 모델이 허용하지 않는 조합을 만들어 일부 반복이 실패하면 제외하고 비율을 알린다.
- **참고**: 결과 확률은 입력 분포 가정과 보정되지 않은 모델에서 나온 값이다. 화면은 이 안내를 상시 표시한다.

### SC-08. 실제 데이터로 모델을 검증한다 (3차)

- **액터**: 모델러
- **기본 흐름**
  1. 과거 프로젝트의 실제 시계열 데이터를 CSV로 가져온다.
  2. 변수 매핑을 지정하고 같은 조건으로 시뮬레이션한다.
  3. 시뮬레이션과 실제 데이터를 겹쳐 보고 오차 지표(MAPE, RMSE 등)를 확인한다.
  4. 극단 조건 테스트, 교란 시험(스텝·펄스·램프), 구조 점검 체크리스트를 실행한다. 결과는 통과·주의·실패·정보로 분류되고 확인하지 못한 것이 함께 표시된다.
  5. 파라미터를 보정하고(식별 가능성 진단과 시간 분할 검증 포함) 프리셋으로 저장해 시나리오로 적용한다.
  6. 수행한 점검의 요약(검증 기록)을 내보낸다.

### SC-09. 모델 구조를 편집하고 보고서를 작성한다 (4차)

- **액터**: 모델러, PM
- **기본 흐름**
  1. 모델 에디터에서 Level, Rate, Auxiliary를 배치하고 수식과 단위를 입력한다.
  2. 구조 라이브러리에서 생산·재작업, 인력 체인 같은 구조를 가져온다.
  3. 구조 점검이 통과하면 시뮬레이션에 사용한다.
  4. 보고서 메뉴에서 계획 요약, 시나리오 비교, 위험 분석을 선택해 PDF 또는 HTML로 내보낸다.

## 5. 공통 비기능 가정

- 규모 단위는 태스크, 시간 단위는 일(dt=0.25일)이다. MVP 통합 모델은 핵심 4섹터 단순판이다(상세는 기능 목록 7장).
- 모든 데이터는 로컬 파일로 저장하며 네트워크가 없어도 동작한다.
- 한 번의 시뮬레이션은 일반적인 프로젝트 규모(수백 일, dt=0.25일)에서 수 초 이내에 끝난다.
- Monte Carlo처럼 오래 걸리는 작업은 UI를 막지 않고 백그라운드에서 실행한다.
- 예제 모델은 원본이 보호되며 사용자는 복사본을 수정한다.
