# 보고서 설계 (4차)

기능 목록 RPT-01~05, 사용 시나리오 SC-09의 4단계 설계. 프로젝트의 계획·시나리오 비교·위험 분석·통제 상태를 **읽기 쉬운 문서(HTML·PDF)**로 내보낸다. 모델 편집기는 [08.모델편집기설계.md](08.모델편집기설계.md)에서 다룬다.

- 근거: 책 2.9(정책 분석: 결과를 의사결정에 쓰는 방법), 2.8(모델 평가: 결과를 읽을 때의 한계), 2.12(프로젝트 관리 고려사항), 앞선 설계 문서 04~07의 "상시 안내" 원칙. 표시는 앞 문서와 같다. **[책]** 책에 명시, **[표준]** 책에는 없지만 널리 쓰는 방법, **[설계]** 이 문서에서 정함.
- 구현 상태 기준일: 2026-10-22. 코드 이름은 현재 저장소의 것을 쓴다.
- 이 문서는 **설계만** 다룬다. 구현은 10장의 순서를 따른다.

## 0. 먼저 읽을 것: 보고서는 결과를 "더 믿음직하게" 만들지 않는다

- 보고서는 **화면에 있는 것을 문서로 옮기는 것**이다. 새로운 계산·해석을 더하지 않는다. 숫자가 종이에 인쇄되면 화면보다 더 단정하게 읽히므로, **가정·한계·신선도(최신 입력으로 만든 결과인가)**를 본문과 같은 비중으로 싣는다.
- 모든 보고서에는 **"이 보고서를 읽을 때" 절**이 있다(고정 문구 + 모델별 문구): 모델이 보정·검증되었는지, 입력 분포가 가정인지, 결과가 예측이 아니라 시나리오 비교용 추정이라는 점(책 2.8.1, 2.9). 끌 수 없다.
- 결과가 **오래되었거나 없으면** 그 절을 "없음/오래됨"으로 표시하고 숫자를 싣지 않는다(오래된 결과를 새것처럼 싣지 않는다). 필요한 결과를 지금 만들 수 있게 한다(4.2).
- **재현성**: 보고서 끝에 "만든 조건"(앱·모델 버전, 시드, 실행 설정, 반복 수)을 싣는다. 같은 프로젝트·같은 조건이면 같은 숫자가 나온다(NFR-05).

## 2. 핵심 결정과 이유

| 결정 | 내용 | 이유 |
|---|---|---|
| **보고서는 데이터, 렌더링은 별도** | 프로젝트 상태 → **`ReportDoc`**(순수 데이터: 제목, 절, 블록) → HTML 문자열 → (PDF). 각 단계가 순수 함수라 시험할 수 있다. | 내용(무엇을 싣나)과 모양(어떻게 그리나)을 나눠 각각 검증한다. 화면 컴포넌트에 묶인 차트·표 코드를 복사하지 않는다. |
| **차트는 SVG 문자열로** | ECharts의 서버측 SVG 렌더링(`init(null, null, { renderer: 'svg', ssr: true })` → `renderToSVGString()`)으로 HTML에 **인라인 SVG**를 넣는다(이 저장소의 echarts 6.1.0에서 동작을 확인했다). | 한 파일에 모두 들어가고(외부 이미지 없음, NFR-03) 확대해도 선명하며 PDF에서 벡터로 남는다. 화면 차트와 **같은 옵션 빌더**를 쓰면 화면과 보고서가 같은 그림이다(7.2). |
| **PDF는 main에서 `printToPDF`** | 숨은 창에 보고서 HTML을 로드하고 `webContents.printToPDF`로 A4 PDF를 만든다. | 앱 번들에 이미 있는 Chromium을 쓴다(새 의존성 없음). 머리말·꼬리말·쪽 번호·문서 개요(북마크)를 지원한다. |
| **보고서 창은 격리** | 미리보기와 PDF용 창은 `sandbox`·`contextIsolation`, **JavaScript 끔**, 네트워크 요청 차단(`file://`와 `data:`만). | 프로젝트·모델 파일에서 온 문자열(이름, 메모, 설명)이 문서에 들어간다. 모든 문자열을 이스케이프하고(8.1) 그래도 스크립트가 실행되지 않게 한다. |
| **보고서에 넣는 것은 현재 세션의 최신 결과** | 파일에 저장되지 않는 결과(시나리오 실행, 위험 분석)는 세션에 있는 것을 쓰고, 없거나 오래되면 **다시 실행해 채운다**(4.2). | 결과는 입력과 시드로 재현되므로(NFR-05) 다시 만들어도 같은 값이다. 보고서를 위해 결과를 파일에 저장하지 않는다(파일 크기·낡음 문제). |

## 3. 보고서 종류와 절

보고서 하나는 **절의 묶음**이다. 종류는 미리 정한 절 구성이고, 사용자는 절을 켜고 끌 수 있다(RPT-07).

| 보고서 | 기본 절 |
|---|---|
| **계획서 요약** (RPT-01) | 개요 · 입력 · 기준 실행 결과 · 채택 계획 · (선택) 시나리오 요약 · 읽을 때 · 만든 조건 |
| **시나리오 비교** (RPT-02) | 개요 · 시나리오 목록과 기준과 다른 값 · 지표 비교표 · 차트(막대·레이더·시계열) · 채택 계획 · 읽을 때 · 만든 조건 |
| **위험 분석** (RPT-03) | 개요 · 불확실한 입력(분포) · 결과 분포 · 목표 달성 확률 · 민감도 · 수렴 진단 · (선택) 시나리오 간 비교 확률 · 읽을 때(가정 강조) · 만든 조건 |
| **상태 보고서** (RPT-04) | 개요 · 보고일 기준 지표(PV·EV·AC·CPI·SPI) · 추이 차트 · 경고 · 완료 예측과 재예측 범위 · 시정 조치 비교와 기준선 개정 이력 · 읽을 때 · 만든 조건 |
| **종합** | 위 네 보고서의 절을 차례로, 중복되는 개요·읽을 때·만든 조건은 한 번만 |
| 검증 기록 절 (RPT-06) | 위 어느 보고서에든 "모델 검증" 절로 붙일 수 있다(데이터 비교 지표, 극단 조건·구조 점검 요약, 체크리스트, 보정 프리셋, **확인하지 못한 것**) |

각 절은 **자료가 없을 때의 모양**이 정해져 있다(예: 위험 분석을 안 했으면 "위험 분석을 실행하지 않았습니다"). 자료가 없는 절은 기본으로 꺼져 있고, 켜면 안내 문구만 나간다.

### 3.1 절의 내용

| 절 | 내용(출처) |
|---|---|
| 개요 | 프로젝트 이름·설명(PRJ-01), 모델(사용자 모델이면 표시, 08번 문서 8.3), 작성자·날짜(설정), 한 문단 요약(핵심 지표 3~4개: 완료일, 총 공수, 필요하면 결함) |
| 입력 | 모델 파라미터를 그룹별 표로(기본값과 다른 것을 강조), 실행 설정(종료 시각·dt·시드) |
| 기준 실행 결과 | 요약 카드와 같은 지표(홈의 `summarizeLastRun`), 핵심 변수 시계열 차트 1~2개 |
| 시나리오 비교 | `buildComparison`의 표(좋음/나쁨 표시는 색만이 아니라 기호로도), 막대·레이더(축이 3개 이상일 때)·시계열 겹쳐 보기, 기준과 다른 값 표(`diffRows`) |
| 채택 계획 | 채택한 시나리오, 계획 완료일·BAC, 개정 이력 요약 |
| 위험 분석 | 분포 히스토그램과 P10~P90, 목표 달성 확률(Wilson 구간), 토네이도(OAT와 순위상관), 수렴, 시나리오 간 비교 확률. **"입력 분포는 가정입니다"** 문구가 이 절 머리에 고정 |
| 통제 상태 | 선택한 보고일의 PV·EV·AC·CPI·SPI와 경고, EVM 추이 차트, 완료 예측(`Forecast`), 재예측 범위(있으면 "추정" 표시), 시정 조치 비교, 개정 이력 |
| 모델 검증 | `ValidationRecord`(07번 문서 6장): 수행한 것과 **하지 않은 것**을 모두 싣는다 |
| 읽을 때 | 고정 문구(0장) + 모델별 문구(내장 모델의 한계: 통합 모델은 책 수치와 정량 일치하지 않고 보정되지 않았다, 03번 문서 0장 등) + 이 보고서에서 오래되었거나 빠진 자료 목록 |
| 만든 조건 | 앱 버전, 모델 id·버전(사용자 모델이면 내용 해시), 실행 설정, 위험 분석의 반복 수·시드, 만든 시각 |

## 4. 데이터 준비와 신선도

### 4.1 자료 상태

보고서 만들기 화면은 절마다 자료 상태를 보인다. 판단은 화면이 이미 쓰는 키 비교(`select*Stale`)와 같다.

| 상태 | 뜻 | 처리 |
|---|---|---|
| 최신 | 지금 입력과 같은 입력으로 만든 결과 | 그대로 쓴다 |
| 오래됨 | 결과를 만든 뒤 입력이 바뀜 | 절을 끄거나 **다시 만들기**(4.2). 그대로 싣는다면 "오래된 결과" 표시를 절 머리에 붙인다 |
| 없음 | 실행한 적이 없음 | 다시 만들기 또는 절 끄기 |
| 해당 없음 | 채택 계획이 없어 통제 절을 못 만드는 경우 등 | 이유를 보이고 절을 끈다 |

### 4.2 "필요한 결과 만들기"

`runScenarios('missing')`, `runRisk()`, 위험 분석 비교·민감도 실행 같은 **기존 액션**을 순서대로 부르고 진행을 보인다(취소 가능, 하나의 Worker 규칙 유지). 이미 최신인 것은 다시 실행하지 않는다. 실행 시간이 길 수 있으므로(위험 분석 500회 수 초) 시작 전에 예상 내용을 알린다. 사용자가 거절하면 그 절은 "결과 없음"으로 나간다.

## 5. 보고서 데이터 모델

```ts
interface ReportDoc {
  title: string
  subtitle?: string
  meta: { author?: string; date: string /* ISO */; app: string; model: { id; name; version; custom?: boolean; hash?: string } }
  sections: ReportSection[]
}
interface ReportSection { id: SectionId; title: string; status: 'fresh' | 'stale' | 'missing'; blocks: Block[] }
type Block =
  | { kind: 'paragraph'; text: string; tone?: 'normal' | 'warning' | 'note' }
  | { kind: 'list'; items: string[]; ordered?: boolean }
  | { kind: 'keyValues'; rows: [label: string, value: string][] }
  | { kind: 'table'; caption?: string; columns: Column[]; rows: Cell[][]; note?: string }
  | { kind: 'chart'; title: string; alt: string; svg: string; table?: TableBlock }   // alt: 요약 문장, table: 같은 값을 담은 표
  | { kind: 'callout'; title: string; text: string; tone: 'warning' | 'note' }
```

- 블록은 **서식이 없는 데이터**다(글꼴·색은 렌더러가 정한다). 숫자는 이미 **표시용 문자열**로 포맷해 담는다(화면의 `formatValue`·`formatDelta`를 재사용해 화면과 같은 반올림). 원자료가 필요한 JSON 내보내기는 만들지 않는다.
- 모든 차트는 **같은 값을 담은 표**(또는 요약 문장)를 함께 갖는다. 접근성(HTML의 `<figure>`와 `<table>`)과 흑백 인쇄 때문이다.
- `ReportDoc`은 순수 데이터라 단위 시험으로 내용(숫자, 문구, 절 구성)을 고정한다.

## 6. 렌더링

### 6.1 HTML (`renderReportHtml(doc, options) → string`)

- 자체 완결: `<style>` 인라인, 차트는 인라인 SVG, 글꼴은 시스템 글꼴 스택(`-apple-system, 'Apple SD Gothic Neo', 'Malgun Gothic', sans-serif`, 글꼴 파일을 넣지 않는다).
- 구조: `<header>`(제목·메타) → 목차(절 링크) → `<section>`들 → 끝의 "만든 조건". 의미 있는 마크업(`<h1>`~`<h3>`, `<figure>`/`<figcaption>`, `<table>`+`<caption>`+`scope`).
- **이스케이프**: 모든 문자열은 `&`, `<`, `>`, `"`, `'`를 이스케이프한다. 문서에 들어가는 HTML 조각은 **SVG 문자열 하나뿐**이고 그것은 ECharts가 만든 것이다(사용자 문자열은 SVG 텍스트로 넣을 때 이스케이프된 상태로 ECharts에 전달한다). 시험으로 `<script>`·`"onload=` 같은 입력이 문자 그대로 나옴을 고정한다.
- 인쇄 CSS: `@page { size: A4; margin: 18mm 16mm }`, 절 제목 뒤 쪽 나눔 방지, 표 행·차트 `figure`는 쪽 중간에서 끊기지 않게(`break-inside: avoid`), 표 머리글 반복, 흑백에서도 구분되는 선 모양과 기호.
- 밝은 테마 고정(보고서는 앱의 어두운 테마를 따르지 않는다). 차트 색은 색맹에도 구분되는 8색 팔레트(`palette.ts`)를 쓰고 선 모양·마커로 중복 표시한다.

### 6.2 PDF (`main: exportPdf`)

1. renderer가 HTML 문자열을 main에 보낸다(IPC `report:exportPdf`, 크기 상한 20 MB).
2. main이 **보이지 않는 `BrowserWindow`**(`show:false`, `sandbox:true`, `javascript:false`, 새 창·네비게이션 거부)에 `data:` URL이 아니라 **임시 파일(`userData/tmp`)**로 로드한다(큰 문서의 URL 길이 한계 회피).
3. `webContents.printToPDF({ pageSize: 'A4', printBackground: true, displayHeaderFooter: true, headerTemplate, footerTemplate(쪽 번호 `<span class="pageNumber">/<span class="totalPages">), generateDocumentOutline: true })`.
4. 저장 대화상자(`.pdf`)로 파일에 쓰고, 임시 파일과 창을 정리한다. 실패하면 이유를 알린다.
5. 렌더러는 PDF를 만들지 않는다(경로·권한은 main만 안다).

### 6.3 HTML 내보내기·미리보기

- HTML 내보내기: 같은 문자열을 저장 대화상자(`.html`)로 쓴다(`files.exportText` 일반화).
- **미리보기**: renderer의 `<iframe sandbox srcDoc>`(스크립트·폼·팝업 없음)로 같은 HTML을 보인다. 화면 폭에 맞춘 "화면용" 스타일과 "인쇄 보기"(A4 폭) 전환. 미리보기와 내보낸 파일이 **같은 문자열**이라 보이는 것과 나오는 것이 같다.

## 7. 화면

메뉴의 `보고서`(지금은 "준비 중" 항목)를 활성화하고 새 탭 **"보고서"**를 둔다(홈 다음, 또는 검증 오른쪽).

```
┌ 보고서 ─────────────────────────────────────────────────────────────────────────┐
│ 종류 [시나리오 비교 ▾]  제목 [………]  작성자 [………]  날짜 [2026-10-22]                   │
├────────────────────────────────┬──────────────────────────────────────────────┤
│ 절                    자료 상태    │ 미리보기   [화면][A4]                          │
│ ☑ 개요                 최신        │ ┌────────────────────────────────────────┐ │
│ ☑ 시나리오 목록          최신        │ │ 시나리오 비교 보고서                        │ │
│ ☑ 지표 비교표           오래됨 ⟳    │ │ …                                         │ │
│ ☑ 차트                 최신        │ └────────────────────────────────────────┘ │
│ ☐ 위험 분석             없음 ⟳      │                                              │
│ ☑ 모델 검증             없음        │ [필요한 결과 만들기] [HTML로 저장] [PDF로 저장]   │
└────────────────────────────────┴──────────────────────────────────────────────┘
```

| 요소 | 설명 |
|---|---|
| 종류·설정 | RPT-07. 제목 기본값은 "<프로젝트 이름> — <종류>". 작성자·날짜·절 선택·차트 크기(보통/크게)는 **프로젝트 파일의 `reports` 필드**에 저장한다(결과는 저장하지 않는다) |
| 절 목록 | 절 체크박스와 자료 상태, 오래됨·없음 옆에 "만들기"(4.2). 해당 없음은 이유를 툴팁으로 |
| 미리보기 | 6.3. 자료가 바뀌면 다시 만든다(디바운스) |
| 저장 | 데스크톱 앱에서만(브라우저 개발 모드는 미리보기만). 완료 안내에 파일 이름 |
| 접근성 | 절 목록은 체크박스 그룹, 미리보기는 `iframe title`, 상태는 텍스트로(색만 쓰지 않는다) |

## 8. 안전과 한도

### 8.1 문자열과 문서

- 이스케이프는 `escapeHtml` 하나로 모은다(렌더러의 모든 텍스트 경로가 통과). **`innerHTML`·`dangerouslySetInnerHTML`을 쓰지 않는다**(미리보기는 `srcDoc`).
- 사용자 문자열의 길이를 자른다(제목 200자, 메모 500자는 이미 한도가 있다). 표는 행 상한(시나리오 12 × 지표 12, 위험 반복별 표는 싣지 않는다 — 요약 통계만).
- 문서 크기 상한 20 MB(SVG가 가장 크다). 넘으면 차트 해상도(점 수)를 줄여 다시 만든다.

### 8.2 개인정보와 경로

- 보고서에는 **파일 경로를 넣지 않는다**(프로젝트 파일 이름만). 작성자는 사용자가 적은 것만 쓰고 운영체제 사용자 이름을 읽지 않는다.
- 보고서는 **외부로 전송하지 않는다**. 저장만 하고 열기·보내기는 사용자의 몫이다.

## 12. 위험과 결정이 필요한 것

| 번호 | 항목 | 내용 | 제안 |
|---|---|---|---|
| D1 | PDF 방식 | Electron `printToPDF` 외에 라이브러리(pdf-lib 등)로 직접 만드는 방법 | **`printToPDF`**. 새 의존성이 없고 HTML과 같은 문서를 쓴다 |

| D5 | 상태 보고서의 기준일 | 마지막 보고일을 기본으로 하되 선택 가능 | **기본 마지막 보고일, 선택 가능**(CTL-10의 과거 보고일 기준 보기와 같다) |
| D6 | 보고서 템플릿 | 사용자가 절 구성을 만드는 기능 | **후속**. 4차는 종류와 절 선택까지 |
