# 기술 스택

[docs/01.분석](../01.분석/02.기능목록.md)의 기능 목록과 확정 사항(태스크·일·dt=0.25일, MVP 핵심 4섹터 단순판)을 만족하기 위한 기술 선택과 그 이유.
버전은 구현 시점의 최신 안정판을 쓰고 `package.json`에서 고정한다. 이 문서에는 선택한 도구만 적는다.

## 1. 선택 요약

|---|---|---|---|

## 2. 핵심 결정과 근거

### 2.1 모델을 코드가 아니라 데이터로 정의한다

- 모델(Brooks, 통합 프로젝트)은 Level·Rate·Auxiliary·상수와 수식 문자열로 구성된 **JSON 모델 정의**로 표현하고, 엔진이 이를 해석해 실행한다.
- 이유
  1. 4차 모델 에디터(EDT)가 같은 형식을 그대로 읽고 쓴다.
  2. 시나리오(SCN-02)가 "파라미터 덮어쓰기"만으로 표현된다.
  3. 검증 화면(VAL)이 변수 이름으로 결과 시계열을 매핑하기 쉽다.
- 대가: 수식 파서와 컴파일러를 직접 만들어야 한다. 대신 지원 문법을 SD에 필요한 최소 집합으로 제한한다(2.3 참조).

### 2.2 적분은 Euler 고정 간격으로 시작한다

- 책 2.1.4의 `Level(t) = Level(t−dt) + (inflow − outflow)·dt` 형태를 그대로 구현한다. dt=0.25일.
- 엔진 인터페이스를 적분기와 분리해 두어 Runge-Kutta 4를 나중에 교체 가능하게 한다(책 2장은 진동 모델에서 Euler 오차를 지적하며 RK를 대안으로 제시).
- 모델 정의에서 `dt`는 기본값이며 실행 옵션으로 덮어쓸 수 있다.

### 2.3 수식 언어의 지원 범위 (MVP)

| 분류 | 지원 |
|---|---|
| 연산 | `+ − * / ^`, 비교, `AND OR NOT`, 괄호 |
| 조건/수학 | `IF(c, a, b)`, `MIN`, `MAX`, `ABS`, `SQRT`, `EXP`, `LN`, `ROUND`, `CLAMP` |
| 시간 | `TIME`, `DT`, `STEP(h, t)`, `PULSE(h, t, w)`, `RAMP(s, t)` |
| 지연/평활 | `DELAY1(x, d)`, `DELAY3(x, d)`, `SMOOTH(x, d)` — 내부적으로 보조 Level을 생성 |
| 테이블 | `GRAPH(x, [x0..xn], [y0..yn])` 선형 보간 |
| 난수 | `RANDOM_UNIFORM`, `RANDOM_NORMAL`, `RANDOM_TRIANGULAR` (시드 PRNG 사용) |

3차 이후 필요한 함수는 레지스트리에 추가한다.

### 2.4 시뮬레이션은 renderer의 Web Worker에서 실행한다

- 단일 실행(수 초 이내)은 Worker 하나로 충분하고 메인 스레드의 UI는 멈추지 않는다.
- 실행 중 진행 상황은 일정 간격(예: 매 N 스텝)으로 Worker가 요약 데이터를 postMessage해 실시간 그래프(RUN-02)에 전달한다.
- Monte Carlo(RSK-02)처럼 수백~수천 회 반복은 3차에 Worker 풀 또는 main의 `utilityProcess`로 분산한다. 이를 위해 엔진은 DOM·Electron API에 의존하지 않는 순수 TypeScript 패키지로 둔다.

### 2.5 파일 I/O는 main 프로세스만 수행한다

- renderer는 Node API에 접근하지 않는다(`contextIsolation: true`, `nodeIntegration: false`).
- preload에서 `contextBridge`로 필요한 IPC만 노출한다(프로젝트 열기/저장, CSV 가져오기/내보내기, PDF 출력).
- 보안 이유와 함께, 모든 파일 경로를 main이 다이얼로그를 통해서만 받도록 하여 임의 경로 접근을 막는다.

### 2.6 UI 언어

- 화면 문구는 한국어를 기본으로 하되, 문자열을 i18n 리소스로 분리한다(COM-03 한/영 지원 대비).

## 3. 저장소 구조(모노레포)

엔진을 UI와 분리하기 위해 npm workspaces로 패키지를 나눈다. 상세는 [02.아키텍처설계.md](02.아키텍처설계.md)의 4장 참조.

```
SPD/
├─ packages/
│  ├─ sd-engine/      # 순수 TS: 수식, 모델 정의, 적분, 시뮬레이션 실행
│  ├─ models/         # 내장 모델(JSON): brooks, integrated-project
│  └─ analysis/       # EVM, 시나리오 비교, Monte Carlo, 통계 (2차 이후 채움)
├─ apps/
│  └─ desktop/        # Electron 앱 (main, preload, renderer)
└─ docs/
```

## 5. 위험과 대응

| 위험 | 영향 | 대응 |
|---|---|---|
| 자체 수식 파서의 버그 | 모델 결과 오류 | 파서·함수 단위 테스트를 책의 단순 예제(지수 성장, 목표 추구, 지연)로 작성하고 해석해와 대조 |
| Euler 수치 오차 | 진동 모델 발산 | 적분기 인터페이스 분리, 회귀 테스트로 dt 민감도 확인, 필요 시 RK4 교체 |
| 책 모델의 파라미터 불명확 | 결과가 책 그래프와 다름 | 책 그림의 기준 행동(참조 곡선)과 형태 비교로 검증, 보정값을 문서화 |
| Electron 번들 크기 | 앱 용량 증가 | 차트 모듈 부분 임포트(ECharts tree-shaking) |
| Worker 데이터 전달 비용 | 대용량 시계열 지연 | 결과는 Float64Array로 전달(transferable), 표시는 다운샘플링 |
