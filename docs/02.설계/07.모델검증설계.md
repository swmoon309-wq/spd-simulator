# 모델 검증 설계 (3차)

기능 목록 VAL-01~05, 사용 시나리오 SC-08의 설계. 모델이 **목적에 맞는지** 실제 데이터와 비교하고, 극단 조건·구조·수치 점검으로 신뢰를 쌓고, 데이터에 맞게 파라미터를 보정해 프리셋으로 저장한다. 위험 분석(Monte Carlo)은 [06.위험분석설계.md](06.위험분석설계.md)에서 다룬다.

- 근거: 책 2.6.5~2.6.6(모델 구성의 규칙: 단위 일관성, 흐름·보존), 2.7(시뮬레이션: 정상 상태, 테스트 입력 함수, 기준 행동), 2.8(모델 평가: 검증 시험 표 2-4~2-6, 민감도). 표시는 05번 문서와 같다. **[책]** 책에 명시, **[표준 통계]** 책에는 없지만 널리 쓰는 방법, **[설계]** 이 문서에서 정함.
- 구현 상태 기준일: 2차 완료 시점. 코드 이름은 현재 저장소의 것을 쓴다.

## 0. 먼저 읽을 것: 검증은 증명이 아니다

책(2.8.1)이 이 설계의 전제이다.

- "모델이 현실의 정확한 표현임을 증명할 수 없다." 검증은 **신뢰를 쌓는 활동의 묶음**이고, 시험 하나로 충분하지 않다(표 2-4~2-6의 여러 시험을 함께 본다).
- 신뢰의 양은 "모델이 답해야 하는 질문"과 "그 답이 얼마나 정확해야 하는가"에 달렸고, 마지막은 **사람의 판단**이다. 그래서 이 도구는 **합격·불합격을 선언하지 않는다**. 지표와 사용자가 정한 허용 기준의 충족 여부(기준 안/밖)를 보여 줄 뿐이다.
- 많은 목적에서 **상대 결과**(정책 간 차이)로 충분하고 절대값 예측은 불필요하다(책). 그래서 오차 지표와 함께 **추세·순위 일치** 지표를 보인다.
- 통합 모델은 책과 정량 일치하지 않고 보정되지 않았다(03번 문서 0장). 이 도구는 그 사실을 숨기지 않고 오히려 드러내는 용도이기도 하다.

## 2. 데이터 가져오기와 매핑 (VAL-01)

기존 기능을 재사용한다: 기준 행동 CSV 가져오기(`parseReferenceCsv`: 첫 열 시간, 나머지 열 하나씩 시계열, 빈 칸 건너뜀, 숫자가 아니면 행·열 위치와 함께 거부)와 열 이름을 모델 변수에 맞추는 규칙(`matchVariable`). 지금은 이 데이터가 그래프에 겹쳐 그리기만 하고 저장되지 않는다. 검증에서는 이를 **데이터셋**으로 승격한다.

| 항목 | 설명 |
|---|---|
| 데이터셋 | 이름, 가져온 파일 이름, 시간 단위, 시간 이동, 열 목록 |
| 열 | 열 이름, 매핑한 모델 변수(없으면 비교에서 제외), **값 배율**(단위 변환, 기본 1), 점 `[시각, 값]`(최대 5,000개) |
| 시간 단위·이동 | 일(기본), 주(×7), 월(×30.4375) 중 선택하고 **시간 이동**(실제 프로젝트 시작일 − 시뮬레이션 0일, 일)을 입력. 변환은 데이터 시각 `t_sim = t_data × 단위 + 이동` |
| 제한 | 데이터셋 최대 5개, 열 최대 20개, 프로젝트 파일에 저장하는 점 합계 최대 50,000개(약 1 MB) |
| 같은 조건 | 비교는 **대상 시나리오**(기준 또는 시나리오)의 유효 파라미터와 실행 설정으로 시뮬레이션한 결과와 한다. 실제 프로젝트의 알려진 입력(초기 인원, 총 태스크 등)은 사용자가 그 시나리오에 반영해 둔다. 실제 시계열 입력(날짜별 실제 채용 등)을 모델에 주입하는 것은 지원하지 않는다(교란 시험의 상수 시각 변경으로 근사할 수는 있다) |

## 3. 오차 지표 (VAL-02)

### 3.1 정렬

비교할 점은 데이터 시각 `t_i`이고, 시뮬레이션 값은 **선형 보간**(`valueAt`)으로 읽는다. 시뮬레이션 범위(0~종료 시각) 밖의 점은 제외하고 개수를 알린다. 매핑한 열마다 `n`쌍 `(O_i, S_i)`(관측, 시뮬레이션)을 만든다.

### 3.2 지표 정의

| 지표 | 정의 | 출처·주의 |
|---|---|---|
| 평균 오차 ME | `mean(S − O)` | 편향(부호 있음) |
| MAE | `mean(|S − O|)` | |
| RMSE | `√mean((S − O)²)` | 책이 언급한 지표(2.8.1) [책] |
| 정규화 RMSE | `RMSE / mean(|O|)` | 단위가 다른 열을 비교하기 위해 [설계] |
| 상대 예측 오차(MRE) | `mean((S − O)/O)` (O = 0인 점 제외, 제외 개수 표시) | 책이 언급(2.8.1) [책]. 부호 있음 |
| MAPE | `mean(|S − O|/|O|)` (O = 0 제외) | [표준 통계] |
| NSE | `1 − Σ(O − S)² / Σ(O − Ō)²` | 1이면 일치, 0이면 평균만큼, 음수면 평균보다 나쁨. 상관만으로 놓치는 편향을 드러낸다 [표준 통계] |
| 상관 r, R² | 피어슨 | 책 1장 경고: 상관은 오해를 부를 수 있다. **상관은 보조로만** 보이고 편향과 함께 읽도록 안내 |
| Theil 부등계수 U | `RMSE / (√mean(S²) + √mean(O²))` | 0이면 일치 |
| Theil 분해 | `U^M = (S̄ − Ō)²/MSE`(편향), `U^S = (s_S − s_O)²/MSE`(변동 크기 차이), `U^C = 2(1−r)s_S s_O/MSE`(비체계적 오차). **세 값의 합 = 1** | 책이 참고문헌으로 제시한 Sterman(2000)의 SD 검증 관례 [표준 SD]. 편향(U^M)이 크면 파라미터 보정, 비체계(U^C)가 크면 모델이 잡지 못한 잡음이므로 보정해도 줄지 않는다는 해석을 돕는다 |
| 추세 일치율 | 인접한 관측 구간에서 `sign(ΔS) = sign(ΔO)`인 비율 | 상대·질적 검증용(책: 질적 기준도 중요) [설계] |
| 완료 시점 오차 | 데이터에 "실제 완료일"(열의 마지막 값이 완료를 뜻하는 변수, 또는 사용자가 입력)이 있으면 `시뮬레이션 완료일 − 실제 완료일`(일, %) | 일정 예측의 핵심 지표 |

### 3.3 허용 기준과 표시

사용자가 지표별 **허용 기준**(예: 정규화 RMSE ≤ 0.15, |MRE| ≤ 10%)을 정하면 "기준 안/밖"을 글자와 기호로 표시한다(색에만 기대지 않음). 기준이 없으면 값만 보인다. 합격·불합격이라는 말은 쓰지 않는다(0장). 화면에는 관측과 시뮬레이션의 겹친 그래프(기존 `TimeSeriesChart`), **잔차(S − O) 그래프**, 지표 표를 함께 둔다. 모든 열이 같은 비중이 아니므로 열별 표와 가중 종합 하나(보정 목적함수와 같은 정의, 5장)를 모두 보인다.

## 4. 극단 조건·교란·구조 점검 (VAL-03, VAL-06, VAL-04)

### 4.1 극단 조건 테스트 (VAL-03)

책 표 2-4의 "수식이 극단값에서도 말이 되는가"를 자동화한다. 폼의 파라미터마다 아래 수준으로 **한 번에 하나씩** 바꿔(나머지는 대상 시나리오의 값) 실행한다.

| 구분 | 수준 | 분류의 의미 |
|---|---|---|
| 허용 범위 안 | 최소, 최대(폼의 범위 양 끝) | 여기서의 오류·음수 Level·불변식 위반은 **모델 결함**(실패) |
| 허용 범위 밖 | 0, 현재 값의 ×10, ×0.1 | 범위 밖이므로 오류는 **정보**(예상된 거동일 수 있음). 음수 Level·불변식 위반은 주의 |

각 실행의 판정:

| 판정 | 조건 |
|---|---|
| 통과 | 오류 없음, Level이 모두 ≥ −허용오차, 모델의 불변식 유지, 지표가 모두 유한 |
| 주의 | 통과 조건 중 Level 음수 또는 불변식 위반이 있으나 오류는 없음, 또는 범위 안인데 종료까지 끝나지 않음(정보로도 표시) |
| 실패 | 범위 안에서 `SimulationError`(NaN·무한대)나 `ModelError` |
| 정보 | 범위 밖에서의 오류, 또는 종료 시각까지 미완료 |

결과는 파라미터 × 수준 표(통과·주의·실패·정보 기호)로 보이고, 셀을 누르면 그 실행의 핵심 변수 그래프와 첫 문제 시점·변수를 보인다. **"말이 되는 거동인가"는 자동으로 판단하지 못한다**: 표는 기계적 결함만 잡고, 지표(완료일 등)를 같이 보여 사람이 읽게 한다. 2차에서 모델 시험에 넣은 범위 시험·퍼징(통합 모델에서 0/0 가드 두 곳을 찾은 것)을 도구로 만드는 일이다. 규모: 통합 모델 파라미터 41개 × 5수준 ≈ 205회 × 4.5 ms ≈ 1초.

### 4.2 교란 시험 (VAL-06)

책 2.7.2: 이상화된 시험 입력(**펄스, 스텝, 램프**)으로 모델을 건드려 반응을 본다. 이 앱의 모델은 외부 입력 변수가 아니라 상수가 있으므로, 2차에서 만든 **시각별 상수 변경**(`setConstant`를 날짜에 맞춰 부름, 08번 구현)으로 상수에 시험 입력을 건다.

| 입력 | 정의 | 구현 |
|---|---|---|
| 스텝 | 시각 `t`부터 상수를 `v`로 | 변경 1개 |
| 펄스 | `[t, t + w)` 동안만 `v`, 이후 원래 값 | 변경 2개 |
| 램프 | `[t, t + w)` 동안 `v₀`에서 `v₁`까지 선형(계단 `K = 10`단) | 변경 K + 1개 |

입력: 상수, 종류, 크기(절대값 또는 기준 대비 ±%), 시각, 폭, 보고 변수(여러 개). 출력: 기준 실행과 교란 실행의 겹친 그래프, **최대 편차·최대에 이르는 시각·원래 값으로 돌아오는지**(편차가 5% 안으로 들어오는 시각, 못 돌아오면 "복귀 안 함"). 책 2.7.2처럼 "레벨이 음수가 되는가, 계속 커지는가, 반응이 너무 빠른가"를 사람이 읽는다. 한계: 외부 신호를 Rate에 직접 넣는 것은 지원하지 않는다(모델 편집기, 4차).

정상 상태 점검(책 2.7.1)은 **Level 변화 점검**으로 대신한다: 짧은 구간(기본 40일)을 실행해 시작 대비 변한 Level과 변화량을 표로 보여 "어느 Level이 움직이는가"(책의 "범인 찾기")를 돕는다. 모델마다 정상 상태를 만드는 중립 입력이 달라 자동 판정은 하지 않는다.

### 4.3 구조 점검 (VAL-04)

자동 점검 6종과 수동 체크리스트로 나눈다. 모든 자동 점검은 "무엇을 확인했고 무엇은 확인하지 못했는지"를 함께 적는다.

| # | 점검 | 방법 | 한계 |
|---|---|---|---|
| S1 | 단위 일관성(부분) | 모든 변수에 단위 문자열이 있는지, **Level에 연결된 Rate의 단위가 `Level 단위/일`인지**(책: Rate는 같은 단위를 시간으로 나눈 것) | 수식 안의 항별 단위 일치는 못 본다(수식 단위 검사는 4차 EDT-03) |
| S2 | 보존 법칙 | 모델이 선언한 **불변식**(아래)을 매 스텝 평가해 최대 위반을 보고 | 선언된 것만 |
| S3 | Level 음수 | 대상 시나리오 실행에서 Level이 −허용오차 아래로 내려갔는지 | |
| S4 | 적분 간격 민감도 | dt와 dt/2로 실행해 완료일·핵심 지표의 상대 변화. ≤ 1% 통과, ≤ 5% 주의, 초과 실패. 책: DT는 가장 작은 시간 상수의 1/2 미만(안전하게는 1/3) | |
| S5 | 구조 정적 점검 | 컴파일된 의존 그래프에서 **쓰이지 않는 상수·보조 변수**(어떤 흐름·Level 초기값·출력에도 안 쓰임), **유입·유출이 없는 Level**, Level·출력에 이어지지 않는 Rate | 변수 이름만으로 의미를 판단하지 못한다 |
| S6 | 수치 건전성 | 시각 0의 Level·Rate가 유한하고 Level 초기값이 ≥ 0 | |

**불변식을 모델 데이터로 선언한다**(엔진 스키마 확장): 모델 JSON의 선택 항목 `invariants`: `{ "name", "label", "lhs": [{"variable", "coef"}], "rhs": [{"variable", "coef"}], "tolerance" }`. 선형 결합 `Σ coef·변수`가 양변에서 같다는 보존 법칙을 적는다(예: Brooks `requirements + developed_software = initial_requirements`, 통합 모델의 개발 태스크 = QA 대기 3단 + QA 완료). 상수도 변수로 쓸 수 있다. 2차에서 모델 시험(`6.3 불변식`)에 코드로 박혀 있던 것을 데이터로 꺼내 화면에서도 같은 점검을 쓰게 하는 것이다. 결과가 같은 값을 내므로 모델 `version`은 올리지 않는다.

**수동 체크리스트**(책 표 2-5, 2-6): 얼굴 타당성(구조가 실제 시스템과 닮았는가), 파라미터가 실제 시스템에서 알아볼 수 있는가, 기준 행동을 재현하는가, 예상 밖 거동이 설명되는가, 모델의 크기·단순함이 대상에 적절한가 등 항목마다 **미확인 / 확인 / 문제 있음 + 메모**를 기록하고 프로젝트 파일에 저장한다(검증 기록의 일부). 책의 통과 기준 문구를 항목 설명으로 보인다.

## 5. 파라미터 보정·프리셋 (VAL-05)

### 5.1 문제의 정의

선택한 파라미터 `θ`(최대 5개, 각 구간은 폼의 허용 범위 또는 사용자가 좁힌 범위)와 비교할 열(가중치)로 **목적함수**를 최소화한다.

```
J(θ) = Σ_열 w_c · NRMSE_c(θ)²      (NRMSE_c = RMSE_c / mean(|O_c|),  w_c 기본 = 1/열 수)
```

2차 설계가 택하지 않은 방법("실적 전체에 파라미터 여러 개를 맞추는 보정 — 점이 적고 파라미터가 많아 해가 유일하지 않다", 05번 7.2)과 같은 문제이므로 **식별 가능성 진단을 기본 기능으로** 한다. 보정이 "맞는 값"을 준다고 약속하지 않는다.

### 5.2 알고리즘 [설계]

| 항목 | 선택 | 이유 |
|---|---|---|
| 최적화 | **유계 Nelder–Mead**(도함수 없는 심플렉스, 경계로 사영) | 모델이 블랙박스고 1회 약 5 ms라 수백 번이면 몇 초. 파라미터 ≤ 5개에 적합 |
| 다중 시작 | 시작 5개(현재 값 + 시드로 뽑은 라틴 하이퍼큐브 4개) | 국소해와 비유일성을 드러내려고 |
| 종료 | 목적함수 변화 < 1e-6 연속 3회, 또는 평가 횟수 상한(파라미터 수 × 200) | |
| 재현성 | 시작점은 시드로 정해 같은 입력이면 같은 결과 | NFR-05 |
| 취소 | Worker가 12 ms마다 확인하고 그때까지의 최선 결과를 돌려줌 | |

### 5.3 식별 가능성 진단과 과적합 방지

| 진단 | 보이는 문구 |
|---|---|
| 경계 도달 | 파라미터가 허용 범위 끝에 붙음 → "범위가 좁거나 모델이 이 데이터를 설명하지 못함" |
| 평탄 | 보정값에서 각 파라미터를 ±10% 움직였을 때 `J`의 증가가 작음(예: < 1%) → "이 데이터로는 정해지지 않는 파라미터" |
| 다중 시작의 분산 | 시작점마다 파라미터가 다른데 `J`가 비슷함 → "해가 유일하지 않음(서로 보완하는 파라미터)" |
| 자료 부족 | 관측 점 수 < 파라미터 수 × 3 → 과적합 경고 |
| **시간 분할 검증** | 관측이 15점 이상이면 기본으로 앞 70%로 보정하고 뒤 30%로 **보정에 쓰지 않은 구간의 오차**를 보인다 [표준 통계]. 보정 구간 오차만 작고 검증 구간 오차가 크면 과적합 |

### 5.4 프리셋

보정 결과를 **프리셋**으로 저장한다: 이름, 파라미터 값(보정한 것만), 출처(데이터셋, 목적함수, 보정 시각, 시간 분할 여부, 지표). 프로젝트 파일에 저장한다(최대 20개).

| 동작 | 설명 |
|---|---|
| 시나리오로 적용 | 프리셋을 새 시나리오의 overrides로 만든다(기본 설정은 그대로). 기본 권장 |
| 기본 설정에 적용 | 확인 후 기본 설정 값을 바꾼다(저장하지 않은 변경이 생김) |
| 내보내기·가져오기 | 프리셋을 JSON 파일로 저장하고 다른 프로젝트에서 가져온다(`files` IPC 재사용). COM-04(템플릿·보정값 라이브러리)의 최소 형태 |
| 호환 검사 | 가져올 때 모델 id, 파라미터 이름·범위를 검사하고 맞지 않는 항목은 버리고 알린다(2차 시나리오 정리와 같은 방식) |

| 보정 방법 | Nelder–Mead 다중 시작. 파라미터가 많으면 해가 유일하지 않다 | 최대 5개로 제한하고 진단을 기본 표시. 격자 탐색·베이즈 방법은 후속 |
| 교란의 한계 | 상수에만 건다(Rate 주입 불가) | 책의 방식과 차이를 화면에 명시. Rate 주입은 4차 모델 편집기 |
| 단위 검사의 범위 | Level–Rate 단위 관계와 단위 누락까지 | 수식 단위 해석은 4차(EDT-03). S1에 "확인하지 못한 것" 표시 |
| 모델 JSON 확장 | `invariants` 선택 항목 추가 | 결과가 변하지 않으므로 모델 version 유지. 스키마는 선택 항목이라 기존 모델 파일과 호환 |
| 실제 입력 시계열 주입 | 날짜별 실제 채용 등을 모델 입력으로 넣는 비교 | 3차 제외. 교란 시험의 시각별 상수 변경으로 근사 가능 |
| 모델 결함 발견 시 | 극단 조건에서 결함이 나오면 모델을 고쳐야 한다 | 결함은 모델 시험(2차 방식)으로 고치고 모델 version을 올린다. 이 도구는 발견만 한다 |
