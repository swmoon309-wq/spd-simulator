## 1. CFG-01 SLOC로 입력

규모 입력 아래의 **"SLOC로 입력"** 보조 입력(`components/SizeConverter.tsx`, `lib/sizeConversion.ts`).

| 항목 | 내용 |
|---|---|
| 동작 | 코드 규모(SLOC)와 단위당 SLOC를 적으면 `SLOC ÷ (SLOC/단위)`로 환산해 보여 주고, **규모에 적용**을 누르면 모델의 규모 파라미터에 넣는다. 정수 파라미터는 반올림, 허용 범위 밖이면 이유를 알리고 적용하지 않는다. 지금 규모가 몇 SLOC인지도 보인다. |
| 모델별 기준 | 모델의 `size` 정보(`catalog/types.ts`의 `SizeInfo`)로 정한다. **통합 프로젝트 모델과 구조 모델은 태스크, 기본값 60 SLOC/태스크**(책 6.3: 태스크 하나는 약 60라인 = 0.06 KDSI, 근거를 화면에 적는다). **Brooks 모델의 규모 단위는 FP**인데 책에 FP↔SLOC 환산 기준이 없어 **기본값을 비워 두고** 사용자가 조직의 실측값을 적게 했다(언어·도메인마다 달라 값을 지어내지 않는다). |
| 저장 | 보조 입력의 값은 프로젝트에 저장하지 않는다(규모 파라미터만 저장된다). |
| 범위 | CFG-01의 "목표 일정·가용 인력"은 이미 입력 항목이다. **예산**은 모델의 입력이 아니라 채택한 계획의 BAC(총 공수)로 나온다. 그래서 이번에 더한 것은 SLOC 환산이다. |

시험 8개(`lib/sizeConversion.test.ts`): 쉼표·공백 입력, 24,000 ÷ 60 = 400, 정수 반올림(24.67 → 25, 25.5 → 26), FP는 소수 유지, 범위 밖 거절, 잘못된 입력 메시지, 역환산, 모델의 규모 정보가 입력 항목·단위와 맞음.

## 2. MDL-03 기본 구조 라이브러리

책 3장의 구조를 **하나씩 단독으로 실행해 보는 작은 모델 5개**. 모델 선택 목록에 "기본 구조 라이브러리(책 3장)" 묶음으로 나오고(`catalogGroups()`, 헤더와 홈의 선택에 `optgroup`), 홈의 예제로도 복사본으로 열 수 있다. 모두 "일을 하는 작은 프로젝트" 모양(작업 규모, 완료일, 공수)이라 **시나리오 비교·채택·위험 분석·검증이 그대로 동작한다**.

| 모델 (id) | 책 | 구조와 방정식 | 기본 설정의 결과 |
|---|---|---|---|
| 생산과 재작업 (`production-rework`) | 3.4.7 그림 3.36 | 개발률 = 인원×생산성, 올바른 부분 = f배, 나머지는 발견 전 재작업 → 발견률 = 재작업/지연 → 다시 해야 할 일 | 187일, 발견 전 재작업 정점 |
| 인력 학습곡선 (`learning-curve`) | 3.4.9 그림 3.38~3.39 | 생산성 = 공칭 × 학습곡선(진행률). 곡선은 시작 배율에서 학습 끝 배율까지 매끈한 S자(3p²−2p³) | 103일(학습 없으면 80일) |
| Rayleigh 인력 곡선 (`rayleigh`) | 3.4.10 그림 3.40 | 투입 공수율 = 학습 함수 × (추정 총 공수 − 누적 공수), 학습 함수 = 계수 × 시간 | 정점 100일·24명, 99% 도달 303일 |
| 인력 체인 3단계 (`personnel-chain`) | 3.5.3.1 그림 3.63, 3.4.8 | 신입 → 일반 → 선임, 채용은 신입, 이직은 선임, 단계별 생산성이 개발률을 정함 | 318일, 인원 보존 |
| 결함 발생·검출·재작업 (`defect-chain`) | 3.5.2.1~3.5.2.3 그림 3.56~3.58 | 오류 발생 = 개발률 × 밀도(코플로), 검출 효율로 검출·미검출로 분할, 검출한 오류는 지연 뒤 재작업 | 125일, 검출 못 한 오류 240 |

**정한 것**
- 모든 모델 JSON에 **불변식**(작업 규모 보존, 인력 보존, 오류 보존)을 선언했고 구조 점검 화면이 그대로 쓴다.
- **책에 이 모델들의 수치 결과가 없다.** 검증은 책이 준 방정식의 닫힌 형식 해·정확한 관계와의 일치다(아래 3장). 학습곡선의 S자 모양은 책 그림 3.39를 매끈한 곡선으로 둔 것이고 **수치는 책의 값이 아님**을 모델 설명에 적었다. 기본값(인원, 생산성, 지연 등)은 구조를 보기 좋게 고른 값이다.
- **Rayleigh 모델의 완료**는 누적 공수가 추정치의 99%(설정 가능)에 이른 시점이다(추정치에 점근하므로 100%에는 닿지 않는다). 진척은 누적 공수 ÷ 태스크당 공수로 태스크에 환산해 통제(EVM)에 쓴다.
- **생산과 재작업의 완료**는 남은 일이 0.5태스크 이하일 때다(재작업은 지수적으로 줄어 0이 되지 않으므로, 이 허용 오차는 입력 항목이다).
- **결함 체인의 총 공수**는 개발이 끝난 뒤 검출한 오류를 마저 고친 공수까지 포함한다(실행이 끝난 시점의 누적 공수).
- **재예측·시정 조치 시험은 지원하지 않는다.** 두 기능은 모델마다 상태를 실적으로 덮어쓰는 어댑터가 필요해 프로젝트 모델(Brooks, 통합)에만 있다. 구조 모델에서는 통제 탭에 이유가 보이고(`reforecastUnsupported`), 스토어 액션도 같은 이유를 돌려준다. 실적에 따른 CPI·SPI·경고와 완료 예측은 그대로 쓸 수 있다.
- 구현: `packages/models/src/*.json`(5개)·`index.ts`, `catalog/structures.ts`(항목 5개와 공통 도우미), `catalog/types.ts`(`category`, `size`), `catalog/index.ts`(`catalogGroups`), `engine/models.ts`.
- 도움말에 용어 4개(생산과 재작업, 학습곡선, Rayleigh 곡선, 코플로와 분할 흐름)와 "기본 구조 라이브러리로 구조 익히기" 안내를 더했다(용어 44개, 안내 5건).

## 3. 시험

전체: analysis 564, models 229(+40), engine 193, desktop 1,094(+144) 통과. 타입 검사·`npm run build` 통과.

- `packages/models/test/structures.test.ts` 40개. **닫힌 형식과 정확한 관계로 확인**:
  - 공통: 컴파일·id·version, 불변식이 여러 조건에서 성립, 같은 입력은 비트 단위로 같음.
  - 생산과 재작업: f=1이면 재작업 없이 80일·공수=인원×80, 지연 1일이면 총 작업 job/f의 100일에 가까움, 품질·발견 지연의 단조성, 개발률 분해.
  - 학습곡선: 배율 일정이면 80일, 시작·끝 배율, 단조 증가와 S자(가운데가 가파름), 50%에서 두 값의 가운데, 생산성 = 공칭 × 학습곡선.
  - **Rayleigh: 누적 공수가 K·(1−e^(−bt²/2))를 따름(Euler 오차 0.3% 이내), dt를 줄이면 오차가 줄어듦, 정점 시각 1/√b = 100일과 높이 K·b·t·e^(−1/2), 99%·95% 도달 시점이 √(2·ln100/b)·√(2·ln20/b)**.
  - 인력 체인: 정지하면 완료 = job ÷ (공칭×환산 인원), 신입 단계가 E(t) = rτ + (E₀−rτ)e^(−t/τ)를 따름, 인원 보존, 채용을 늘리면 신입이 먼저 늘고 선임은 지연, 완료하면 채용 중단.
  - 결함 체인: 오류 = 개발률×밀도, 검출 못 한 오류 = (1−e)·600, 고친 오류 = e·600, 양 끝(e=0, 1), 지연이 길수록 쌓임, 총 공수 = 개발 + 오류 × 오류당 공수.
- 기존 **카탈로그 공통 시험이 새 모델 5개에도 자동으로 적용**되어 통과했다(모든 상수가 폼에 있음, 지표 정의, EVM 어댑터, 허용 범위 안 무작위 조합 100개가 수치 오류 없이 실행됨). 이 시험이 설계 몇 가지를 바로잡았다(모든 상수를 폼에 둠, 완료 전 실행이 null이어야 해서 결함 체인 규모 400 → 500, Rayleigh 완료 비율 95% → 99%).
- `stores/structures.test.ts` 31개: 모델 5개마다 기준 실행, 프리셋을 시나리오로 일괄 실행·채택, **구조 점검 S1~S6 실패 0**, **극단 조건 시험에서 허용 범위 안의 값은 실패 0**, 위험 분석 입력, 그리고 재예측 미지원 안내.
- **브라우저**: 모델 목록이 두 묶음, 통합 모델에서 30,000 SLOC → 500태스크로 환산·적용·"지금 규모 ≈ 30,000 SLOC"·2태스크는 "허용 범위(20~5000)" 오류와 적용 비활성, Rayleigh 모델의 종 모양 그래프와 프리셋 4개 겹쳐 보기.
- 확인하지 못한 것: Electron 앱 화면(이번 변경은 렌더러와 모델 데이터라 개발 서버 화면으로 확인했다). 메뉴의 모델 목록은 7개로 늘어난다(메뉴 구조는 단위 시험).
