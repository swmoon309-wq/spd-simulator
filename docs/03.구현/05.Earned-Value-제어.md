## 2. 지표 정의

| 양 | 구현 |
|---|---|
| 진척률 P | `Σ(w_k × N_k) / N_total`. 통합 모델 개발 0.5 / QA 0.2 / 시험 0.3, Brooks 개발 완료 1.0. 비율은 기준선 스냅샷에 함께 저장해 기준선과 실적이 같은 비율을 쓴다. |
| BAC | 기준선 완료 시점의 누적 공수(맨데이) |
| PV(t) | 기준선의 **계획 공수 곡선**(`pvAt`): 선형 보간, 계획 완료 뒤에는 BAC로 평평 |
| EV(P) | 계획이 진척률 P에 **처음 도달할 때까지 쓴 공수**(`evAt`): 진척 곡선을 이분 탐색, 평탄 구간은 처음 도달 시각, 계획 완료 진척 `P_end` 이상은 `BAC × P / P_end`로 비례 확장 |
| CV, SV | `EV − AC`, `EV − PV` |
| CPI, SPI | `EV / AC`, `EV / PV`. 분모가 0이면 `null`("–"로 표시, 0이나 무한대로 보이지 않음) |
| 구간 지수 | 최근 k(기본 3)개 보고 구간의 증분 비. 보고가 k개 미만이면 출발점(0)부터 센다. |
| 추세 | 구간 지수가 연속 n(기본 3)번 하락하면 "악화 중"(값이 n+1개 필요, null이 섞이면 아님) |

**설계 변경 (비용 정렬)**: 처음에는 설계대로 `EV = BAC × P`, `PV = BAC × P_기준선`으로 구현했다. 그러자 시뮬레이션 기준선에서 "실적 = 계획"이어도 **CPI가 1이 아닌** 현상이 시험으로 드러났다(Brooks 기준선 50일에 CPI ≈ 2.2). 시뮬레이션이 쓴 공수 곡선(AC)이 `BAC × P(t)`와 같지 않기 때문이다. 사용자 결정(후보 A)으로 PV와 EV를 모두 계획의 공수 곡선에 정렬했다. 이제 실적이 계획과 같으면 EV = PV = AC라서 CPI = SPI = 1이고, 같은 진척을 25% 더 많은 공수로 하면 CPI 0.8·SPI 1이 된다. 진척과 공수가 비례하는 선형 계획(책 시험 1단계)에서는 이전 정의와 일치한다.

## 3. 실적 입력 (CTL-01, CTL-02)

- **레코드**: `{day, cum{단계 변수: 누적 태스크}, effort, headcount?, defects?, note?}`. 값은 모두 누적이다.
- **검증**(`validateActuals`): 오류(행을 계산에서 제외) — 보고일 0 이상·**이전 정상 행보다 커야 함**, 공수·단계·인원·결함이 유한한 음이 아닌 수, 메모 200자 이하, 행 400개 이하. 경고 — 단계 칸이 비어 0으로 봄, 누적값·공수·결함이 이전 행보다 줄어듦, 단계 순서(개발 ≥ QA ≥ 시험) 어긋남, 개발 완료가 총 태스크의 1.5배 초과("범위 증가인가요?"). 순서 검사는 마지막 **정상** 행과 비교하므로 오류 행 하나가 뒤 행을 연쇄로 오류로 만들지 않는다.
- **파일 스키마**: `actuals[]`는 구조(유한한 수, 최대 400행, 메모 200자)만 검사하고 내용 오류는 앱이 행마다 표시한다. **설계의 "저장 불가"와 달리 오류 행도 저장한다**(입력을 잃지 않도록). 없으면 `[]`. 다른 모델의 단계 변수가 든 실적은 열 때 버리고 경고한다.
- **스토어**: `addActual`(7일 간격으로 이전 값을 이어받음, 400건이면 거부), `updateActual`(일부 항목, 단계 값은 합침), `removeActual`, `clearActuals`, `setActuals`(일괄, 한도 초과면 거부). 변경됨 표시·저장·열기에 포함한다. 채택을 해제하거나 시나리오를 지워도 실적은 남는다.
- **CSV 가져오기**(`actualsCsv.ts`): 첫 열이 보고일, 나머지 열을 단계 변수 이름·라벨, `effort`/누적 공수/공수/AC, 인원, 결함, 메모에 대소문자·공백·"(단위)"를 무시하고 맞춘다. 구분자 자동 판별(세미콜론은 소수점 쉼표), BOM 허용. 맞지 않는 열은 무시하고 알리며, 내보낸 계산 열(PV·EV·CV·SV·CPI·SPI·progress)은 조용히 건너뛴다. 공수·단계 열이 없거나, 숫자가 아닌 값(행·열 표시), 빈 보고일·빈 공수, 같은 항목 열 중복, 400행 초과는 거부한다.
- **합치기**: 이미 실적이 있으면 덧붙이기/교체/취소를 묻는다. 덧붙이기는 같은 보고일을 새 값으로 덮고 보고일 순으로 정렬한다(400건 초과면 거부).
- **증분 입력**: 설계의 "증분 입력 토글" 대신 **증분 입력 폼**으로 구현했다(경과 일수, 단계별 증가, 구간 공수, 현재 인원(시점 값이라 더하지 않음), 결함 증가). 이전 누적에 더한 누적 행을 추가한다.
- **내보내기**: 입력 열 + 진척률·PV·EV·CV·SV·CPI·SPI. 오류 행은 계산 열을 비운다. 내보낸 파일을 다시 가져오면 입력이 같다(시험). IPC는 기존 `files.importCsv/exportCsv`를 그대로 썼다.

## 4. 경고 (CTL-05)

`EvmSettings{k, alerts{warn 0.9, critical 0.8, trend 3, early{progress 0.15, cpi 0.9}}}`. `validateEvmSettings`는 구간 1~10 정수, 임계값 유한·0 초과·2 이하, 위험 ≤ 주의, 연속 하락 2~10 정수, 조기 경고 진척률 0~1·CPI 0 초과 2 이하를 검사한다. `evaluateAlerts`가 보고일마다 평가한다: CPI·SPI 임계값(위험 < 0.8 ≤ 주의 < 0.9, 계산 불가 지수는 건너뜀), 구간 지수 연속 하락(그 보고일까지의 값으로 판단, "악화 중"), 조기 경고(진척률 ≥ 15%이고 CPI < 0.9이면 "회복이 어렵습니다…", 수준은 위험). `statusAt`은 그날 가장 심각한 수준(정상·주의·위험, 보고가 없으면 –)을 돌려준다. 설정은 프로젝트 파일 `evm` 필드(없으면 기본값)에 저장하고, 구조만 스키마가 검사하며 값 검사는 열 때 한다(잘못되면 기본값으로 돌리고 경고).

## 5. 예측 (CTL-06)

`forecastAt(baseline, points, i, k)`는 선택한 보고일의 예측을 돌려준다. 모든 수식은 표준 EVM이다.

- **비용**: `EAC = AC + (BAC − EV)/CPI`, `ETC = EAC − AC`, `VAC = BAC − EAC`. 누적 CPI와 최근 구간 CPI_k로 두 값을 내고 범위(낙관 ~ 비관, `rangeOf`)로 보인다. CPI가 상수이면 EAC가 실제 최종 비용과 같음을 시험한다.
- **일정**: **획득 일정** `ES`(`earnedSchedule`)는 PV 곡선이 EV에 처음 도달한 시각(선형 역산, 평탄 구간은 처음 도달, BAC 이상은 계획 완료일). 예상 완료일 = `t + (계획 기간 − ES) / 속도`. 누적 속도는 ES/t(= SPI_t, 결과는 계획 기간/SPI_t와 같음), 최근 구간 속도는 최근 k개 보고 구간의 ES 증가량/일수(설계 문장의 "최근 구간 SPI_k"를 ES 기준으로 구체화).
- **산출 불가**: AC=0이면 비용 불가(일정은 계산), EV=0이면 둘 다 불가, 보고일 0이면 일정 불가. 이유를 문장 목록으로 보인다.
- **완료**: EV ≥ BAC(범위 증가로 넘는 경우 포함)이면 예측 대신 **처음 완료한 보고일**과 그날의 최종 공수를 보인다. 나중 보고일을 골라도 같다.

## 6. 화면 (통제 탭)

위에서 아래로: 채택 배너와 **보고 기준일** 선택(기본 최근, 과거를 고르면 그날의 지표·예측; 기준선의 모델 버전이 다르면 경고) → 핵심 지표 카드(CPI, SPI, CV, SV, 진척률, 상태 ●정상 ▲주의 ■위험) → 예측 영역(예상 완료일·EAC·ETC·VAC의 범위, "현재의 효율이 남은 작업에도 계속된다는 가정의 추정이며 예측이 아닙니다" 문구, 제한 사유; 완료하면 "완료" 영역) → 차트 3장(`EvmChart`, ECharts) → 경고 목록(최근 보고일 먼저)과 경고 설정 폼(올바른 값은 바로 저장, 잘못된 값은 이유만 표시, 기본값으로) → 실적 입력 표(행마다 오류·경고, 삭제, 모두 지우기 확인) → CSV 가져오기·내보내기·증분 입력 → 지표 표(진척률, PV·EV·AC, CV·SV, CPI·SPI, 구간 지수, 지수 < 1은 ▼ 병행, 계산 불가 "–").

| 차트 | 내용 |
|---|---|
| A | PV(점선, 예상 완료일까지 연장), EV(실선+점), AC(점선+점), 선택한 보고일에서 BAC까지 EV 예측·EAC까지 AC 예측(점선), BAC 가로선, 계획 완료일·예상 완료일·기준일 세로선 |
| B | CV·SV와 0선 |
| C | 누적 CPI·SPI, 최근 구간 CPI·SPI, 1.0선 |

색에만 기대지 않도록 선 모양(실선·점선)과 점을 함께 쓰고, 차트마다 마지막 값을 요약한 `aria-label`을 둔다. 채택이 없으면 안내만 보이고(실적은 입력·저장 가능), 실적이 없으면 PV 곡선만 보인다.

## 8. 설계와 달라진 점

- PV·EV를 계획 공수 곡선에 정렬(§2). 설계 문서 2.2와 13장에 반영했다.
- 실적의 오류 행도 저장한다(설계 4.2의 "저장 불가"를 바꿈).
- 증분 입력은 토글이 아니라 폼(§3).
- 최근 구간 일정 예측을 ES 증가 속도로 구체화(§5).
- 조기 경고의 수준을 "위험"으로 정했다.

## 9. 알려진 한계

- 진척이 아주 작은 초기 보고(예: 10일에 1% 미만)에서는 속도가 작아 예상 완료일이 터무니없이 크게 나온다(예: 1,000일). 지금은 그대로 보인다. 진척률이 낮을 때 "초기 외삽은 불안정" 안내를 붙일지는 사용해 보고 정한다.
- 경고 설정 폼은 탭을 연 뒤 다른 경로로 설정이 바뀌면(열기 등) 탭을 다시 열 때 맞춘다.
- 조치 시험·계획 개정은 [08](08.시정-조치-시험과-계획-개정.md), 재예측은 [07](07.시뮬레이션-기반-재예측.md)에서 구현했다.
