# 48. 데스크톱 앱 패키징 (macOS)

개발 환경 없이 설치해 쓸 수 있도록 앱을 `.dmg`와 `.zip`으로 묶었다. 앞 단계: [03](03.데스크톱-앱-골격.md), [27](27.메뉴-설정-도움말.md).

## 1. 한 일

| 항목 | 내용 |
|---|---|
| 도구 | `electron-builder` 26(개발 의존성) |
| 명령 | `npm run package -w @spd/desktop`(빌드 + `release/mac-arm64/SPD.app`만), `npm run dist -w @spd/desktop`(빌드 + `.dmg` + `.zip`) |
| 산출물 | `apps/desktop/release/SPD-0.1.0-arm64.dmg`(약 132 MB), `SPD-0.1.0-arm64-mac.zip`(약 128 MB). `release/`는 `.gitignore`에 넣었다 |
| 대상 | macOS arm64(Apple Silicon)와 Windows x64. Intel Mac은 만들지 않았다 |
| Windows | `npm run dist:win -w @spd/desktop` → `release/SPD Setup 0.1.0.exe`(NSIS 설치 프로그램, 약 122 MB, 설치 폴더 선택 가능)와 `release/SPD-0.1.0-win.zip`(약 155 MB, 풀어서 `SPD.exe` 실행). **macOS에서 교차 빌드**했다(Wine 없이 되도록 `signAndEditExecutable: false`) |
| 설정 | `apps/desktop/package.json`의 `build` 필드(appId `kr.spd.simulator`, 파일은 `out/**`만, asar) |
| 의존성 정리 | 렌더러에 번들되는 패키지(react, echarts, zustand, `@spd/*` 등)를 `devDependencies`로 옮기고 **메인 프로세스가 런타임에 읽는 `zod`만 `dependencies`**에 남겼다. 번들되는 패키지를 `dependencies`에 두면 작업 공간 패키지의 TypeScript 소스가 앱에 들어간다 |

## 2. 알아 둘 것(문제와 해결)

- **앱 이름에 한글을 쓰면 시작하자마자 죽는다.** 처음에 `productName`을 한글로 두었더니 실행 즉시 `SIGTRAP`(충돌 보고서: 메인 스레드, Electron Framework)으로 종료되고 macOS가 “다시 열기” 창을 반복해서 띄웠다. 원인은 macOS 파일 시스템이 한글 파일 이름을 자모로 분해해 저장하는데(`NFD`) 앱 설정 파일의 이름은 합쳐진 글자(`NFC`)라서, Electron이 보조 프로그램(`… Helper.app`)을 찾지 못하는 것이다(실제로 Frameworks 폴더의 이름은 NFD, plist는 NFC였다). **앱 파일 이름을 영문 `SPD`로 하고, 창 제목은 코드에서 한글(`소프트웨어 프로젝트 시뮬레이터`)로 둔다.** Dock과 메뉴 막대의 앱 이름은 `SPD`이다.
- **서명하지 않았다.** 인증서가 없어 ad-hoc(임시) 서명만 있다. Apple Silicon에서는 서명이 없으면 실행되지 않으므로 서명을 끄지 않고(`identity: null`을 쓰지 않음) 기본 동작인 ad-hoc 서명에 맡겼다. 다른 Mac에서 내려받아 처음 열면 “확인되지 않은 개발자” 경고가 뜬다(아래 3).
- **아이콘이 없다.** 기본 Electron 아이콘을 쓴다. `build/icon.icns`를 두면 쓴다.
- **전자 버전을 고정했다**(`electronVersion: 44.9.1`). `electron-builder`는 범위(`^44.9.1`)를 받지 않는다. Electron을 올릴 때 이 값도 올린다.
- 데이터 위치: `~/Library/Application Support/@spd/desktop`(설정, 최근 프로젝트, 자동 저장).

- **Windows 교차 빌드의 제약**: 실행 파일의 아이콘·버전 정보(속성 창의 제품명 등)는 편집하지 않아 기본 Electron 값이 보인다. 서명이 없어 처음 실행하면 **SmartScreen 경고**(“Windows의 PC 보호”)가 뜨며 **추가 정보 → 실행**으로 넘긴다. **Windows에서 실행해 보지는 못했다.** 문제가 있으면 Windows PC에서 저장소를 받아 `npm install` 후 `npm run dist:win -w @spd/desktop`으로 다시 만들면 된다(그 환경에서는 `build.win.signAndEditExecutable`을 지워도 된다).

## 3. 설치와 첫 실행

1. `SPD-0.1.0-arm64.dmg`를 열고 **SPD**를 **Applications**로 끌어다 놓는다(또는 zip을 풀어 `SPD.app`을 응용 프로그램 폴더에 둔다).
2. 처음 열 때 “확인되지 않은 개발자” 경고가 뜨면 **시스템 설정 → 개인정보 보호 및 보안**에서 **그래도 열기**를 누른다(또는 Finder에서 앱을 Control-클릭 → **열기**). 한 번만 하면 된다.
3. 터미널에서 풀려면 `xattr -dr com.apple.quarantine /Applications/SPD.app`.

## 4. 확인한 것

- 패키지된 앱을 실행해(원격 디버깅으로 연결) **창 제목**, **데스크톱 API**(`window.spd`: 프로젝트·파일·보고서·최근·복구·설정·모델·대화상자 등)가 있음, “데스크톱 앱에서만 사용할 수 있습니다” 문구가 없음, **파일에서 열기 버튼이 활성**, 실험 탭의 **실행이 되어 `#1 기준 274.1일`**이 나옴.
- `.dmg`를 열어 `SPD.app`과 `Applications` 바로가기가 있고 ad-hoc 서명이 있음을 확인했다.
- 타입 검사와 전체 시험은 그대로 통과(패키징은 소스를 바꾸지 않았다).
- **확인하지 못한 것**: **Windows에서의 설치와 실행 전부**, 다른 Mac에서의 첫 실행(Gatekeeper), 저장·열기·PDF 저장 같은 파일 대화상자 흐름(대화상자는 자동화할 수 없음), Intel Mac, 자동 업데이트.
