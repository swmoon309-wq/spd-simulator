# 모델 검증: 데이터 가져오기·비교 화면과 파일 저장 (설계 07의 순서 2)

설계: [07.모델검증설계.md](../02.설계/07.모델검증설계.md) 2~3장, 7장(데이터 비교 하위 탭), 8장(`validation`). 계산 모듈은 [15](15.검증-지표와-정렬.md).

## 1. 구현한 것

새 탭 **검증**(실험 / 시나리오 / 통제 / 위험 분석 / 검증)에서 실제 데이터를 가져와 변수에 연결하고, 같은 조건의 시뮬레이션과 비교해 지표 표와 그래프를 본다.

| 영역 | 내용 | 파일 |
|---|---|---|
| 가져오기 | CSV(기존 `parseReferenceCsv`: 첫 열 시간, 나머지 열마다 시계열, BOM·세미콜론·소수점 쉼표 처리)를 데이터셋으로 만든다. 열 이름이 모델 변수와 맞으면(`matchVariable`) 자동 연결, 나머지는 "비교 안 함". 한도(5개·20열·열당 5,000점·합계 50,000점)를 넘으면 이유와 요약·다운샘플 안내와 함께 거절한다. 데스크톱 앱에서만 가져올 수 있다 | `lib/validation.ts`(`datasetFromCsv`), `lib/fileActions.ts`(`importDatasetCsv`) |
| 데이터셋 관리 | 이름, **시간 단위**(일·주·월), **시간 이동**(일), **실제 완료일**(선택), 삭제(한 번 더 확인). 변경은 즉시 저장 안 됨 표시에 반영 | `DatasetPanel.tsx`, `OptionalNumber.tsx` |
| 열 연결 | 열마다 모델 변수 선택(또는 비교 안 함)과 **값 배율**(0보다 큰 수). 시뮬레이션 범위 밖·무효로 뺀 점 수를 보인다 | `ColumnMapping.tsx` |
| 비교 대상 | 기준 또는 시나리오. **시나리오 탭의 실행·캐시·"오래됨" 판정을 그대로 쓴다**(`runScenarios`, `taskFor`/`rowStatus`): 같은 입력이면 다시 계산하지 않고, 입력이 바뀌면 "오래되었습니다"와 함께 이전 결과를 흐리게 비교한다 | `ValidationTab.tsx` |
| 지표 표 | 열마다 n, ME, RMSE, 정규화 RMSE, MRE, NSE, Theil 분해(U^M·U^S·U^C), 추세 일치율, 사용자가 정한 기준의 **✓ 안 / ✗ 밖**(기준이 없으면 "기준 없음"). 종합 J, 완료 시점 오차. 해석 안내(편향 vs 비체계 오차, 상관의 한계) | `MetricsTable.tsx`, `lib/validationView.ts` |
| 그래프 | 관측(◆)과 시뮬레이션(선)을 겹친 그래프, **잔차**(시뮬레이션 − 관측) 그래프, 같은 값의 짝 표(접기). 차트에 요약 `aria-label` | `ValidationCharts.tsx` |
| 허용 기준 | 정규화 RMSE·MRE·MAPE·NSE·추세 일치율. **기본값 없음**(설계 12장 결정). 범위 검사(음수 불가, 추세는 0~1 등) | `DatasetPanel.tsx`, `lib/validation.ts` |
| 파일 | `validation` 필드(없으면 `null`): 데이터셋(열·점·변수·배율·시간 단위·이동·실제 완료일), 허용 기준, 비교 대상. **지표·잔차는 저장하지 않고** 열 때마다 다시 비교한다. 스키마 한도 검사(5·20·5,000·50,000), id 중복 거부 | `shared/projectFile.ts` |
| 열 때 정리 | `sanitizeValidation`: 모델에 없는 변수는 **연결만 풀고 데이터는 남기며** 경고, 올바르지 않은 배율은 1로, 올바르지 않은 기준은 버리고, 없는 비교 대상은 기준으로 돌린다 | `lib/validation.ts`, `lib/projectApply.ts` |
| 변경됨 표시 | `snapshotOf`에 검증 설정을 넣었다. 활성 데이터셋 선택은 UI 상태라 포함하지 않는다 | `lib/params.ts`, `stores/appStore.ts` |

차트 훅 `useEChart`는 위험 분석과 검증이 함께 쓰도록 `components/useEChart.ts`로 옮겼고 산점도(`ScatterChart`)를 등록했다.

## 2. 설계와 다른 점

- 하위 탭 4개(데이터 비교·극단/교란·구조 점검·보정) 중 **데이터 비교만** 있어 하위 탭 막대를 두지 않았다(빈 탭을 만들지 않기 위함). 나머지는 순서 4~6.
- 설계 8장의 `checklist`·`presets`·`report`는 해당 순서에서 추가한다. 모두 기본값이 있는 선택 항목으로 더할 것이므로 이 단계의 파일과 호환된다.
- **실제 완료일**은 설계 3.2의 "또는 사용자가 입력"을 구현한 것으로, 데이터셋마다 한 값이다(열의 마지막 값에서 추정하는 방식은 하지 않았다).
- 같은 조건 비교는 대상의 **유효 파라미터와 실험 탭의 실행 설정**으로 한다. 실제 시계열을 모델에 주입하는 것은 지원하지 않는다(설계 2장).

- **Electron E2E 37개**(임시 작업 폴더의 스크립트, 앱을 `--inspect`·`--remote-debugging-port`로 띄우고 대화상자를 가짜로 교체). 데이터는 앱 자체의 "비교 CSV 저장"으로 만든 실제 실행의 주 단위 값이다. 가져오기(안내·알림) → 열 연결·시간 단위 → 실행 → **RMSE 0·NSE 1.00·추세 100%**, 허용 기준 안(✓)·잘못된 배율 2배는 밖(✗, NSE 0.21), 배율 0 거절, 단위를 일로 잘못 두면 지표가 나빠짐(NSE −0.46), 주로 되돌리면 다시 일치, 완료 시점 오차(274.1일 − 300일 = −25.9일), 저장(파일에 지표 없음) → 새 프로젝트(비움) → 열기(데이터·단위·연결·기준·실제 완료일 복원, 다시 실행하면 같은 일치), 범위 밖 점 1개 알림, 다섯 개까지 가져오고 여섯 번째는 거절, 고친 파일(없는 변수·없는 대상)은 연결을 풀고 경고하되 데이터(57점)는 남김, `validation` 없는 파일은 데이터 없이 열림. renderer·main 콘솔 오류 없음. 화면 캡처로 관측 점이 시뮬레이션 곡선에 겹치고 잔차가 0임을 확인했다.
- 개발 서버(renderer 전용)에서는 파일 가져오기가 안 되므로 이 화면은 Electron으로 점검했다.
