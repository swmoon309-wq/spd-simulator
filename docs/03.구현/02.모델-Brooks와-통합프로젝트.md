## 1. Brooks 법칙 모델 (MDL-01)

| 항목 | 내용 |
|---|---|
| 규모 | 상수 11, Level 6, Rate 4, Auxiliary 5. 시간 0~400일, dt 0.25 |
| 구조 | 요구사항 → 개발 완료(`requirements`, `developed_software`), 신입·숙련 인원 Level, 신입의 동화(`assimilation_time`), 의사소통 오버헤드(`comm_overhead_coeff × n²`), 신입 훈련에 드는 숙련자(`training_overhead`) |
| 개발률 | `nominal_productivity × productive_capacity × (1 − communication_overhead)`, 가용 숙련 인력은 훈련에 쓰는 만큼 뺀다 |
| 실험 파라미터 | `extra_people`(추가 투입 인원), `hire_day`(투입 시각, 기본 110일). `PULSE(extra_people / DT, hire_day, DT)`로 한 번에 들어온다 |
| 누적 공수 | `cum_effort`(유입 `total_personnel`, 맨데이)를 시나리오 비교·Earned Value용으로 추가했다 |

### 정량 검증 (책 1.4.1, p.19~21)

| 책의 수치 | 모델 결과 | 시험 허용 |
|---|---|---|
| 숙련 20명만: 274일 | 274.12일, 개발률은 해석값 20·0.12·(1−0.24) = 1.824 FP/일로 일정 | ±0.5일 |
| 110일에 5명 추가: 271일 | 약 272.0일 | ±2일 |
| 110일에 10명 추가: 296일 | 약 294.6일 | ±2일 |

책은 투입 시점을 "일정 편차 15% 시점(약 110일)"이라고만 적었다. 그래서 시점을 파라미터로 두고, **책의 두 수치(271, 296)를 ±1일 안에서 동시에 맞추는 투입 시점이 80~110일 사이에 있음**을 따로 시험한다. 그 밖에: 요구사항과 개발 완료 규모의 합이 500 FP로 보존, 완료 후 정지, 투입 시각이 종료 이후이면 결과가 기준선과 같음, +10명은 일찍 추가할수록(90 → 120일 비교) 완료가 단조롭게 늦어짐(지연이 커짐), 투입 직후 개발률이 급락한 뒤 회복(책 그림 1.10), 누적 공수가 총 인원의 Euler 합과 같음, 인원을 추가하면 공수가 는다(책 p.21), 엔진 정합성(dt 변경 등).

## 2. 통합 프로젝트 모델 (MDL-02, 4섹터 단순판)

| 항목 | 내용 |
|---|---|
| 규모 | 상수 41, Level 26, Rate 22(이후 추가분 포함), Auxiliary 60, 출력 12. 시간 0~400일, dt 0.25 |
| 섹터 | 변수 이름 접두어로 구분한다: 인력 `hr_`, 계획 `plan_`, 생산 `prod_`, 오류 `err_`, 통제 `ctl_`, 소진 `exh_`(시험으로 접두어가 모두 쓰임을 확인). 상수는 접두어 없이 이름만 쓰는 것이 많다. |
| 핵심 흐름 | 개발 → QA → 시험 순 태스크 흐름, 오류 발생·검출·수정, 인식 규모(과소추정)와 계획 일정의 시간 지연 조정, 일정 압박 → 업무 비율·소진·QA 인력 비율·오류 배수, 신입/숙련 인력의 채용·동화·이직·전출 |
| 신뢰 수준 | 책(6.3, 4.3~4.4)에는 구조와 일부 수치만 있어 **수치는 책과 정량 일치하지 않는다**. 값마다 출처 표시(책·책-그림·설계·가정)를 명세에 두었고, 검증 기준은 정성 거동과 불변식이다. 그림 6.6·6.7·4.5·4.6의 곡선은 `pdftoppm`으로 읽어 `GRAPH` 값을 보정했다. |
| 기본 설정 결과 | 완료 314.25일(계획 200일 대비 +57%), 총 투입 공수 1,224 맨데이, 잔존 결함 추정 약 7.9. 과소추정 없음 266.0일·1,094 맨데이. |

### 구현 중 발견·수정한 결함 (범위 시험과 퍼징으로)

- 시험 인력 비율 분모가 0일 때 `exh_flow`가 0/0이 되어 NaN → `MAX` 가드로 고침.
- `prod_test_rate` 분모 0 → 같은 방식으로 가드.
- QA 지연을 단일 지연으로 두면 태스크가 보존되지 않아 **3단 체인(Level 3개)**으로 바꿔 보존을 확보.
- 허용 범위 안의 파라미터 조합을 무작위로 돌려 NaN·무한대·음수 Level이 없음을 확인(카탈로그 시험이 이 범위를 사용).

### 통합 모델 시험 (41개)

| 영역 | 확인한 것 |
|---|---|
| 모델 정의 | 컴파일됨, 모든 상수에 라벨·단위, 모든 Level·Rate·Auxiliary에 단위, 네 섹터 접두어, 기본 실행이 종료 안에 끝남, 완료 시각과 시험 종료의 일치(한 스텝 이내) |
| 6.3 불변식 | ① 모든 Level ≥ 0 ② 시험 ≤ QA ≤ 개발 ≤ 총 태스크, QA 파이프라인 보존 ③ 오류 보존(발생+불량 수정 = 잠재+검출+QA 통과+수정 완료+시험 발견) ④ 누적 공수 = 총 인원의 Euler 합 ⑤ 같은 입력은 비트 동일(난수 없음, 시드 무관), 인식·미발견·반영 대기 태스크 합 보존, 소진 ≤ 한도 |
| 시작 상태 | 압박 0·업무 비율 기준값·소진 0·인력 초기 인원, 초기 인원 0이면 채용도 진행도 없음 |
| 6.2 정성 거동 | 과소추정 없음/있음(인식 규모 268 → 400, 계획 일정이 지연을 두고 상승, 실제 완료가 초기 계획보다 늦음, 늦은 증원), 일정 압박·소진(업무 비율 상승, 과로 한도, 회복), QA 인력 비율 감소(15% → 7.5%)와 오류 배수 증가, 과로 차단(`max_boost=0`), 신입 비율 효과(생산성·오류·동화 회복), 채용 지연, `plan_wcwf1/2` 경계값, 인원 상한, 규모, dt 민감도(0.25 vs 0.125) |
