# 모델 검증: 극단 조건·교란 시험과 화면 (설계 07의 순서 4)

설계: [07.모델검증설계.md](../02.설계/07.모델검증설계.md) 4.1~4.2장(VAL-03, VAL-06), 7장(극단·교란 하위 탭). 앞 단계: [17](17.검증-불변식과-구조-점검.md).

## 1. 구현한 것

검증 탭에 하위 탭 **데이터 비교 / 극단·교란 시험**을 두고, 대상(기준 또는 시나리오) 선택을 공통 머리글로 올렸다. 극단·교란 탭은 세 영역이다.

| 영역 | 내용 | 파일 |
|---|---|---|
| 극단 조건 시험 | 폼의 모든 파라미터를 **최소·최대·0·현재 값의 ×10·×0.1**로 한 번에 하나씩 바꿔 실행하고 판정(통과·주의·실패·정보). 파라미터 × 수준 표(✓▲✗ⓘ 글자 기호), 상태별 개수, "문제가 있는 파라미터만" 거르기, 실패(범위 안 오류)는 결함 후보 목록. 셀을 누르면 판정 이유·지표·**대상 실행과 겹친 그래프**(그 값으로 다시 실행해 그림). 진행 막대·중단(그때까지의 셀 유지)·오래됨 표시 | `analysis/validation/extremes.ts`, `ExtremesPanel.tsx` |
| 교란 시험 | 상수에 **스텝·펄스·램프**를 걸어 기준 실행과 비교. 크기는 새 값(절대) 또는 현재 값 대비 ±%, 시작·폭, 보고 변수 여러 개. 변경 목록, 반응 요약(최대 편차·시각·기준 대비·**복귀 시각 또는 "복귀 안 함"**·마지막 편차·음수 여부), 기준 vs 교란 그래프(변경 시각 점선) | `analysis/validation/perturb.ts`, `PerturbPanel.tsx` |
| Level 변화 점검 | 짧은 구간(기본 40일)을 실행해 시작 대비 변하는 Level을 변화량 순으로(시작·끝·변화·비율·움직임). **정상 상태인지는 판정하지 않는다**(책 2.7.1: 사람이 범인을 찾음) | `perturb.ts`(`levelChanges`), `LevelCheckPanel.tsx` |

스토어: `validationExtremes`·`validationPerturb`·`validationLevels`와 액션 `runExtremes`·`cancelExtremes`·`runPerturb`·`runLevelCheck`, 오래됨 선택자 3개. 결과는 파일에 저장하지 않으며 새 프로젝트·열기에서 비운다.

## 2. 정한 것(설계에서 구체화·해소한 것)

- **판정 기준의 모순을 해소했다.** 설계 4.1의 두 표가 어긋났다(앞 표: 범위 안의 음수 Level·불변식 위반 = 결함, 판정 표: 주의). **판정 표를 따라** 오류만 실패로 하고 음수 Level·불변식 위반은 주의로 했다. 범위 안의 오류 = 실패, 범위 밖의 오류 = 정보, 종료 시각 안에 끝나지 않음은 범위 안 = 주의·범위 밖 = 정보.
- **값 계획**: 같은 값은 한 셀로 합치고 수준 이름을 모두 남긴다(예: 현재 값이 0이면 0·×10·×0.1이 한 셀). 범위 안인지는 이름이 아니라 **실제 값**으로 가른다(최소가 0이면 0도 범위 안). 정수 파라미터는 반올림하고, 부동소수 잡음(0.1×0.1 = 0.010000000000000002)은 유효숫자 12자리로 정리한다.
- **램프**: `[day, day + width]`를 K = 10단 계단으로 원래 값에서 새 값까지 올리고(변경 K + 1개) 이후 새 값을 유지한다. 펄스는 폭이 끝난 스텝부터 원래 값, 스텝은 변경 1개. 변경은 해당 시각의 스텝부터 적용된다(엔진 `setConstant`, 2차의 조치 시험과 같은 방식).
- **복귀 시각**: 설계의 "편차가 5% 안으로 들어오는 시각"을 **최대 편차의 5% 이하로 줄어드는 첫 시각(최대 이후)** 으로 정의했다. 기준 값 대비 5%로 하면 누적량이 영구히 달라졌는데도 "복귀"로 나오기 때문이다. 누적량처럼 영구히 달라진 변수는 "복귀 안 함"이 된다.
- **실행 방식**: 설계 4.1은 Worker 메시지를 말했지만, 모델 한 번이 5 ms 안팎이라 **주 스레드에서 12 ms마다 UI에 양보**하며 나눠 실행한다(Worker 프로토콜을 늘리지 않음). 통합 모델 174개 값이 약 0.9초. 중단은 다음 양보 때 처리하고, 실행 중 프로젝트가 바뀌면 실행 번호로 늦게 끝난 결과를 버린다.
- 교란 시험의 기본값은 추가 투입 인원이 있는 모델이면 **+10명 스텝**(Brooks 법칙 실험), 아니면 첫 상수의 +20%이다. 처음에는 +20%였으나 현재 값이 0이면 반응이 없어 바꿨다. 초기값에만 쓰이는 상수는 시작 뒤에 바꿔도 반응이 없다는 안내를 폼에 둔다.
- 외부 신호를 Rate에 직접 넣는 시험은 지원하지 않는다(4차 모델 편집기). 화면에 명시한다.

## 3. 결과: 실제 두 모델의 극단 조건

폼의 허용 범위 기준으로 **두 모델 모두 허용 범위 안의 값에서 실패 0건**이다(2차 퍼징의 0/0 가드 두 곳 이후 새 결함 없음).

| 모델 | 값 수 | 통과 | 주의 | 실패 | 정보 |
|---|---|---|---|---|---|
| Brooks | 42 | 30 | 10 | 0 | 2 |
| 통합 프로젝트 | 174 | 129 | 16 | 0 | 29 |

주의는 대부분 극단 값(예: 요구사항 규모 100,000 FP, 생산성 0.001)에서 종료 시각 안에 끝나지 않는 경우이고, 통합 모델에서는 범위 밖의 두 값에서 Level이 음수가 되는 것이 잡혔다(`plan_known_fraction` 6.7: 미발견·반영 대기 태스크 음수, `planned_qa_fraction` 1.5: 인력·계획 일정·작업량 음수). 범위 밖이라 결함은 아니지만 사용자가 입력 범위를 이해하는 데 쓸 정보이다.

## 4. 시험

- `analysis/test/extremes.test.ts` 16, `analysis/test/perturb.test.ts` 22 (analysis 469 → 507): 값 계획(수준·범위 안 판정·합치기·정수·−0·부동소수·여러 파라미터), **판정 분류를 일부러 결함을 넣은 모델로 확인**(범위 안 0으로 나누기 = 실패, 범위 밖 = 정보, 음수 Level·불변식 위반 = 주의, 끝나지 않음 안/밖, 여러 이유 중 최악의 판정, 완료 지표 없음, 대상 시나리오 값에서 출발), 요약; 교란 변경 목록(스텝·펄스·램프, 절대·%, 단조), 입력 검사, **변경 없으면 비트 동일**, 스텝은 변경 이전이 기준과 비트 동일, 펄스는 폭 뒤 원래 값, 램프 단조, 시작 이하·종료 이후·순서 뒤섞인 변경, 반응 요약(스텝은 복귀 안 함, 펄스는 1차 지연으로 약 ln(20)·τ ≈ 15일 뒤 5% 이하, 반응 없음, 음수), 실제 모델 Brooks 법칙(90일째 인력 +10 → 총 인원 +10, 완료가 늦어짐), Level 변화 점검.
