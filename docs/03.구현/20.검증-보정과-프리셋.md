# 모델 검증: 파라미터 보정과 프리셋 (설계 07의 순서 6)

설계: [07.모델검증설계.md](../02.설계/07.모델검증설계.md) 5장(VAL-05), 6장(기록에 프리셋 요약), 7~8장. 앞 단계: [19](19.검증-구조-점검-화면과-기록.md).

## 1. 구현한 것

검증 탭에 네 번째 하위 탭 **보정**(데이터 비교 / 극단·교란 시험 / 구조 점검 / 보정)이 생겼다.

| 영역 | 내용 | 파일 |
|---|---|---|
| 보정 알고리즘 | 선택한 파라미터(최대 5개)로 `J(θ) = Σ w·NRMSE²`(열별 가중, NRMSE = RMSE / 관측의 평균 크기)를 줄인다. **유계 Nelder–Mead**(정규화 좌표 [0,1]^k로 사영)를 **다중 시작 5개**(현재 값 + 시드로 뽑은 라틴 하이퍼큐브 4개)로 돌린다. 시작점당 평가 상한 = 파라미터 수 × 200. 같은 입력(시드 포함)은 결과가 정확히 같다. 한 평가씩 진행하는 **생성기**(`calibrationSteps`)로 만들어 UI가 진행·취소를 처리한다 | `analysis/validation/calibrate.ts` |
| 시간 분할 검증 | 관측이 15점 이상이면 기본으로 앞 70%(시각 기준)로 보정하고 뒤 30%로 **보정에 쓰지 않은 구간의 J**를 보인다. 끄거나 비율을 바꿀 수 있다 | 같음 |
| 식별 가능성 진단 | **경계 도달**(보정으로 움직인 값이 허용 범위 끝에 붙음), **평탄**(±10% 움직여도 J가 1% 미만으로만 늘어남 → "정해지지 않는 파라미터"), **비유일성**(J가 비슷한 시작점들이 범위의 10% 넘게 다른 값에 도달), **자료 부족**(관측 점 < 파라미터 수 × 3), **과적합**(검증 J > 보정 J의 2배), 개선 없음·취소·제외한 열 | 같음 |
| 보정 화면 | 데이터셋·열(사용 여부·**가중치**)·파라미터(최대 5개, 기본 범위는 현재 값의 0.25~4배)·시간 분할, 실행·**중단**(그때까지의 최선 유지)·진행(시작점·평가 횟수·최선 J). 결과: 보정 구간·검증 구간의 J(전→후), 보정한 값 표(경계·평탄·비유일 표시), 진단 목록, 열별 NRMSE(전→후), 시작점 5개의 표, **관측(◆)·보정 전·보정 후 그래프**(점선: 보정/검증 경계) | `CalibrateForm.tsx`, `CalibrateTab.tsx` |
| 프리셋 | 보정 결과를 이름 붙여 저장(보정한 파라미터 값 + 출처: 데이터셋·열·J·검증 J·시간 분할 비율·시각), 최대 20개, 프로젝트 파일 `validation.presets`. **새 시나리오로 적용**(권장: 기본 설정과 다른 값만 덮어쓰고 이름·메모를 붙임, 기본 설정은 그대로), **기본 설정에 적용**(확인 뒤 입력값이 바뀜), 이름 바꾸기, 삭제 | `lib/presets.ts`, `PresetPanel.tsx` |
| 내보내기·가져오기 | JSON(`kind: "spd-presets"`, 버전 1)으로 내보내고(프리셋 id는 담지 않음) 다른 프로젝트에서 가져온다. **호환 검사**: 다른 모델의 프리셋은 건너뛰고, 모델 버전이 다르면 알리되 가져오며, 모델에 없는 파라미터·허용 범위 밖·정수가 아닌 값은 버리고, 쓸 수 있는 파라미터가 없으면 건너뛴다. 이름이 겹치면 번호(`이름 (2)`), 20개 초과는 가져오지 않는다 | `shared/presetFile.ts`, `lib/presets.ts` |

## 2. 정한 것

- 보정은 **"맞는 값"을 약속하지 않는다.** 화면·마크다운·안내문에 그렇게 적고, 진단을 결과 바로 아래에 기본으로 보인다. 경고가 없어도 "모델이 맞다는 증명은 아니다"라고 덧붙인다.
- **정수 파라미터는 탐색 중 연속 값으로 두고** 끝에서 내림·올림 조합 중 J가 가장 작은 정수로 맞춘다. 처음에는 탐색 중에도 반올림했는데 목적함수가 계단식이 되어 Nelder–Mead가 평탄 구간에서 멈췄다(초기 숙련 인원 28을 19로 회수).
- **종료 판정은 "단체 꼭짓점들의 J 차이 < 1e-6이 연속 3번"** 이다. 처음에는 "최선의 J가 개선되지 않음 3번"이었는데 반사·수축 중의 정체를 수렴으로 오판해 7~21번 평가만 하고 J 0.17~0.6에서 멈췄다. 비유일성 시험이 이를 잡아냈다.
- 비유일성의 "J가 비슷함"은 상대 5% + **절대 1e-5**이다(최적화 해상도 아래의 차이는 구별할 수 없다. 잡음 없는 데이터에서는 J가 1e-7~1e-12로 모두 사실상 0이라 상대 기준만으로는 비슷함을 보지 못했다).
- 평탄·비유일성·과적합 진단은 **개선 여부와 무관하게** 낸다. 시작 값에서 이미 J가 0이어도(신입 생산성 계수처럼 영향이 없는 파라미터) "정해지지 않는 파라미터"를 알려야 하기 때문이다. 경계 도달은 값이 움직였을 때만 알린다(시작 값이 경계인 것은 사용자가 정한 것).
- 실행은 설계 5.2의 "Worker가 12 ms마다 확인"과 달리 **주 스레드에서 12 ms마다 UI에 양보**하며 나눠 진행한다(극단 조건 시험과 같은 방식). 취소하면 그때까지 **끝난 시작점** 중 최선으로 끝난다(진행 중이던 시작점은 버린다).
- 프리셋 id·이름: id는 비어 있는 가장 작은 번호(`p1`…), 이름이 겹치면 번호를 붙인다. 프로젝트 파일을 열 때는 다른 모델의 프리셋과 쓸 수 있는 파라미터가 없는 프리셋을 버리고 경고한다(모델 버전이 다른 것은 유지하고 화면이 표시).

## 3. 점검에서 확인한 것

- **쌍둥이 회수**(Brooks, 28주 관측): 잡음 없는 데이터에서 공칭 생산성 0.13을 0.5% 안으로, 3% 잡음에서 5% 안으로, 정수 파라미터는 정확히(28) 회수한다. 통합 모델(공칭 pro_prod 0.5, hiring_delay 40)도 2개 파라미터에서 0.500·40.025로 회수(1.3초)하고 4개에서는 4.2초, 나머지 둘이 정해지지 않음을 비유일성으로 경고한다.
- **공칭 생산성 × 숙련자 계수는 곱으로만 영향을 주므로**(`nominal_productivity * … * experienced_productivity_factor`) 곱 0.156은 2% 안으로 회수하지만 개별 값은 정해지지 않는다 → **비유일성 경고가 나온다**. 신입이 없는 모델에서 신입 생산성 계수는 **평탄 경고**, 허용 범위(0.01~0.12)가 참값(0.13)을 포함하지 않으면 **경계 경고**, 인력 투입이 보정 구간 뒤에 일어나는 데이터는 **과적합 경고**(보정 구간 J ≈ 0, 검증 구간 J가 2배 넘게 큼)를 낸다.
- Electron E2E에서 앱 자체로 만든 합성 데이터(참값 0.13)를 보정해 0.13±1%를 회수하고 그래프에서 보정 후 곡선이 관측 점에 겹친다.
