# 구현: 저장소와 데스크톱 앱 (MVP)

- 구현한 설계: [01.기술스택.md](../02.설계/01.기술스택.md), [02.아키텍처설계.md](../02.설계/02.아키텍처설계.md) 3.4~9장 (MVP 범위: 사용 시나리오 SC-01~03)
- 상태: 완료. 이후 시나리오 비교·채택·통제 화면이 같은 골격 위에 추가됨 → [04](04.시나리오-비교.md), [05](05.Earned-Value-제어.md)
- 위치: 저장소 루트, `apps/desktop`

## 1. 저장소

- **npm workspaces**: `packages/*`(sd-engine, models, analysis), `apps/*`(desktop). 루트 스크립트 `npm run check`(전 패키지 타입 검사 + 시험), `npm run build`, `npm run dev`. Node 22 이상, TypeScript 공통 설정은 `tsconfig.base.json`.
- 패키지 의존 방향: `sd-engine` ← `models`, `analysis`(←sd-engine, 시험에서 models) ← `desktop`. 엔진과 분석 패키지는 Electron·DOM에 의존하지 않아 Node에서 시험한다.
- 데스크톱: electron-vite(main, preload, renderer 3개 빌드), React 19, Zustand, ECharts, zod, vitest. `@spd/analysis`와 `@spd/models`는 desktop의 devDependency이고 vite가 renderer 번들에 포함한다.

## 2. 프로세스 구조와 보안

| 프로세스 | 역할 | 위치 |
|---|---|---|
| main | 창, 앱 메뉴, 파일 I/O, 저장 확인 대화상자 | `src/main` |
| preload | `window.spd`만 노출(`contextBridge`). 경로·Node API는 노출하지 않는다. | `src/preload/index.ts`, 계약은 `src/shared/ipc.ts` |
| renderer | React UI, 상태, 시뮬레이션 요청 | `src/renderer/src` |
| Web Worker | 시뮬레이션 실행(UI 스레드를 막지 않음) | `src/renderer/src/engine/sim.worker.ts` |

- 창 설정: `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`. 외부 링크는 앱 안에서 열지 않고 기본 브라우저로 보낸다(`https://`만).
- **경로를 renderer에 주지 않는다.** 파일 경로는 main이 열기/저장 대화상자로만 받아 기억하고(`ProjectService.currentPath`) renderer에는 파일 이름만 돌려준다. IPC 채널은 `project:open/save/saveAs/reset/confirmDiscard/setDirty`, `file:exportCsv/importCsv`, `menu:command`뿐이다.
- 저장하지 않은 변경이 있을 때 창을 닫으면 main이 "저장 / 저장 안 함 / 취소"를 묻는다. "저장"은 renderer에 저장 명령을 보내고 저장이 성공하면 닫는다. renderer는 변경 여부를 `setDirty`로 알린다.
- 메뉴(`menu.ts`): 새 프로젝트(Ctrl/Cmd+N), 열기(O), 저장(S), 다른 이름으로 저장(Shift+S), 편집·보기·창 기본 항목. 프로젝트 명령은 renderer로 보내 처리한다(상태가 renderer에 있으므로). 개발 중에만 새로고침·개발자 도구.

## 3. 시뮬레이션 실행 (Worker)

- `protocol.ts`: `WorkerIn`(`run {id, modelId, overrides, options{end, dt, seed}}`, `cancel {id}`), `WorkerOut`(`progress`, `done`, `error`).
- `execute.ts`의 `executeRun`이 본체다. `Simulation.advance`를 진행 콜백 간격으로 반복하다가 **12ms가 지나면 이벤트 루프에 양보**해 취소 메시지를 처리하고, 끝나면 결과를 `Transferable`(Float64Array 버퍼)로 넘긴다. 취소하면 그때까지의 결과를 `completed=false`로 돌려준다. 오류(`ModelError`, `SimulationError`)는 메시지로 변환한다. Worker와 무관하게 의존성을 주입받아(`post`, `isCancelled`, `yieldToEventLoop`, `now`) 시험한다.
- `engineClient.ts`: `startRun(req, onProgress) → {promise, cancel}`. Worker 하나를 지연 생성하고 요청 id로 응답을 짝짓는다. Worker 오류는 대기 중인 모든 요청을 reject하고 Worker를 버려 다음 요청이 새로 만든다.
- `models.ts`: 모델 ID → 컴파일된 모델 캐시(`getCompiledModel`). 같은 모델을 다시 컴파일하지 않는다.

## 4. 모델 카탈로그 (`catalog/`)

`ModelEntry`가 모델 하나의 화면용 메타데이터를 묶는다: 설명, 파라미터 그룹(이름·허용 범위·단계·정수 여부), 차트 변수 목록, 프리셋, 실행 요약 지표(`kpis`), 시나리오 비교용 `kpiSpecs`·`radarAxes`, Earned Value 어댑터 `evm`. 새 모델은 JSON과 카탈로그 항목 하나로 붙는다.

- Brooks: 파라미터 11개(프로젝트 1, 인력과 추가 투입 4, 생산성과 오버헤드 6), 프리셋 "추가 없음/5명 추가/10명 추가".
- 통합 모델: 그룹 "프로젝트와 계획", "인력", "생산성과 소진" 등.
- 공통 검사(시험): 폼의 모든 이름이 모델 상수에 있고, **모델의 모든 상수가 폼에 있어** 화면에서 모두 조절할 수 있다. 기본값과 허용 범위 안의 값으로 실행해도 오류가 없다.
- `lib/params.ts`: `defaultParams`, `parseParam`(빈 값·숫자 아님·정수 아님·범위 밖에 한국어 오류 메시지), `describeRun`(기본값과 다른 값만 나열한 실행 이름, 모두 같으면 "기준"), `snapshotOf`(변경 여부 비교용 정규화 직렬화).
- `lib/runSettings.ts`: 종료 시각(1~5000일), dt(0.01~5), 시드(정수), 조합 검사(최대 100,000스텝).

## 5. 실험 화면 (SC-01~03)

| 요소 | 구현 |
|---|---|
| 파라미터 폼 | `ParamForm`/`NumberField`: 그룹별 입력, 입력 중에도 오류를 필드 옆에 표시하고 오류가 있으면 "실행"을 막는다(`paramErrors`), 기본값으로 되돌리기, 바깥에서 값이 바뀌면(열기·복원) 입력창을 맞추되 입력 중인 글자는 건드리지 않는다. |
| 실행 컨트롤 | `RunControls`: 실행/중단, 진행 막대(`role=progressbar`), 오류 메시지, 프리셋 한 번에 실행, 실행 설정(종료·dt·시드). 시나리오 일괄 실행 중에는 막는다. |
| 결과 그래프 | `TimeSeriesChart`(ECharts): 변수 선택, 여러 실행 겹쳐 보기(실행마다 색, 실행 중에는 점선으로 라이브 곡선), 완료 시각 세로선, 확대·구간 선택(dataZoom), 이미지 저장, 다크 모드 팔레트(`chartTheme.ts`의 `useDarkMode`). |
| 실행 표 | `RunTable`: 실행 이름(`describeRun`), 완료일(없으면 "미완료"), 최대 인원, 표시 토글, 삭제·모두 지우기, 실행별 CSV. |
| 앱 시작 | 처음 한 번 기본 설정으로 자동 실행(`runBaselineOnce`). 새 프로젝트·열기 뒤에도 한 번 자동 실행한다. |
| 모델 전환 | 상단 선택. 저장하지 않은 변경이 있으면 먼저 묻고 새 프로젝트로 시작한다(`switchModel`). |

## 6. 프로젝트 파일 저장·열기 (`*.spd.json`)

- **스키마**(`src/shared/projectFile.ts`, zod): `schemaVersion`, `meta{name, createdAt, updatedAt}`, `model{id, version}`, `params`(모델 상수 덮어쓰기), `run{end, dt, seed}`, `ui{chartVariable}`. 사람이 읽을 수 있는 들여쓴 JSON. v1이 MVP이고 이후 v2(시나리오·채택·실적·경고 설정)로 상승했다([04](04.시나리오-비교.md) §6, [05](05.Earned-Value-제어.md) §3).
- **`ProjectService`**(`src/main/projectService.ts`, Electron 비의존): 열기(파일 크기 상한 5MB, JSON 파싱과 스키마 검사, 더 새로운 버전·깨진 파일은 한국어 오류), 저장(스키마 재검사, **프로젝트 이름은 파일 이름을 따름**, 확장자를 `.spd.json`으로 맞춤), 현재 경로 기억과 `reset`. 대화상자와 파일 시스템은 주입한다.
- **원자적 쓰기**(`atomicWrite.ts`): 임시 파일에 쓴 뒤 이름을 바꾸고, 실패하면 임시 파일을 지우고 오류를 던져 기존 파일이 깨지지 않는다.
- **renderer 쪽**: `buildProjectFile`(스토어 → 파일)와 `applyProjectFile`(파일 → 스토어; 허용 범위 밖·알 수 없는 파라미터는 기본값으로 돌리고 경고 목록을 돌려줌, 모델 버전이 다르면 경고). `selectIsDirty`가 `snapshotOf`로 저장 시점과 현재를 비교하고, `ProjectBar`가 창 제목에 "● "를 붙이고 main에 알린다. 저장·열기·새 프로젝트는 저장하지 않은 변경이 있으면 묻는다(`projectActions.ts`의 `confirmDiscardIfDirty`).
- **알림**(`Notice`): 정보는 5초 뒤 사라지고 경고·오류는 직접 닫을 때까지 남는다. 경고에는 세부 목록이 붙는다.

## 7. CSV 내보내기·가져오기

| 기능 | 구현 |
|---|---|
| 형식 (`shared/csv.ts`) | RFC 4180, 줄 끝 CRLF, UTF-8 BOM(Excel 한글), 숫자는 `.` 소수점·전체 자릿수, 유한하지 않은 값은 빈 칸. 읽기는 쉼표·세미콜론·탭을 첫 줄에서 자동 판별(따옴표 안은 세지 않고 모호하면 쉼표)하고, BOM 제거, 따옴표 안의 쉼표·이스케이프·줄바꿈, 빈 줄 건너뛰기를 처리하며 닫히지 않은 따옴표는 행 번호와 함께 오류로 알린다. |
| 내보내기 | 한 실행의 모든 변수(`runToCsv`)와, 표시 중인 실행들의 그래프 변수를 한 표로(`comparisonToCsv`, dt가 다른 실행은 시각의 합집합에 빈 칸). main의 `TextFileService`가 저장 대화상자(제안 이름의 금지 문자 치환, `.csv` 보정), 원자적 쓰기, 100MB 상한. |
| 기준 행동 가져오기 | `lib/referenceCsv.ts`: 첫 열 시간, 나머지 열 각각 하나의 시계열(최대 50열·100,000행), 빈 칸은 건너뜀, 숫자가 아닌 값은 행·열 위치와 함께 거부, 열 이름을 변수(이름·라벨·"라벨 (단위)")에 대소문자·공백 무시로 연결(`matchVariable`). 그래프에 점선·점으로 겹쳐 그리고 `ReferencePanel`에서 표시·연결 변수·삭제를 관리. main의 가져오기는 20MB 상한. |

## 8. 상태 관리 (`stores/appStore.ts`)

Zustand 스토어 하나가 모델, 파라미터, 실행 설정, 실행 기록(`runs`), 기준 행동(`references`), 진행 상태(`status`, `progress`, `live`), 프로젝트 메타(`projectName`, `projectFile`, `savedSnapshot`), 알림을 갖는다. 같은 스토어가 이후 단계의 `scenarios`, `adopted`, `actuals`, `evm`도 갖는다. 실행은 Worker를 한 번에 하나만 쓰도록 `status`로 배제하고, 실행이 끝나면 `RunRecord`(색, 이름, 결과, KPI)를 목록에 더한다.

## 9. 시험

| 대상 | 내용 |
|---|---|
| main | `ProjectService`(저장·열기·원자적 쓰기 실패·확장자·큰 파일·손상·이름 규칙), `TextFileService`(파일 이름 보정, 상한, 가져오기 오류) — 대화상자·파일 시스템을 가짜로 주입 |
| shared | 프로젝트 스키마(필수 항목·범위·버전), CSV 형식·파싱(따옴표·줄바꿈·구분자·오류 행) |
| renderer | `executeRun`(진행, 취소, 오류), 카탈로그 공통 검사와 KPI, `params`(검증·이름·스냅샷), `projectApply`(복원·경고·변경 감지), 기준 행동 CSV, 내보내기 CSV(전체 자릿수·합집합), 스토어 |
| Electron E2E | 앱을 `--remote-debugging-port`로 띄워 renderer를 CDP로 조작하고 main의 대화상자를 가짜로 바꿔 검증: 저장·열기·같은 파일에 재저장·수정 후 새 프로젝트 확인, 창 닫기, CSV 내보내기·가져오기·다시 가져오기, 모델 전환. 스크립트는 `docs`가 아닌 임시 작업 폴더에 둔다. |

## 10. 설계와 달라진 점

- 설계 9장의 구현 순서 일부(창 닫기 확인, 기준 행동 CSV 연결 UI)를 MVP 안에서 함께 구현했다.
- 프로젝트 이름을 파일 이름에 묶었다(파일을 옮기거나 이름을 바꿔도 안과 밖이 어긋나지 않도록).
- Worker 실행은 renderer의 Web Worker이고, 설계의 "main 프로세스에서 실행" 대안은 택하지 않았다(설계 2.4와 같음).
