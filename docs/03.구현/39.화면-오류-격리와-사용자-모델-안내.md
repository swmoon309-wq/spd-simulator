# 화면 오류 격리·화면 스모크 시험·사용자 모델 안내

기준일 2026-10-29. 보고서 탭을 누르면 화면 전체가 사라지는 결함을 고치고, 같은 종류의 결함이 앱 전체를 비우지 않도록 막았다. 38번에서 남긴 "사용자 모델 상시 안내"도 구현했다.

## 1. 보고서 탭 결함

- **증상**: 보고서 탭을 누르면 화면이 비었다. 콘솔에 `getSnapshot should be cached`, `Maximum update depth exceeded`.
- **원인**: `ReportTab`의 `useAppStore((s) => s.actuals.map(...))`가 렌더마다 새 배열을 돌려줘 zustand가 매번 "바뀌었다"고 보고 무한히 다시 그렸다.
- **수정**: `actuals`만 구독하고 `useMemo`로 날짜 목록을 만든다([ReportTab.tsx](../../apps/desktop/src/renderer/src/components/report/ReportTab.tsx)).
- **교훈**: 셀렉터는 저장소의 값을 그대로 돌려주고, 파생 값은 `useMemo`로 만든다. 기존 시험은 화면을 그리지 않아 이 결함을 잡지 못했다.

## 2. 오류 경계 (`TabErrorBoundary`)

- 탭 내용을 `TabErrorBoundary`로 감쌌다(`key={tab}`이라 탭을 바꾸면 오류 상태가 사라진다).
- 그리는 중 오류가 나면 **그 탭만** "○○ 화면을 표시하지 못했습니다"와 오류 메시지, "다시 시도" 버튼으로 바뀐다. 다른 탭과 프로젝트 데이터는 그대로다.
- 오류는 콘솔에도 남긴다(`[탭 이름] 화면 오류`).
- 탭 목록(`TABS`)을 상수로 뽑아 탭 단추와 탭 이름 표가 같은 목록을 쓰게 했다.

## 3. 화면 스모크 시험 (`App.smoke.test.tsx`)

- **jsdom**을 desktop의 개발 의존성에 추가했다(이 파일만 `@vitest-environment jsdom`).
- 8개 탭을 하나씩 열어 ① 오류 경계가 뜨지 않고 ② 탭 패널이 있고 ③ `console.error`가 없는지 확인한다.
- jsdom에 없는 것은 시험에서만 채운다: `ResizeObserver`, `matchMedia`, canvas(echarts를 가짜로 바꿈). 엔진은 Worker 대신 직접 실행한다.
- **효과 확인**: 수정 전 코드로 되돌리면 보고서 탭 시험이 실패하고, 수정하면 통과한다.

## 4. 사용자 모델 상시 안내 (설계 08의 8.3)

- `UserModelNotice`: 현재 모델이 **내 모델(사용자 모델)**이면 시나리오·통제·위험 분석·검증 화면 머리에 경고 줄을 보인다. 문구는 보고서의 "읽을 때" 절과 같은 `modelCaveat`을 쓴다(보정·검증되지 않았을 수 있음, 단위 경고가 있으면 함께).
- 내장 모델이면 나타나지 않고, 홈·실험·보고서·모델 탭에도 없다(보고서에는 자체 안내가 있다).
- 시험 2개: 사용자 모델(Brooks 사본)을 올려 네 화면에서 보임·홈에서 안 보임, 내장 모델에서는 어느 화면에도 안 보임.

## 6. 남은 것

- 스모크 시험은 **각 탭의 첫 화면**만 그린다. 탭 안의 하위 화면·대화상자·실제 클릭 흐름은 Electron E2E로 확인해야 한다.
- 안내 줄은 **구조 점검 시각·데이터 비교 여부** 같은 검증 상태를 아직 보여 주지 않는다(설계 8.3의 "검증 상태 줄"). 모델 선택·홈 카드·결과 표 머리글의 "사용자 모델" 표시도 아직 없다.
- 같은 id에 해시가 다른 모델이 있을 때 어느 쪽을 쓸지 묻는 대화상자(설계 4.1)는 여전히 없다.
