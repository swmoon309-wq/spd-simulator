# 계획 곡선 CSV를 PV로 (CTL-11)

기준일 2026-10-29. 현장 계획서의 일정 곡선을 가져와 PV로 쓴다. 2차에서는 PV가 "채택한 시나리오의 시뮬레이션 곡선"뿐이었다(기능 목록 7장). 기준선 스냅샷 구조(`adopted`)는 바꾸지 않고, 곡선에서 같은 스냅샷을 만든다.

## 1. CSV 형식 (`lib/planCurveCsv.ts`)

| 열 | 필수 | 뜻 |
|---|---|---|
| 첫 열 | 예 | 일(day) |
| `effort` · `누적 공수` · `PV` · `계획 공수` | 예 | **누적** 계획 공수(맨데이). 마지막 값이 총 예산(BAC) |
| `progress` · `진척률` | 아니오 | 누적 진척률. 비율(0~1), 열 이름 끝이 `%`이면 백분율(`진척률(%)`) |

- 진척률 열이 없으면 **진척률 = 누적 공수 ÷ 총 예산**(비용 정렬, 설계 05의 2.2)으로 둔다. 파일에 있으면 그 값을 쓴다.
- 일은 엄격히 증가하고, 누적 공수·진척률은 줄어들 수 없다. 위반하면 행 번호를 알려 거부한다(숫자가 아님, 빈 칸, 100% 초과, 음수, 열이 둘 이상, 총 예산 0, 4,999일 초과).
- 첫 일이 0보다 크면 0일(공수 0)을 앞에 붙이고 알린다. 누적 공수가 총 예산에 먼저 닿으면 그 시각이 **계획 완료일**이고 이후는 평평하다(알림).
- 1일 간격으로 선형 보간해 다시 표본화한다(시뮬레이션 기준선과 같은 모양). 세미콜론 구분·소수 쉼표, 모르는 열 무시(알림), 빈 줄 건너뛰기는 실적 CSV와 같다.

## 2. 채택 계획 (`lib/adoption.ts`)

- `createAdoptionFromPlan`: 곡선에서 `series`·`bac`·`plannedCompletion`을 가져오고, **진척 인정 규칙·총 태스크·모델·파라미터·실행 설정은 지금 프로젝트의 것**을 쓴다. 파일 모양은 그대로다(스키마 변경은 `scenarioId`에 `@plan-csv`를 허용한 것뿐이라 이전 파일과 호환된다).
- `scenarioId = '@plan-csv'`, 이름은 `계획 곡선: <파일 이름>`.
- 어느 입력에서 나온 것이 아니므로 **입력이 바뀌어도 "채택 이후 수정됨"으로 보지 않고** 모델 버전 차이만 본다.
- 스토어 `adoptPlanCurve`: 채택하면 이전 개정 이력·조치 시험·재예측을 지운다(시나리오 채택과 같다).

## 3. 화면 (통제 탭)

- 실적 표 위의 **"계획 곡선 CSV를 PV로…"** 단추(데스크톱 전용). 이미 채택 계획이 있으면 바꿀지, 개정 이력이 몇 건 지워지는지 확인한다.
- 가져온 뒤 알림에 총 예산·계획 완료일, 진척률의 출처, 무시한 열, 경고가 나온다. 이후 PV 곡선·EV·SPI·완료 예측은 시나리오 채택과 같은 코드가 곡선으로 계산한다.
- 시나리오 탭의 채택 요약줄은 이 경우 "보기" 링크를 숨긴다(가리킬 시나리오가 없다).

## 4. 쓸 수 없는 것 (의도)

계획 곡선을 PV로 쓰는 동안 **재예측과 시정 조치 시험(기준선 개정)은 쓸 수 없고** 이유를 화면에 적는다. 두 기능은 채택 계획의 모델·파라미터로 시뮬레이션을 다시 실행해 출발하는데, 계획서의 곡선은 그 모델에서 나온 것이 아니라 두 곡선이 섞이기 때문이다. 시나리오를 채택하면 다시 쓸 수 있다. EVM 지표·경고·완료 예측(획득 일정)은 그대로 쓴다.

## 5. 시험

전체: analysis 566, models 239, engine 286, **desktop 1,542**(+13) 통과. 타입 검사 통과.

- `planCurveCsv.test.ts` 13: 진척률 없음/비율/백분율, 0일 보충, 예산에 먼저 닿는 곡선, 세미콜론·모르는 열, 14가지 거부 경우, 오류 형식, **프로젝트 파일 스키마 통과**(이 시험이 `@plan-csv`를 스키마가 거부하는 것을 잡았다), 보고일의 PV·EV·SPI가 곡선에서 나옴, 모델 버전만 비교, 진척 정의 없는 모델 거부, 스토어 채택이 개정 이력을 지움.
- 화면 스모크 시험의 통제 탭이 새 단추를 포함해 오류 없이 그려진다.

## 6. 확인하지 못한 것

- 실제 Electron에서 CSV를 골라 가져오는 흐름(시스템 파일 대화상자)은 확인하지 못했다. 가져온 뒤의 계산은 단위 시험으로 확인했다.
- 계획 곡선의 진척률과 모델의 진척 인정 규칙(개발·QA·시험 비율)은 서로 독립이다. 계획서의 진척률 정의가 다르면 EV의 뜻이 달라질 수 있어, 진척률 열이 없는 비용 정렬 쪽을 기본으로 권한다.
