- 구현한 설계: [01.기술스택.md](../02.설계/01.기술스택.md) 2.1~2.3, [02.아키텍처설계.md](../02.설계/02.아키텍처설계.md) 3.1

- 위치: `packages/sd-engine/src` (순수 TypeScript, Electron·DOM에 의존하지 않음). 의존 라이브러리는 `zod`(모델 정의 검증)뿐이다.

## 1. 구성

| 폴더·파일 | 역할 |
|---|---|
| `expr/tokenizer.ts`, `parser.ts`, `ast.ts` | 수식 문자열 → 토큰 → AST. 위치 정보가 든 `ExprError`로 문법 오류를 알린다. |
| `expr/compiler.ts` | AST → 평가 함수(클로저). 이름 해석, 인자 개수 검사, 지연·평활 함수의 상태 등록, 의존 변수 수집. |
| `expr/functions.ts` | 순수 내장 함수와 `GRAPH` 보간(`interpolate`). |
| `expr/runtime.ts` | `Runtime`(값 배열, 상태 배열, 시각, dt, 난수, 초기화 플래그)과 `StateStore`(지연·평활 상태 저장소). |
| `model/schema.ts` | `ModelDef`의 zod 스키마(`parseModelDef`). |
| `model/compile.ts`, `graph.ts`, `errors.ts` | 모델 컴파일, 위상 정렬·순환 감지, `ModelError`/`SimulationError`. |
| `solver/integrator.ts` | `Integrator` 인터페이스와 `EulerIntegrator`. |
| `runner/simulation.ts` | `Simulation`(초기화, 스텝 진행, 기록, 진행 콜백, 중단)과 `runModel`. |
| `rng.ts`, `result.ts` | 시드 가능한 난수(mulberry32), `RunOptions`·`RunResult` 타입. |

## 2. 수식 언어

토크나이저는 숫자(`1`, `.5`, `2e-3`), 식별자, 연산자(`+ - * / ^`, 괄호·대괄호·쉼표, 비교 `< > <= >= = <> ==` `!=`)와 키워드 `AND`/`OR`/`NOT`을 인식한다. `==`는 `=`, `!=`는 `<>`로 정규화한다.

| 항목 | 구현 |
|---|---|
| 우선순위 | `OR` < `AND` < `NOT` < 비교 < `+ -` < `* /` < 단항 `-` < `^`. 거듭제곱은 우결합이고 **단항 마이너스는 거듭제곱보다 약하다(`-2^2 = -4`)**. 비교는 연속해서 쓸 수 없다(`a < b < c`는 오류, `AND`로 나누게 함). |
| 대소문자 | 변수 이름은 구분하고 함수 이름은 구분하지 않는다. `TIME`, `DT`는 예약어(현재 시각, 적분 간격). |
| 순수 함수 | `IF MIN MAX ABS SQRT EXP LN ROUND CLAMP`, 시간 함수 `STEP PULSE RAMP`, 난수 `RANDOM_UNIFORM RANDOM_NORMAL RANDOM_TRIANGULAR`(모델의 시드 난수를 씀). |
| 상태 함수 | `SMOOTH(x, d)`와 `DELAY1(x, d)`(1차 지수 지연), `DELAY3(x, d)`(평균 지연 d의 3차 지연 = 단당 d/3인 1차 3단). 상태 크기는 컴파일 때 `StateStore`에 확정된다. |
| `GRAPH` | `GRAPH(입력, [x…], [y…])` 인라인(좌표는 상수 수식만) 또는 `GRAPH(입력, 테이블이름)`. 선형 보간, 범위 밖은 끝값, 입력이 NaN이면 NaN. 테이블은 x 오름차순이어야 한다(스키마가 검사). |
| 시간 함수 경계 | `STEP`/`PULSE`는 `1e-9` 허용 오차로 경계를 비교한다(부동소수 시각 누적 방지). `PULSE`는 `[시작, 시작+폭)`. |
| 의존성 | 각 수식이 `algebraicDeps`(현재 스텝 값에 직접 의존)와 `delayedDeps`(지연·평활의 입력, 다음 스텝에 영향)를 돌려준다. 후자는 순환을 끊는다. |

## 3. 모델 컴파일

`compileModel(def)`는 이름을 슬롯(숫자 인덱스)으로 바꿔 `Float64Array`에 값을 두는 방식이다. 슬롯 순서는 상수 → Level → Rate → Auxiliary(정의 순서). 검사와 규칙:

- 이름은 `[A-Za-z_][A-Za-z0-9_]*`, 예약어(`TIME DT AND OR NOT`) 금지, **상수·Level·Rate·Auxiliary 사이의 중복 이름 금지**.
- Level의 `inflows`/`outflows`는 Rate 또는 Auxiliary 이름이어야 하고, Level 초기값 수식에는 `SMOOTH`/`DELAY`를 쓸 수 없다.
- Rate와 Auxiliary는 현재 값 의존성(`algebraicDeps`)으로 **위상 정렬**한다(Kahn, 같은 순위에서는 정의 순서를 유지해 결과가 결정적). 순환이 있으면 경로(`a → b → a`)를 담은 `CycleError`/`ModelError('cycle')`. 초기값 평가에도 같은 검사(`init-cycle`).
- 모든 오류는 변수 이름을 담은 `ModelError`(종류: name, expression, flow, cycle, init-cycle, output, option)로 화면에 보일 수 있다.
- 결과는 상수 덮어쓰기만 다른 여러 실행에 재사용할 수 있다.

## 4. 실행 (`Simulation`)

- **적분**: Euler 고정 간격. `Level(t+dt) = Level(t) + (Σ유입 − Σ유출) × dt`. 도함수는 이미 평가된 유입·유출 슬롯을 읽는다(RK4 등을 붙일 때는 모델 재평가로 바꿔야 함을 주석에 남김). 기본 `dt = 0.25`일.
- **한 스텝의 순서**: (1) 지연·평활 상태 갱신, (2) Level 적분, (3) 시각 전진(`start + step × dt`로 계산해 누적 오차 방지), (4) 모든 Rate·Auxiliary 재평가(위상 순서), (5) 유한성 검사와 기록.
- **초기화**: 상수(덮어쓰기 적용) → Level 초기값(`initPlan`) → 지연·평활 체인이 입력을 전파하도록 (함수 개수 + 1)번 전체 평가 → 지연·평활 상태를 입력값으로 정상 상태 초기화 → 재평가 → 시각 0 기록. 초기화 중에는 지연·평활 함수가 입력을 그대로 돌려준다(`initializing` 플래그).
- **수치 오류**: 스텝마다 상수가 아닌 모든 변수가 유한한지 검사해 NaN·무한대가 생기면 `SimulationError`(변수, 시각, 값)로 멈춘다(0으로 나누기 등).
- **옵션** (`RunOptions`): `overrides`(정의된 상수만, 유한한 값만), `seed`, `dt`, `end`, `recordEvery`(마지막 스텝은 항상 기록), `record`(기록할 변수), `progressEvery`(기본 전체의 약 1%).
- **진행·중단**: `advance(maxSteps)`로 조금씩 진행해 Worker가 청크 사이에 메시지를 처리할 수 있고, `run({onProgress, shouldStop})`은 진행 콜백 간격마다 중단 여부를 본다. 중단하면 그때까지의 결과가 `meta.completed = false`로 나온다. 모델의 `outputs`가 진행 콜백의 값에 실린다.
- **재현성**: 같은 모델·입력·시드는 비트 단위로 같은 결과다. 난수는 mulberry32(시드마다 같은 수열), 정규분포는 Box–Muller, 삼각분포는 역변환법.
- **결과**: `RunResult {time, series: Record<이름, Float64Array>, meta{model, version, dt, seed, completed}}`. Web Worker로 넘길 때 버퍼를 전송(transfer)할 수 있는 형태다.

## 5. 시험 (엔진 단독)

| 영역 | 확인한 것 |
|---|---|
| 토크나이저·파서 | 토큰 종류, 우선순위·결합(`-2^2`, 우결합 거듭제곱), 구문 오류의 위치와 메시지 |
| 컴파일러 | 변수·예약어, 비교·논리, 순수 함수, `STEP/PULSE/RAMP`, `GRAPH`(보간·범위 밖·NaN), 컴파일 오류, 난수의 시드 재현·분포 통계, 의존성 수집, **지연·평활을 해석해와 비교**(1차·3차 지연의 응답) |
| 의존 그래프 | 위상 정렬(정의 순서 유지), 순환 경로 보고 |
| 적분 | Euler 폐형식 `x₀(1+r·dt)ⁿ`과 일치, 목표 추구의 해석해 근사, 유입·유출 체인의 총량 보존 |
| 러너 | 평가 순서, 순환 참조, 초기화(Level 초기값 의존·지연 체인), 덮어쓰기와 옵션 검증, 재현성, 단계 실행, 진행 콜백과 중단, 수치 오류 감지, 모델 검증 |

전체 엔진 시험은 현재 181개(스냅샷·이어 실행 시험 포함)다.

## 6. 설계와 달라진 점

- 설계(02 3.1)가 후속으로 둔 `RK4Integrator`는 구현하지 않았고 `Integrator` 인터페이스만 있다. Euler의 dt 민감도는 모델 시험(통합 모델 dt 0.25 vs 0.125)으로 확인한다.
- `GRAPH`의 인라인 좌표는 상수 수식(`[0, 1 + 1]`, 음수)을 컴파일 때 접어 허용하고, 변수가 든 좌표(`[0, x]`)는 오류로 거부한다.
- 변수 이름의 대소문자는 구분하지만 함수 이름은 구분하지 않는다(설계에 명시되지 않아 구현에서 정한 규칙).
