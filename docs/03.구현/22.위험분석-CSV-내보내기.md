# 위험 분석: 결과 CSV 내보내기 (설계 06의 7장)

설계: [06.위험분석설계.md](../02.설계/06.위험분석설계.md) 7장("내보내기: 반복별 입력과 지표를 CSV, 요약 통계 CSV"). 3차에 남아 있던 마지막 항목이다. 앞 단계: [13](13.위험분석-목표-민감도-수렴-비교.md), [14](14.위험분석-파일-저장과-E2E.md).

## 1. 구현한 것

위험 분석 탭의 실행 줄에 **반복별 CSV…** 와 **요약 통계 CSV…** 버튼을 두었다. 기존 CSV 내보내기(`files.exportCsv`)와 같은 규약(UTF-8 BOM, CRLF, 숫자는 전체 자릿수)을 쓴다. 결과가 없거나 실행 중이거나 데스크톱 앱이 아니면 버튼이 잠긴다.

| 파일 | 내용 | 코드 |
|---|---|---|
| 반복별 | 한 줄이 반복 하나: `반복`, `상태`(성공/실패), 입력 표본(라벨과 단위), 지표(라벨과 단위). 실패한 반복은 지표가 모두 빈 칸이고 입력 표본은 남는다. 지표를 계산할 수 없는 반복(예: 종료 시각 안에 끝나지 않음)은 그 지표만 빈 칸이다. 취소한 결과는 **끝난 반복만** 나온다 | `lib/riskCsv.ts`(`riskIterationsCsv`) |
| 요약 통계 | 지표마다 한 줄: 성공한 반복 수, 지표가 있는 반복 수, **지표 없는 비율**, 평균과 95% 신뢰구간, 표준편차, 최소, P10·P25·P50·P75·P80·P90·P95, 최대. 평균을 알 수 없으면 빈 칸 | `lib/riskCsv.ts`(`riskSummaryCsv`) |
| 파일 이름 | `모델-위험분석-반복별|요약-시드N-M회.csv` | `riskCsvFileName` |
| 동작 | `exportRiskCsv('iterations'|'summary')`: 결과가 없으면 알림, 저장하면 "CSV를 저장했습니다" | `lib/fileActions.ts`, `RiskRunBar.tsx` |

## 2. 정한 것

- **입력이 바뀌어 오래된 결과도 내보낼 수 있다.** 파일 이름에 시드와 반복 수가 들어가고 내용은 그 결과 그대로이므로, 오래된 결과를 내보내는 것이 오해를 부르지 않는다고 보았다(화면은 "오래되었습니다"를 계속 보인다).
- 반복별 CSV는 **재현된다**: 같은 입력·시드로 다시 실행해 내보내면 바이트 단위로 같다(E2E로 확인).
- 시계열 띠, 목표·민감도·수렴 결과는 이번 범위가 아니다(설계 06의 7장은 반복별 입력·지표와 요약 통계만 정했다).

## 3. 시험

- `lib/riskCsv.test.ts` 9(desktop 779 → 788): 머리글(입력·지표의 라벨과 단위)·BOM·반복마다 한 줄·모든 줄의 열 수, **값이 전체 자릿수로 쓰여 다시 읽어도 결과와 같음**, 정수 입력은 정수, 종료 시각 안에 끝나지 않는 반복의 빈 칸, 실패한 반복(상태 "실패", 지표 빈 칸, 입력 유지), 취소한 결과는 끝난 반복만, 요약 통계의 머리글·지표 3줄·값이 분석 계층의 요약과 같음(평균·신뢰구간·P50·P80·최대), 지표 없는 비율과 빈 평균, 파일 이름.
- **Electron E2E 15개**(임시 작업 폴더의 스크립트): 실행 전 두 버튼 잠김 → 60회 실행 → 열림 → 반복별 CSV 저장(BOM, 머리글, 61줄·열 수 7, 첫 행 형식, 입력 표본이 분포의 허용 범위 안) → 요약 CSV(머리글, 지표 3줄, 완료일 행이 `60,60,0`) → **요약의 평균 = 반복별 CSV에서 다시 계산한 평균** → 알림 → 같은 시드로 다시 실행해 내보낸 CSV가 바이트 단위로 같음 → 3,000회를 1.5초 뒤 중단하면 끝난 반복만 내보냄 → 실행 중에는 버튼이 잠김. 콘솔 오류 없음.
- 전체: analysis 564, models 189, engine 192, desktop 788 통과. 타입 검사와 빌드 통과. 이전 E2E는 이 변경이 위험 분석 실행 줄에 버튼만 더한 것이라 다시 돌리지 않았다(위험 분석 저장·열기·비교 스크립트의 대상 요소는 바뀌지 않았다).

점검 중 메모: E2E 스크립트가 처음에 "추가 투입 시점의 표본이 정수"라고 가정했으나 카탈로그에서 이 파라미터는 정수가 아니다(일 단위 실수). 앱은 맞게 동작했고 스크립트의 가정이 틀렸다. 단위 시험의 정수 입력은 테스트가 직접 정수로 지정한 것이다.
