설계: [09.보고서설계.md](../02.설계/09.보고서설계.md) 10장 **R3(위험 분석·상태 보고서)**. 기능 목록 RPT-03·RPT-04. 앞 단계: [30](30.보고서-PDF.md).

## 1. 구현

보고서 종류가 둘 늘었다(위험 분석, 상태 보고서). 보고서 메뉴에도 같은 항목이 생겼다.

| 종류 | 절(SectionId) | 코드 |
|---|---|---|
| 위험 분석 | 개요, `riskInputs`(불확실한 입력·분포), `riskResults`(P10/P50/P90·히스토그램·신뢰구간), `riskTargets`(목표 달성 확률·동시 달성 확률), `riskSensitivity`(토네이도·순위), `riskConvergence`, `riskCompare`(시나리오 간 비교 확률·CDF), 읽을 때, 만든 조건 | `lib/report/riskSections.ts` |
| 상태 보고서 | 개요, `statusIndicators`(보고일 지표), `statusCharts`(EVM 차트), `statusAlerts`(경고), `statusForecast`(재예측), `statusActions`(시정 조치 시험·개정 이력), 읽을 때, 만든 조건 | `lib/report/statusSections.ts` |

- **가정 안내**: 위험 분석 결과 절에는 "입력 분포를 가정한 결과이며 예측이 아니다"라는 콜아웃이 항상 붙는다.
- **최신성**: 절마다 fresh/stale/missing/na. 오래된 결과는 숫자를 싣지 않는다(`includeStale`를 켜면 "오래된 결과" 표시와 함께 싣는다). 재예측·조치 시험은 그 결과를 만든 입력·실적의 키와 현재 키를 비교해 판단한다. 비교 대상이 2개 미만이면 `riskCompare`는 "해당 없음"이다.
- **차트 공유**: 화면 컴포넌트(위험 차트, EVM 차트)의 ECharts 옵션을 `lib/charts/{riskOptions,evmOption}.ts`로 뽑아 화면과 보고서가 같은 옵션을 쓴다. 화면 동작은 바뀌지 않았다.
- **필요한 결과 만들기**(`lib/report/make.ts`): 위험 분석은 위험 분석 → 민감도(OAT) → 시나리오 비교를 기존 액션으로 차례로 실행하고, 이미 최신이면 다시 실행하지 않는다. 불확실한 입력이 없으면 이유를 알린다. **재예측·조치 시험은 판단이 필요한 일이라 자동으로 만들지 않는다**(통제 탭에서 직접).
- 상태 보고서에는 **보고 기준일 선택**이 있다(기본: 마지막 보고일). 상태 `reportDay`는 `reportStore`에 둔다.

## 2. 시험

전체: desktop 1,169(+9) 통과. 타입 검사·`npm run check` 통과.

- `stores/reportRiskStatus.test.ts` 9개(실제 스토어 + 실행기 목): 설정이 없을 때의 상태(입력 na·결과 missing·비교 na), 결과가 있을 때 가정 안내·목표 절, 시드를 바꾸면 stale이 되어 숫자가 빠지고 `includeStale`로 다시 실리는 것, 만들기가 위험 분석·민감도를 채우고 두 번째에는 실행하지 않는 것, 입력이 없을 때 이유, HTML 렌더링(차트 SVG 포함), 상태 보고서의 지표·차트·재예측(실적이 바뀌면 stale), 보고일 선택, 모든 종류가 오류 없이 만들어지는 것.
- 시험에서 찾은 결함: 비교 대상이 2개 미만인데 `riskCompare`가 "없음"이어서 "만들기"가 켜졌다 → "해당 없음"으로 고침.

## 3. 확인하지 못한 것

- 위험·상태 보고서의 **실제 PDF 쪽 모양**은 아직 보지 않았다(R4의 Electron 확인에서 함께 본다).
- 재예측 어댑터가 없는 모델의 상태 보고서는 재예측 절이 "해당 없음"이 되는 경로를 코드로 처리했지만 별도 시험은 없다.
