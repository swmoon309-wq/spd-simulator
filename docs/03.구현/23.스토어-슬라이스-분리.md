## 2. 정한 것

- **import 경로는 그대로다.** `appStore.ts`가 `useAppStore`와 기존에 내보내던 타입·선택자(`RunRecord`, `Notice`, `busyReason`, `selectXxxStale`, `selectIsDirty`, `UNTITLED` 등)를 모두 다시 내보낸다. 이 파일을 부르는 49개 파일과 시험은 한 줄도 바꾸지 않았다.
- **슬라이스끼리는 `get()`으로 서로를 부른다.** 예: 프리셋 적용(보정 슬라이스)이 `addScenario`(시나리오 슬라이스)를 부른다. 전체 상태 형식이 하나라서 타입 검사가 이를 확인한다.
- **스토어 밖의 가변 상태는 `rt`에 모았다.** 원래 모듈 변수(`handle`, `runSeq`, `batchControl`, `extremesCancel`, `calibCancel`, `riskControl`, `resultCache` 등)였고, 프로젝트를 열거나 새로 만들 때 번호를 되돌리고 실행을 멈추려고 여러 영역이 함께 쓴다. 한 슬라이스에 넣을 수 없어 별도 모듈로 뺐다. 값과 쓰임은 그대로다.
- `stopRunning`은 `useAppStore.subscribe` 대신 슬라이스 생성 함수가 받는 `api.subscribe`를 쓴다(같은 스토어, 순환 import를 피한다).
- 기능을 바꾸거나 합치지 않았다. 멤버 본문은 원본 그대로 옮겼고 모듈 변수 참조만 `rt.`로 바뀌었다.

## 3. 방법과 확인

원본을 멤버 단위로 나누는 일회용 스크립트로 옮겨 손으로 옮기다 생길 오타를 피했다(스크립트는 저장소에 두지 않았다). **한 번에 하나씩 슬라이스를 빼고 매번 검사했다.**

| 단계 | 상태 | 타입 검사 | desktop 시험 |
|---|---|---|---|
| 1 | 기반 파일(`runtime`·`initial`·`busy`·`state`)만 만들고 모든 멤버는 임시 `legacySlice`에 둠 | 통과 | 788 통과 |
| 2 | 위험 분석 분리 | 통과 | 788 통과 |
| 3 | 검증·보정 분리 | 통과 | 788 통과 |
| 4 | 시정 조치·제어 분리 | 통과 | 788 통과 |
| 5 | 시나리오 분리 | 통과 | 788 통과 |
| 6 | 실험·프로젝트 분리(임시 `legacySlice` 삭제) | 통과 | 788 통과 |

마지막에 `npm run check`(analysis 564, models 189, engine 192, desktop 788)와 `npm run build`가 통과했다. 또 스토어의 키가 원본과 같은 132개이고(상태 41 + 액션 91) 모두 값이 있음을 일회용 시험으로 확인했다(시험 파일은 지웠다).

확인하지 못한 것: 이 변경은 상태 조립 방식만 바꾸어 **Electron E2E는 다시 돌리지 않았다**(스크립트가 저장소 밖에 있다). 화면 코드는 건드리지 않았고 스토어 단위 시험이 영역별로 이미 있어 위험은 낮다고 보지만, 다음 기능을 얹기 전에 E2E 한 번을 권한다.

## 4. 남은 기술 부채

- 컴포넌트 단위 시험 환경 없음(상태 선택자가 원시값이어야 한다는 규칙을 시험으로 잡지 못한다).
- E2E 스크립트가 저장소 밖 임시 폴더에 있다.
- 슬라이스 하나가 여전히 300줄 안팎이다(`controlSlice`·`riskSlice`). 지금은 더 쪼갤 이유가 없다.
