## 1. 범위 결정

**COM-03 설정은 테마만 구현했다**(사용자 결정). 기능 목록은 "단위, 언어(한/영), 테마"인데, 화면 문구가 모두 한국어로 코드에 들어 있어 영어 UI는 문구를 분리하는(i18n) 별도 작업이 필요하고, 시간 단위(일)·규모 단위(태스크)는 기능 목록 7장에서 고정한 결정이다. 그래서 설정 창에 그 사실을 적고 선택지는 두지 않았다. 영어를 하려면 i18n 분리부터 따로 계획한다.

## 2. COM-03 설정(테마)

| 항목 | 내용 |
|---|---|
| 값 | `system`(운영체제 따르기, 기본) · `light` · `dark` (`shared/settings.ts`) |
| 저장 | **사용자별** `userData/settings.json`(main의 `SettingsService`). 프로젝트 파일에는 넣지 않는다. 파일이 없거나 깨졌거나 값이 올바르지 않으면 기본값, 모르는 키는 버린다. 저장하지 못해도 이번 실행에서는 바뀐 설정을 쓴다. |
| 적용 | 문서의 `data-theme`(`light`/`dark`, `system`이면 속성 없음)와 CSS 변수. 운영체제가 어두워도 "밝게"를 고르면 밝게 보이도록 `:root:not([data-theme='light'])`로 운영체제 설정을 따르고, "어둡게"는 `:root[data-theme='dark']`로 고정한다(두 곳의 색 값은 같다). **차트도 따른다**(`useDarkMode`가 설정을 본다). |
| 운영체제 쪽 | main이 `nativeTheme.themeSource`를 같은 값으로 맞춰 대화상자·메뉴도 어울리게 한다. |
| 깜빡임 방지 | 마지막으로 쓴 테마를 `localStorage`에 두고 앱이 설정을 읽어 오기 전에 먼저 적용한다(`main.tsx`). 브라우저(개발용)에서는 이 캐시만 쓴다. |
| 화면 | 헤더의 **설정** 버튼 또는 메뉴(Cmd/Ctrl+,) → 설정 창의 테마 라디오. 바로 적용·저장된다. |

코드: `shared/settings.ts`, `main/settingsService.ts`, `stores/settingsStore.ts`, `lib/theme.ts`, `components/SettingsDialog.tsx`, `components/chartTheme.ts`, `styles.css`. IPC `settings:get|set`(보낸 값은 main에서 다시 검증).

## 3. COM-06 도움말

헤더의 **도움말** 버튼, 메뉴, F1로 여는 창(`components/HelpDialog.tsx`). 앱 안에 들어 있어 네트워크가 필요 없다(NFR-03).

| 탭 | 내용 |
|---|---|
| **용어 설명** | 40개 용어를 영역별로 풀이: 모델과 실행(누적량·흐름·되먹임·dt·시드·스텝·Brooks 법칙…), 시나리오(기준·채택 계획·오래됨), 통제(PV·EV·AC·BAC·CPI·SPI·κ·재예측·개정), 위험 분석(몬테카를로·분포·백분위수·민감도·수렴·공통난수), 모델 검증(NRMSE·Theil 분해·NSE·극단 조건·교란·보정·프리셋). 이름·약어·풀이로 검색한다(`searchGlossary`). **이 앱의 화면에서 쓰는 뜻으로 적었고**, 모델에서 확인한 것(예: 일정 압박이 오류 발생과 품질보증 비율에 미치는 영향, 분포 종류, 최대 스텝 수)만 담았다. |
| **예제 안내** | 사용 시나리오를 화면 순서로 푼 4개 안내: Brooks 법칙 보기, 새 프로젝트로 계획·시나리오 비교, 진행 중인 프로젝트 통제, 불확실성·모델 신뢰도 확인. "홈에서 예제 열기" 버튼. |
| **단축키** | 메뉴와 **같은 정의**(`shared/shortcuts.ts`)에서 만든 표. macOS는 ⌘⇧ 기호, 그 밖에는 Ctrl+Shift+ 형식. |
| **앱 정보** | 버전·실행 환경(데스크톱 앱에서만)과 모델의 근거 문헌. |

내용은 `lib/help.ts`의 데이터라 고치기 쉽고 시험이 형식을 지킨다(용어 중복 금지, 풀이 필수, 영역·핵심 약어 존재).

## 4. COM-01 앱 메뉴

메뉴 구성(Windows·Linux 기준, macOS는 앞에 앱 메뉴가 붙고 설정이 거기에 있다): **파일 · 편집 · 보기 · 프로젝트 · 모델 · 시뮬레이션 · 분석 · 제어 · 보고서 · 창 · 도움말**.

| 메뉴 | 항목 |
|---|---|
| 파일 | 새 프로젝트, 열기…, 저장, 다른 이름으로 저장…, (설정…), 종료/창 닫기 |
| 편집 | 실행 취소, 다시 실행, 잘라내기·복사·붙여넣기·모두 선택 |
| 보기 | (개발 중에만 다시 불러오기·개발자 도구), 확대·축소, 전체 화면 |
| 프로젝트 | 홈(요약·최근 프로젝트·예제) |
| 모델 | **모델 목록(라디오, 현재 모델 표시)**, 입력값을 기본값으로 되돌리기 |
| 시뮬레이션 | 실험 화면, 실행, 일시정지/계속, 스텝(1일 진행), 리셋, 중단 |
| 분석 | 시나리오 비교, 위험 분석, 모델 검증 |
| 제어 | 통제(Earned Value) |
| 보고서 | "보고서 만들기… (준비 중)" — 보고서는 4차 범위라 **쓸 수 없는 항목**만 있다. 메뉴 구성은 갖췄다. |
| 도움말 | 도움말(용어 설명), 예제 안내, 단축키, (앱 정보) |

**단축키:** 화면 이동 Cmd/Ctrl+1~6(홈·실험·시나리오·통제·위험 분석·검증), 실행 Cmd/Ctrl+Enter, 일시정지/계속 Shift+Cmd/Ctrl+P, 스텝 Cmd/Ctrl+., 설정 Cmd/Ctrl+,, 도움말 F1, 그 밖에 기존의 새로 만들기·열기·저장·실행 취소/다시 실행. 같은 키를 두 명령에 쓰지 않는다(시험).

**구조**
- main은 **명령 이름만** renderer로 보낸다(`shared/menuCommands.ts`의 `MenuCommand`: `tab:<화면>`, `model:<id>`, `help:<주제>`, `run`·`step`·`togglePause`·`reset`·`cancel`·`resetParams`·`settings`·파일·편집 명령). 처리는 renderer의 `lib/commands.ts`(`handleMenuCommand`)가 한다. 모르는 화면·모델·주제·명령은 무시한다.
- 모델 목록은 renderer의 카탈로그에 있어, 화면이 `menu.update({ models, modelId })`로 알리면 main이 메뉴를 다시 만든다(모델이 바뀌어도 같다).
- 메뉴 구조는 Electron에 의존하지 않는 순수 함수(`main/menuTemplate.ts`)라 시험한다. `main/menu.ts`는 그것을 `Menu`로 만든다.
- 화면 이동·대화상자는 `stores/uiStore.ts`(탭, 열린 대화상자)로 옮겼다. 앱의 탭 상태는 더 이상 `App`의 로컬 상태가 아니다.
- 시뮬레이션 명령은 실험 화면으로 옮겨서 결과가 보이게 하고, 실행 중이 아닐 때 일시정지/계속은 아무것도 하지 않는다. 입력 오류가 있을 때의 동작은 화면의 버튼과 같다(스토어 액션이 같은 검사를 한다).
- 사용자에게 보이는 앱 이름은 상수(`APP_TITLE`)로 쓴다. 앱 이름(`app.setName`)을 바꾸면 사용자 데이터 폴더가 바뀌어 자동 저장본·최근 목록·설정을 잃으므로 바꾸지 않았다.

- `lib/theme.test.ts`, `lib/help.test.ts`(내용 형식·검색), `stores/settingsStore.test.ts`(적용·캐시·잘못된 값·저장 실패·브라우저·읽기 실패), `stores/commands.test.ts`(화면 이동, 모르는 명령 무시, 대화상자, 모델 전환, 실행·스텝·일시정지·리셋·중단, 입력 초기화, 실행 취소/다시 실행).
- **브라우저**: 설정에서 어둡게를 고르면 배경이 `rgb(23,24,27)`·`color-scheme: dark`, 밝게면 `rgb(244,245,247)`, 시스템이면 속성이 지워진다. Esc로 닫힌다. 도움말은 40개 용어, `cpi` 검색에 CPI·κ 두 건, 단축키 표(⌘ 기호), 예제 안내 4건.
- **Electron 앱**(CDP): 새 API 3개가 노출되고, 앱 정보(버전 0.1.0, Electron 44.9.1), 설정 읽기·쓰기, **잘못된 값(`<b>x</b>`, 모르는 키)은 무시**, `settings.json` 저장, 테마를 어둡게 바꾸면 `prefers-color-scheme`이 dark(nativeTheme 연동)였다.
- **확인하지 못한 것:** 운영체제 메뉴 막대의 실제 모양과 항목 클릭은 시스템 UI라 누를 수 없었다(화면 제어 권한 없음). 메뉴 구조·명령은 순수 함수 시험과 `handleMenuCommand` 시험으로 확인했으므로 메뉴를 직접 열어 한 번 훑어보길 권한다.
