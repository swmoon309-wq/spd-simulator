## 1. 구현

### 모델 검증 절 (RPT-06)

네 종류의 보고서 모두에 **"모델 검증"** 절이 있다(`lib/report/validationSections.ts`). 보고서를 만들 때마다 지금의 결과로 검증 기록을 새로 만들어(`buildRecordFromState`, 검증 탭의 "기록 만들기"와 같은 함수) 싣는다. 저장해 둔 마지막 기록(`validation.report`)을 쓰지 않는 까닭은 그것이 입력이 바뀐 뒤에는 오래된 것일 수 있기 때문이다.

| 내용 | 설명 |
|---|---|
| 고정 안내 | "검증은 증명이 아닙니다. 합격·불합격을 판정하지 않습니다" 콜아웃 |
| 데이터 비교 | 데이터셋별 시간 단위·시간 이동·종합 J·허용 기준·완료 시점 오차, 열별 지표 표(정규화 RMSE·MRE·NSE·추세·기준 안/밖) |
| 극단 조건 시험 | 개수별 통과·주의·실패, 허용 범위 안의 오류(모델 결함 후보) |
| 구조 점검 | S1~S6 결과 표와 확인할 항목 |
| 체크리스트 | 사람이 적은 상태·메모(전체 항목, 미확인 포함) |
| 보정 프리셋 | 파라미터·보정/검증 구간 J·비율 |
| **확인하지 못한 것** | **항상** 싣는다: 비교하지 않은 데이터, 실행하지 않았거나 **입력이 바뀌어 오래된** 시험(싣지 않고 그 사실을 적는다), 구조 점검이 밝힌 "확인하지 못한 것", 미확인 체크리스트 수, 통합 모델은 보정되지 않았다는 사실 |

- 기록에 넣을 내용이 하나도 없으면 절은 "없음"이고 기본으로 꺼진다(켜도 이유만 나온다). 내용이 있으면 "최신"이라 기본으로 켜진다.
- `ReportState.validation`(기록과 `RecordContents`)을 `reportStateFrom`이 채운다.

### 보고서 설정 저장 (RPT-07)

종류·제목·작성자·절 선택·"오래된 결과 포함"·차트 크기를 **프로젝트 파일의 `reports` 필드**에 저장한다(결과는 저장하지 않는다). 보고 기준일은 화면 상태라 저장하지 않는다.

| 구성 | 내용 | 코드 |
|---|---|---|
| 파일 스키마 | `reports`(선택, 없으면 null) — 제목 ≤200, 작성자 ≤100, 절 선택 ≤40개, 차트 크기 normal/large. **스키마 버전은 올리지 않았다**(risk·validation과 같은 방식의 선택 필드라 이전 파일은 그대로 열린다) | `shared/projectFile.ts` |
| 설정 모델 | 기본값·`reportsToFile`(처음 값이면 null)·`sanitizeReports`(모르는 종류는 계획서 요약으로, 모르는 절 선택은 버리고 **경고**) | `lib/reportSettings.ts` |
| 스토어 | 설정은 앱 스토어의 `reports`(`reportSlice`)로 옮겼다. 그래서 **수정됨 표시·실행 취소/다시 실행("보고서 설정 변경")·자동 저장·복구**가 다른 입력과 똑같이 동작한다. `reportStore`에는 보고 기준일만 남았다 | `stores/slices/reportSlice.ts`, `stores/history.ts`, `lib/projectApply.ts`, `projectSlice.ts` |
| 보고서 종류 변경 | 종류를 바꾸면 절 선택은 처음 값으로 돌아간다(같은 종류를 다시 고르면 그대로) | `reportSlice.ts` |
| 절 식별자 | `SECTION_IDS` 상수 배열에서 `SectionId`를 만든다(저장된 값을 검사할 수 있도록) | `shared/reportDoc.ts` |

### 도움말
용어집에 "보고서" 묶음 5개(보고서, 이 보고서를 읽을 때, 만든 조건, 절의 자료 상태, 모델 검증 절)를 더했다.

## 3. 확인하지 못한 것·남긴 것

- **"종합" 보고서(네 보고서를 한 문서로)**는 설계에서 선택 사항으로 두었고 구현하지 않았다. 지금은 종류마다 따로 만들고 "모델 검증" 절은 어느 종류에든 붙일 수 있다.
- 보고서 탭의 **새 설정(저장·복구)을 실제 앱 화면에서 클릭해 본 것은 아니다**: 스토어·파일 왕복은 시험으로, 화면 구성은 앞 단계에서 확인했다. 저장 대화상자는 시스템 UI라 앱 안에서 눌러 보지 못한다(다른 저장 기능과 같은 방식).
- 막대 차트의 기준선 라벨이 축 숫자와 겹치는 경우가 있다(앞 단계 [30](30.보고서-PDF.md) §3과 같은 후속).
