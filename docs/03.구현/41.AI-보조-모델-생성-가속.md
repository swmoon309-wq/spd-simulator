# AI 보조 통합 프로젝트 모델 — P0 생성 가속

기준일 2026-10-29. 설계 [10](../02.설계/10.AI-보조-개발-생산성-요인과-모델-확장설계.md)의 **P0**를 구현했다. 확정한 결정(2026-10-29): D1 새 내장 모델, D2 기본값은 "영향 없음", D3 신입·숙련자 2레벨, D8 오류 종류는 나누지 않는다.

## 1. 무엇을 만들었나

- **새 내장 모델 `integrated-project-ai`**([integrated-project-ai.json](../../packages/models/src/integrated-project-ai.json)): 통합 프로젝트 모델의 사본에 아래만 더했다. 기존 모델은 건드리지 않았다.
- 상수 4개(모두 기본값이 영향 없음):

| 상수 | 기본 | 범위 | 뜻 |
|---|---|---|---|
| `ai_adoption` | 0 | 0~1 | AI 적용 비율 x |
| `ai_gen_pro` | 1 | 0.5~3 | 숙련자의 생성 가속 g. 1 미만이면 느려짐(RCT) |
| `ai_gen_new` | 1 | 0.5~3 | 신입의 생성 가속 |
| `ai_iter_overhead` | 0 | 0~2 | 반복·재시도 오버헤드(수작업 시간 대비) |

- 변수 2개와 식 1개 변경:

```
ai_gen_mix       = IF(hr_total > 0.001, (hr_pros * ai_gen_pro + hr_new * ai_gen_new) / hr_total, ai_gen_pro)
ai_dev_time_mult = (1 - ai_adoption) + ai_adoption * (1 / ai_gen_mix + ai_iter_overhead)
prod_productivity = prod_potential * prod_loss_mult * prod_calibration / ai_dev_time_mult      // 기존에서 나누기만 추가
```

- 가속은 AI로 하는 부분에만 걸린다(암달의 법칙). 인원이 0이어도 NaN이 나지 않게 `IF`로 막았다.
- **새 Level은 없다.** 재예측·시정 조치 시험이 같은 어댑터를 그대로 쓴다(`integratedAiReforecast`, 조치 3종 모두 지원).

## 2. 앱 연결

- 카탈로그 [integratedAi.ts](../../apps/desktop/src/renderer/src/catalog/integratedAi.ts): 통합 프로젝트 항목을 펼쳐 쓰고 "AI 보조 개발" 파라미터 묶음, 변수 2개, 프리셋 3개(이름에 **"예시"**를 붙여 보정된 값이 아님을 밝힘)를 더했다. 모델 선택의 "프로젝트 모델" 묶음에 통합 프로젝트 바로 뒤에 나온다.
- 도움말 용어 3개(AI 적용 비율, 생성 가속, 반복·재시도 오버헤드), 보고서의 모델 안내·검증 절의 "확인하지 못한 것"·위험 분석의 가정 문구에 이 모델의 한계(보정 전, AI 항목은 문헌 범위의 가정, 검토·오류·부채·계획 오판은 아직 없음)를 넣었다.
- 모델 편집기의 구조 팔레트는 카탈로그에서 템플릿을 만들어, 이 모델도 **라이브러리 템플릿으로 자동 포함**된다(기존 시험이 비트 동일성까지 확인).
- 내장 예제도 카탈로그를 따라 이 모델의 예제가 생긴다.

## 3. 시험

전체: analysis 566, models **252**(+13), engine 286, desktop **1,580**(+38) 통과. 타입 검사 통과.

- `integratedAi.test.ts`(models) 13:
  - **불변식**: 적용 비율 0이면 기존 모델의 **모든 변수(100개 이상)가 비트 동일**. 가속·오버헤드를 바꿔도 적용 비율 0이면 같음. 가속 1·오버헤드 0이면 적용 비율이 달라도 같음. 인원·규모 변화에서도 같음. 인원 0에서 NaN 없음.
  - **방향(인원 고정)**: 가속이 클수록·적용 비율이 클수록 단조롭게 빨라짐, 가속 < 1이면 늦어짐, 오버헤드가 이득을 깎고 (1/g + 오버헤드 = 1)이면 기본과 같음, 숙련자·신입 가속을 따로 줄 수 있음.
  - 선언한 불변식 전부 AI를 켜도 위반 없음(점검 개수가 기존 모델과 같은지도 확인).
- `integratedAi.test.ts`(desktop) 7: 카탈로그 위치, 파라미터 묶음과 기본값, 범위, 기본값 실행이 기존 모델과 같음, 프리셋 범위, 진척·지표 공유와 재예측·조치 지원, 보고서 문구.
- 모델 편집기 템플릿 시험의 개수를 7개 → 8개로 고쳤다.
- 실제 브라우저: 모델 선택에서 전환하면 "AI 보조 개발" 묶음의 4개 파라미터와 새 변수 2개가 보이고 콘솔 오류가 없다.

## 4. 알게 된 것 (중요)

**인력이 일정에 따라 정해지면 가속이 클수록 완료일이 단조롭게 줄지 않는다.** 기본 설정에서 완료일은 AI 없음 314일, 가속 1.25배 305일, 1.5배 306일, 2배 309일, 3배 301일이다(모두 AI 없음보다 빠르지만 순서가 일정하지 않다). 최대 인원도 8.4명에서 4.9~7.0명으로 **줄어든다.**

- 원인은 모델의 계획 섹터다. 필요 인력 = 남은 일 ÷ 남은 시간이라, 속도가 오르면 필요 인력이 줄고 채용이 억제된다(기존 되먹임).
- 인원을 고정하면 124 → 116 → 95일처럼 **단조롭게** 줄고 공수는 거의 같다.
- 문헌의 "개인 속도 향상이 조직 결과로 그대로 이어지지 않는다"(Queue & AI, SLR)와 같은 방향의 거동이라 **결함이 아니라 모델의 성질**로 보고 시험에 그대로 적었다(단조를 기대하지 않는 시험, 팀이 작아지는지를 확인).
- 이 때문에 P0만으로도 "AI로 일정이 얼마나 줄어드나"의 답은 **인력 정책에 크게 달라진다.** 해석할 때 인력을 고정한 비교와 일정에 따라 정하는 비교를 구분해야 한다.

## 5. 아직 없는 것

- 검토 부하·깊이·오류 탈출(P1), 규모 의존 검출 효율·탈출 하한·후기 발견 배수(P1b), 기술 부채(P2), 인식과 실제의 차이(P3), 비용 층(P4).
- 위험 분석의 분포 입력은 파라미터 목록을 따르므로 AI 4개도 분포로 줄 수 있지만 **문헌 범위를 채운 분포 프리셋은 아직 없다**(D2: 도움말·분포 예시).
- 기능 점수 당 생산성 같은 조직 지표를 받아 AI 파라미터로 환산하는 보정 화면은 따로 없다. 기존 검증(VAL-05) 보정에 AI 파라미터를 고르게 하는 방식으로 쓸 수 있는지는 확인하지 않았다.
- 변경은 커밋하지 않았다.
