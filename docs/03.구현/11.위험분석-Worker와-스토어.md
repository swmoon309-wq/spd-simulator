# 구현: 위험 분석의 Worker 실행과 스토어 (RSK-02)

- 구현한 설계: [06.위험분석설계.md](../02.설계/06.위험분석설계.md) 4장(실행), 구현 순서 3
- 상태: Worker·스토어·상호 배제 완료. **화면(순서 4~5)과 파일 저장(순서 6)은 아직 없다**
- 바탕: 계산 모듈은 [10](10.위험분석-분포와-집계.md)
- 위치: `apps/desktop/src/renderer/src/{engine,lib,stores}`

## 1. Worker 메시지

`engine/protocol.ts`에 추가했다(2차의 `reforecast` 요청과 같은 방식).

| 방향 | 메시지 | 내용 |
|---|---|---|
| 요청 | `montecarlo` (`McRequest`) | `id`, `modelId`, `overrides`(대상 시나리오의 유효 파라미터), `options{end, dt}`, `inputs`(`InputSpec[]`: 이름, 분포, 파라미터의 허용 범위, 정수 여부), `n`, `seed`, `band?{variable}` |
| 응답 | `mcProgress` | `completed`, `total`, 가끔 `snapshot`(지금까지 끝난 반복의 `McResult`) |
| 응답 | `mcDone` | `result: McResult`, `canceled` |
| 응답 | `error` | 입력 검사 실패, 알 수 없는 모델 등(기존 메시지) |
| 요청 | `cancel` | 기존 메시지. Worker가 id로 취소 집합에 넣는다 |

**`executeMonteCarlo`**(`engine/execute.ts`, 의존성을 주입받아 Worker 없이 시험): 카탈로그에서 모델의 `kpiSpecs`를 가져와 `McRunner`를 만들고 반복을 하나씩 진행한다. **12ms가 지나면 이벤트 루프에 양보**해 취소 메시지를 처리한다. 양보할 때 진행 메시지를 **60ms 이상** 간격으로 보내고, 그중 **400ms 이상** 간격일 때만 중간 결과(`runner.result()`)를 붙인다(큰 N에서 복사 비용을 제한). 끝나면(또는 취소되면) 끝난 반복의 결과를 `mcDone`으로 보내며 결과의 `Float64Array`·`Uint8Array` 버퍼를 전송한다. 입력이 잘못되면 `McError`의 한국어 메시지를 `error`로 보낸다(`validateMc`가 시작 전에 모두 거른다).

`engine/engineClient.ts`: `startMonteCarlo(req, onProgress) → {promise, cancel}`. 요청 id로 응답을 짝짓고, `mcDone`이면 `{result, canceled}`로 resolve, `error`면 reject한다(취소는 오류가 아니라 resolve). Worker 자체가 죽으면 대기 중인 모든 요청을 reject한다.

## 2. 위험 설정과 검사 (`lib/risk.ts`)

| 항목 | 내용 |
|---|---|
| `RiskSettings` | `scenarioId`(기준 `@base` 또는 시나리오 id), `n`(기본 500), `seed`(기본 1), `inputs`(`{name, dist}`), `targets`(`McTarget[]`), `bandVariable` |
| `riskBaseParams` | 대상의 유효 파라미터(기준이면 기본 설정, 시나리오면 `effectiveParams`). 대상이 없으면 null |
| `buildInputSpecs` | 입력에 카탈로그의 허용 범위(`min`·`max`)와 정수 여부를 붙여 `InputSpec`으로 만든다 |
| `riskProblems` | 실행 전 검사(한국어 문장 목록): 대상 있음, 반복 수 20~5,000 정수, 시드 0~2³¹−1 정수, 입력 ≥ 1, 입력이 이 모델의 폼 항목인지·이름 중복, 분포 검증(허용 범위 안), 시계열 변수가 모델 변수인지, 목표 지표가 모델 지표인지와 목표 값이 유한한지 |
| `riskKey` | 결과를 만든 입력의 식별 키: 모델 id·버전, **대상의 유효 파라미터(이름순 정렬)**, 종료 시각·dt, 반복 수, 시드, 입력, 시계열 변수. **목표는 넣지 않는다**(결과를 다시 계산하지 않고 해석만 바꾼다) |
| 상수 | 반복 수 하한 20(분석 계층은 1부터), 입력 최대 12개 |

## 3. 스토어 (`stores/appStore.ts`)

### 상태

- `risk: RiskSettings`, `riskRun: RiskRunState | null` — `{key, status: running|done|canceled|error, completed, total, result, partial, error}`. 결과는 파일에 저장하지 않고, 수정 상태(dirty)에도 넣지 않는다(설정의 파일 저장은 순서 6).

### 액션

| 액션 | 동작 |
|---|---|
| `setRiskScenario`, `setRiskIterations`, `setRiskSeed`, `setRiskTargets`, `setRiskBand` | 설정 변경. 없는 시나리오·유한하지 않은 숫자는 무시. 값의 유효성은 실행 전 검사가 알린다(입력 중인 값을 막지 않는다) |
| `addRiskInput(name)` | 폼 항목만, 중복·12개 초과는 이유를 돌려준다. 분포는 **대상의 현재 값에서 만든 삼각 템플릿**(0.8v, v, 1.3v를 허용 범위로 자르고 부동소수 잡음 제거), 정수 파라미터는 정수로 맞춘다 |
| `updateRiskInput`, `removeRiskInput`, `clearRiskRun` | |
| `runRisk()` | 다른 실행 중이면 이유(`busyReason`)를, 설정에 문제가 있으면 첫 문제를 돌려주고 시작하지 않는다. 통과하면 `riskRun`을 running으로 두고 Worker에 요청한다. 진행 메시지는 `completed`와 중간 결과(`partial`)를 갱신하고, 끝나면 `done`/`canceled`(끝난 반복의 결과, `partial`은 비움), 실패하면 `error`와 메시지. 실행하는 동안 프로젝트가 바뀌어 키가 달라졌으면 결과를 버린다 |
| `cancelRisk()` | Worker에 취소를 보낸다. 끝난 반복의 결과가 `canceled`로 남는다 |

### 오래됨 판정

`selectRiskStale(state)`: 실행 중이 아니고 결과가 있을 때, 지금 입력으로 만든 `riskKey`가 결과의 키와 다르면 true. 기본 설정의 파라미터·반복 수·시드·분포·시계열 변수·종료 시각·대상 시나리오의 값이 바뀌면 오래된 것이 되고, 목표나 차트 변수 같은 무관한 변경과 값을 되돌린 경우는 아니다. **대상 시나리오를 바꿔도 유효 파라미터가 같으면 같은 결과이므로 오래된 것이 아니다**(키가 시나리오 id가 아니라 유효 파라미터를 쓰기 때문).

### 상호 배제 (`busyReason`)

시뮬레이션(`status`), 시나리오 일괄 실행(`batch`), 위험 분석, 재예측·조치 시험 중 하나가 실행 중이면 새 실행을 시작하지 않는다. 적용 대상: `run`, `runScenarios`, `runReforecast`, `runActions`, `runRisk`. 2차 구현에서 재예측·조치 시험은 이 규칙 밖에 있었으나(같은 Worker를 써서 결과가 섞이지는 않지만 한 번에 하나라는 설계 규칙과 달랐다) 함께 묶었다. 재예측·조치 시험 자신의 "이미 실행 중" 메시지는 그대로 우선한다. UI는 위험 분석 중 `RunControls`의 실행 버튼을 비활성으로 하고 안내를 보이며, 일괄 실행 패널도 막는다.

**프로젝트 전환**: `newProject`·`loadProjectFile`은 `stopRunning`에서 진행 중인 위험 분석을 취소하고 `riskRun`이 running을 벗어날 때까지 기다린 뒤 `risk`를 기본값으로, `riskRun`을 null로 비운다.

전체: analysis 392, models 169, engine 181, desktop 581 통과. 빌드 통과. 재예측·조치 시험의 Electron 점검(기존 E2E)도 통과해 Worker 변경이 기존 실행을 해치지 않음을 확인했다.

시험 중 발견한 것: ① 템플릿이 `0.08000000000000002`처럼 부동소수 잡음을 가져 `templateDist`를 유효숫자 12자리로 정리했다. ② 시험의 "청크 게이트" 도구가 한 번에 여러 청크를 풀지 못해(분석상 당연한 동작) 취소·진행 시험을 한 청크씩 풀도록 고쳤고, 실패한 시험이 붙잡은 실행이 다음 시험을 막지 않도록 정리 단계를 추가했다.

## 5. 설계와 달라진 점

- 상호 배제 대상에 재예측·조치 시험을 포함했다(설계 4.3은 일괄·재예측·조치 시험·Monte Carlo 상호 배제라고 했으나 2차 구현이 따르지 않았다).
- 진행 메시지(60ms)와 중간 결과(400ms)의 간격은 구현에서 정한 값이다(설계는 5%·250ms 정도를 예로 들었다).
- 설정의 반복 수 하한 20은 스토어(실행 전 검사)에서 건다.

## 6. 남은 일(순서 4~6)

- "위험 분석" 탭: 입력 목록·분포 편집, 분포·목표·민감도·수렴·비교 화면, 상시 안내, 진행·취소 UI, CSV 내보내기(순서 4~5).
- 프로젝트 파일 `risk` 필드와 열 때의 정리, 변경됨 표시(순서 6).
- 민감도 실행(OAT·스윕)의 Worker 요청은 순서 5에서 추가한다(Monte Carlo 결과로 만드는 순위 토네이도는 추가 실행이 필요 없다).
