# 위험 분석: 목표 확률·민감도·수렴·비교 (설계 06의 순서 5)

설계: [06.위험분석설계.md](../02.설계/06.위험분석설계.md) 5.3~5.5, 6장, 7장(RSK-04·05·07·08). 앞 단계: [12](12.위험분석-입력과-분포-화면.md).

## 1. 구현한 것

위험 분석 탭의 결과 영역에 **[분포][목표][민감도][수렴][비교]** 탭과 공통 지표 선택을 두었다.

| 탭 | 내용 | 파일 |
|---|---|---|
| 목표 | 목표(지표·이하/이상·값, 최대 4개)를 정하면 목표별 달성 확률과 Wilson 95% 구간, 둘 이상이면 동시 달성 확률. "채택 계획으로 채우기"는 채택 계획의 완료일과 BAC를 목표로 채운다. 목표는 분포 탭의 신뢰 수준 차트에 세로선으로도 겹친다 | `TargetPanel.tsx` |
| 민감도 | (1) 한 번에 하나씩(OAT) 토네이도: 입력 분포의 P10/P90으로 바꿔 지표 변화 폭을 막대와 표로. 즉시 계산. (2) Monte Carlo 순위상관 토네이도(추가 실행 없음). 두 토네이도의 1위가 다르면 상호작용·비단조 안내. (3) 파라미터 스윕: 파라미터·범위·수준 수(3~21)를 정해 지표 곡선 | `SensitivityPanel.tsx`, `RiskCharts.tsx` |
| 수렴 | 표본을 10%씩 쌓은 누적 평균·P80 곡선, 평균 신뢰구간 반폭, 목표 반폭을 넣으면 필요한 반복 수와 충분 여부 | `ConvergencePanel.tsx` |
| 비교 | 기준·시나리오 2~3개를 골라(먼저 고른 것이 A) 같은 분포·시드로 차례로 실행. 신뢰 수준 곡선 겹치기, 시나리오별 평균·P50·P80·P90·미완료율, A 대비 "더 좋을 확률", 차이의 평균과 95% 구간, 우열이 뒤바뀌는 반복의 비율 | `ComparePanel.tsx`, `CompareChart` |

## 2. 설계와 구조

- **스토어(`appStore.ts`)**: `riskCompare`(상태·끝난 시나리오 결과·진행), `riskSens`(OAT·스윕 결과), 액션 `toggleRiskCompare`·`runRiskCompare`·`runRiskOat`·`runRiskSweep`. 설정에 `compareIds`(최대 3)를 더했다(`lib/risk.ts`). 오래됨 판정은 `selectCompareStale`·`selectOatStale`·`selectSweepStale`.
- **비교 실행**: 시나리오마다 `startMonteCarlo`를 순서대로 부른다. 입력 분포·시드·반복 수가 같고 입력 표본은 파라미터·반복의 이름에서만 유도되므로 시나리오 사이에 표본이 같다(공통난수). 취소하면 끝나지 않은 시나리오는 버리고 끝난 것만 남긴다(일부만 끝난 결과는 다른 시나리오와 쌍을 이룰 수 없다). 비교 중에도 `busyReason`이 다른 실행을 막는다.
- **민감도 실행**: Worker 없이 메인 스레드에서 즉시 계산한다(파라미터 수 × 2 + 1회, 스윕은 최대 21회). 실행 중인 다른 작업이 있으면 시작하지 않는다.
- **민감도 키**: 반복 수·시드는 영향이 없어 키에서 뺐다(`oatKey`·`sweepKey`). 입력·대상 값·실행 설정이 바뀌면 "오래됨".
- **화면 자료(`lib/riskView.ts`)**: `targetView`·`adoptedTargets`·`oatBars`·`tornadoDisagreement`·`convergenceView`·`requiredIterations`·`compareView`·`compareSentence`. 민감도 계산 도우미는 `lib/riskSensitivity.ts`.
- 쌍별 비교 문구는 지표의 방향을 따른다: 낮을수록 좋으면 "A의 완료일이 B보다 낮을(더 좋을) 확률", 높을수록 좋으면 "더 높을 확률", 방향이 없으면 "더 작을 확률".

## 3. 점검에서 찾아 고친 결함

- **무한 렌더링**: 처음에 `useAppStore(selectSensStale)`가 호출마다 새 객체를 돌려줘 민감도 탭을 열면 화면이 멈췄다(React의 `getSnapshot` 경고). 선택자를 원시값(불리언)을 돌려주는 `selectOatStale`·`selectSweepStale`로 나눠 고쳤다. 컴포넌트 시험 환경이 없어 단위 시험으로는 잡지 못했고 브라우저 점검에서 발견했다. 새 선택자는 항상 원시값을 돌려주도록 한다.
- 토네이도 표의 낮은/높은 값이 소수 17자리로 나오던 것을 `formatNumber`로 정리했다.
