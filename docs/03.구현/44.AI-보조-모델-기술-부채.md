# AI 보조 통합 프로젝트 모델 — P2 기술 부채

기준일 2026-10-30. 설계 [10](../02.설계/10.AI-보조-개발-생산성-요인과-모델-확장설계.md)의 **P2**(4.2 d, 요인 F7·F8·F10·F15)를 `integrated-project-ai`에 구현했다. P1b([43](43.AI-보조-모델-규모-의존-검출과-후기-발견-비용.md)) 위에 얹었다. Anderson 등의 기술 부채 구조(부채가 생산성을 깎는 균형 고리, 부채가 부채를 낳는 강화 고리, 리팩터링, 서비스 노후화)를 SPD 변수로 옮긴 것이며, 그 논문은 **확장 초록만 읽었고 수식과 값이 없어** 곡선과 크기는 모두 가정이다.

## 1. 무엇을 더했나

Level 4개(`td_level` + 누적 3), Rate 3개, 상수 10개. 모든 기본값은 "영향 없음"이다.

| 상수 | 기본 | 범위 | 뜻 |
|---|---|---|---|
| `td_per_task` | 0 | 0~1 | 새 태스크당 부채 발생(태스크 환산). **부채 섹터를 켜는 스위치** |
| `td_compound` | 0 | 0~5 | 부채가 부채를 낳는 정도(A1) |
| `ai_td_pro` / `ai_td_new` | 1 / 1 | 0.5~5 / 0.5~10 | AI로 인한 부채 발생 배수(숙련자 / 신입) |
| `td_refactor_fraction` | 0 | 0~0.6 | 리팩터링에 쓰는 개발 인력의 몫 |
| `td_refactor_prod` | 1 | 0.1~5 | 리팩터링 1맨데이당 상환하는 부채 |
| `td_obsolescence_time` | 3650 | 30~3650 | 서비스가 낡아 부채가 사라지는 시간(일) |
| `td_sensitivity` | 1 | 0~3 | 부채 영향 곡선의 민감도(보정용) |
| `td_base_size` / `td_initial_ratio` | 0 / 0 | 0~5000 / 0~1 | 기존 시스템 규모와 초기 부채 비율(brownfield) |

```
td_level (Level)   초기 td_initial = td_initial_ratio * td_base_size
td_gen_rate        = prod_dev_rate * td_per_task * (1 + ai_adoption * (ai_td_mix - 1)) * (1 + td_compound * td_ratio)
td_refactor_rate   = prod_mp_refactor * td_refactor_prod
td_obsolete_rate   = MIN(td_level / td_obsolescence_time, MAX(0, td_level / DT - td_refactor_rate))
td_ratio           = td_level / MAX(prod_tasks_developed + td_base_size, 1)
td_prod_mult       = GRAPH(td_ratio * td_sensitivity, [0, 0.1, 0.25, 0.5, 1], [1, 0.97, 0.88, 0.7, 0.45])   // [가정]
td_err_mult        = GRAPH(td_ratio * td_sensitivity, [0, 0.25, 0.5, 1], [1, 1.1, 1.3, 1.8])                // [가정]
prod_mp_refactor   = MIN(MAX(0, ai_avail_mp - prod_mp_qa - prod_mp_rework) * td_refactor_fraction, td_level / MAX(td_refactor_prod, 0.001) / DT)
prod_mp_remaining  = MAX(0, ai_avail_mp - prod_mp_qa - prod_mp_rework) - prod_mp_refactor        // 개발·시험 인일에서 리팩터링을 뺌
prod_productivity  = (기존) * td_prod_mult        err_gen_rate = (기존) * td_err_mult
```

- 리팩터링은 QA·재작업을 뺀 나머지에서 가져가고, **있는 부채만큼만** 갚는다. 노후화는 그 나머지를 넘지 않게 묶어 `td_level`이 음수가 되지 않는다(시험이 한 번 -3e-5를 잡아 식을 고쳤다).
- 불변식 `기존 부채 + 발생 = 부채 + 상환 + 노후`를 추가했다.
- 기존 식 변경은 셋이다. 생산성에 `td_prod_mult`, 오류 발생에 `td_err_mult`, 개발·시험 인일에서 리팩터링을 뺀다.

## 2. 앱 연결

- "기술 부채" 파라미터 묶음(10개), 그래프 변수 5개(기술 부채, 부채 비율, 생산성 배수, 오류 배수, 리팩터링 인력), 프리셋 2개(예시), 도움말 4개, 보고서 안내문(곡선·크기는 가정, 부채는 태스크 환산 점수라 조직의 정적 분석 지표와 직접 연결되지 않음)을 갱신했다.
- 단위 검사를 통과한다. 브라우저에서 묶음과 변수가 보이고 실행이 오류 없이 끝났다.

## 3. 시험

전체: analysis 566, models **281**(+11), engine 286, desktop 1,580 통과. 타입 검사 통과.

- **중립**: 부채 항목이 모두 기본값이면 P1b와 완전히 같고(P0의 "적용 비율 0이면 기존 모델과 모든 변수 비트 동일"도 통과), 부채가 없으면 다른 부채 파라미터를 아무리 바꿔도(복합 5, 민감도 3, 노후화 30일, 리팩터링 0.5 등) 결과가 같다. 부채가 없으면 리팩터링이 개발 인일을 빼앗지 않는다.
- **방향**: 부채가 쌓이면 생산성이 떨어지고 오류가 늘고 늦게 끝남, 복합 정도가 클수록 부채가 늚(A1), AI 부채 배수가 크면 늚, 신입 구성이 더 쌓음(AND 결과 3의 방향), 리팩터링이 클수록 최종 부채가 줄고 큰 프로젝트에서는 **일정도 줄임**(AND 결과 5의 방향), 노후화가 빠를수록 부채가 적음, 초기 부채는 시작부터 생산성을 깎고 늦춤, 민감도가 크면 피해가 큼.
- **AND의 핵심 결과 두 가지가 재현된다**(아래 4장): AI 적용 비율에 대한 **역U자**와, **신입 중심 팀의 적정점이 더 낮아짐**.
- **보존·안정**: 불변식이 성립하고 모든 변수가 유한.

## 4. 알게 된 것

**역U자는 재현되지만 좁은 조건에서만, 크기가 작다.** 1,600 태스크, 숙련 30명, 가속 2배, 부채 발생 0.1, AI 부채 배수 5, 복합 1로 AI 적용 비율을 0에서 1로 올렸을 때의 완료일(일):

| x | 0 | 0.125 | 0.25 | 0.375 | 0.5 | 0.625 | 0.75 | 0.875 | 1 |
|---|---|---|---|---|---|---|---|---|---|
| 완료일 | 273 | 269 | **266** | 267 | 270 | 276 | 278 | 283 | 300 |

- 적정점은 약 25%이고, 그 이득은 273 → 266일(약 3%)로 작다. 전부 쓰면 오히려 늦어진다(300일).
- 격자 탐색(2~3배 가속, 부채 발생 0.05~0.3, AI 부채 배수 1.5~5, 복합 0.5~3 등)에서는 **부채 영향이 약하면 완료일이 단조롭게 줄고**(AI가 항상 이득), **강하면 단조롭게 는다**(AI가 항상 손해). 역U자는 그 사이의 좁은 영역에서만 나왔다.
- 이는 모델 구조에서 자연스러운 결과이지만, **"AI의 적정점이 있다"는 결론이 가정한 부채 크기에 크게 의존한다**는 뜻이다. 부채 크기는 문헌에 없으므로 조직 자료로 보정해야 한다.

**재현하지 못한 것(결과 2·4).**
- AND 결과 2(짧은 프로젝트일수록 AI를 더 써도 된다): 400·800·1,600 태스크에서 적정점이 모두 25%로 같고, 400 태스크에서는 거의 평평했다. 재현되지 않았다.
- AND 결과 4(brownfield에서는 적정점이 내려간다): **반대로 나왔다.** 기존 시스템(규모 2,000, 초기 부채 30%)에서는 AI를 100% 쓰는 쪽이 가장 빨랐다(297 → 201일). 이 구조에서 부채 비율의 분모에 기존 시스템 규모를 더해, 새 부채가 큰 기존 코드베이스에 **희석**되기 때문이다. 초기 부채가 시작부터 생산성을 깎는 것(0.84배)은 재현된다. 기존 코드가 클수록 새 부채가 덜 해롭다는 이 가정이 AND의 주장과 다르다. **파라미터를 조정해 억지로 맞추지 않았고**, 분모 정의(희석 여부)를 바꿀지는 열어 둔다.
- 위 둘은 시험에서 제외하고 여기에 기록했다.

## 5. 아직 없는 것

- P3(계획이 믿는 효과와 실제의 차이), P4(비용 층).
- AI가 리팩터링을 돕는 효과(AND: AI가 중복 탐지·문서화를 도우면 부채를 일부 상쇄)는 넣지 않았다.
- 부채 영향 곡선과 `td_sensitivity`는 형태만 정한 가정이다. 정적 분석 경고·복잡도 지표(He 등)와의 대응은 정하지 않았다.
- 설계 10의 7.2 오류 분리 실험은 이제 할 수 있다(P0·P1·P1b·P2가 모두 있다).
- 변경은 커밋하지 않았다.
