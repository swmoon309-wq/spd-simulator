# 위험 분석: 프로젝트 파일 저장·열기와 E2E (설계 06의 순서 6)

설계: [06.위험분석설계.md](../02.설계/06.위험분석설계.md) 8장, 10~11장. 앞 단계: [13](13.위험분석-목표-민감도-수렴-비교.md).

## 1. 구현한 것

위험 분석 설정을 프로젝트 파일(`*.spd.json`)에 저장하고 열 때 복원한다. **결과는 저장하지 않는다**: 입력과 시드가 같으면 결과가 항상 같으므로(NFR-05) 열고 다시 실행하면 된다.

| 항목 | 내용 | 파일 |
|---|---|---|
| 스키마 | `risk`(없으면 `null`). 대상, 반복 수, 시드, 입력(분포 4종), 목표, 시간 변화 변수, 비교 대상. 스키마 버전은 2를 그대로 둔다(배포 전). `risk`가 없는 기존 v2 파일과 v1 파일도 열린다. 값은 구조만 검사한다 | `shared/projectFile.ts` |
| 저장 형태 | `riskToFile`: 처음 값과 같으면 `null`, 아니면 위 필드만. 저장 여부 비교와 파일이 같은 형태를 쓴다 | `lib/risk.ts` |
| 열기 | `sanitizeRisk`: 모델에 없는 입력, 허용 범위·순서가 틀린 분포, 겹친 입력, 12개 초과, 없는 지표·시간 변화 변수·시나리오, 범위 밖 반복 수·시드를 **버리거나 처음 값으로 돌리고** 항목마다 경고한다(2차 시나리오 정리와 같은 방식). 알림 창의 "자세히"에 나온다 | `lib/risk.ts`, `lib/projectApply.ts` |
| 변경됨 표시 | `snapshotOf`에 위험 설정을 넣었다. 설정을 바꾸면 "저장 안 됨", 원래 값으로 되돌리면 다시 깨끗하다. 실행·결과는 영향이 없다 | `lib/params.ts`, `stores/appStore.ts` |
| 스토어 | `buildProjectFile`이 `risk`를 담고, `loadProjectFile`이 복원하며 실행 결과·비교·민감도는 비운다 | `stores/appStore.ts` |

## 2. 설계와 다른 점

- 설계 8장의 `bins`(히스토그램 구간 수)는 저장하지 않는다. 화면 지역 상태이고 결과를 보는 방법일 뿐이다.
- 설계에 없던 `bandVariable`(시간 변화 변수)과 `compareIds`(비교 대상)를 저장한다. 둘 다 사용자가 정한 입력이다. 비교 대상은 시나리오 id이므로 열 때 존재하지 않는 id는 뺀다.
- 입력 상한(12), 비교 상한(3)은 스키마(`shared`)와 앱(`lib/risk.ts`)에 같은 값을 두었다. `shared`는 zod만 쓰기 때문에 시험이 일치를 확인한다.

## 4. Electron E2E (임시 작업 폴더의 스크립트)

앱을 `--inspect`와 `--remote-debugging-port`로 띄워 renderer를 CDP로 조작하고 main의 대화상자를 가짜로 바꿔 두 스크립트를 돌렸다. 40개 점검 모두 통과, renderer·main 콘솔 오류 없음.

**파일 저장·열기 (29개)** Brooks 모델: 공칭 생산성·추가 투입 시점에 분포, 반복 40·시드 7, 완료일 ≤ 280일 목표, 시간 변화 변수 지정 → 실행(P50 266.5일, 목표 확률 65.0%) → 저장(파일에 설정이 있고 결과는 없음, 표시 해제) → 새 프로젝트(설정·결과 비움) → 열기(입력·반복·시드·변수·목표 복원, 결과는 없음, 표시 없음) → 다시 실행 → **같은 분위수·요약 통계·목표 확률** → 시드 변경·되돌리기의 표시 → 고친 파일(모르는 입력 `nope`, 모르는 지표 `nokpi`)은 버리고 경고 → `risk` 없는 파일은 처음 값 → 구조가 틀린 파일(`lognormal`)은 거부하고 `risk` 위치를 알림.

**비교·민감도·취소 (11개)** 시나리오와 비교 대상이 든 파일을 열면 비교 대상이 복원되고, 비교 실행(60회 × 2)에서 "추가 10명보다 기준이 낮을 확률 100.0%", 토네이도·스윕·수렴 탭, 3,000회 실행을 1.5초 뒤 중단하면 58/3,000회에서 "취소됨"이 되고 그 결과의 분위수가 남으며 다시 실행할 수 있다.

## 5. SC-07 완료 기준 확인

"파라미터 둘 이상에 분포를 주고 500회 실행해 완료일 분포와 계획 일정 내 완료 확률을 보고, 토네이도로 가장 큰 영향의 파라미터를 확인한다. 취소하면 그때까지의 결과가 남고, 저장·재열기 후 같은 결과가 나온다." → 위 E2E와 브라우저 점검(12, 13)으로 모두 확인했다.
