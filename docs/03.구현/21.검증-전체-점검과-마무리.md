# 모델 검증: 전체 점검과 마무리 (설계 07의 순서 7)

설계: [07.모델검증설계.md](../02.설계/07.모델검증설계.md) 10장(E2E), 11장(순서 7과 SC-08 완료 기준). 앞 단계: [20](20.검증-보정과-프리셋.md). 이 단계는 새 기능을 더하지 않고 **SC-08을 한 흐름으로 끝까지 확인**하고 이전 E2E를 모두 다시 돌려 회귀를 점검하며 문서를 정리했다.

## 1. SC-08 전체 흐름 E2E (28개 점검)

Electron 앱을 `--inspect`·`--remote-debugging-port`로 띄워 CDP로 조작하고 대화상자를 가짜로 교체했다(스크립트는 규칙대로 임시 작업 폴더). Brooks 모델.

| 단계 | 한 일 | 확인한 것 |
|---|---|---|
| 준비 | 앱으로 공칭 생산성 **0.13**의 실행을 만들고 CSV로 내보내 주 단위 28점 + **3% 잡음**의 "과거 프로젝트 데이터"(개발 완료 규모·누적 투입 공수 두 열)를 만든다. 모델의 현재 값은 0.1로 되돌린다 | |
| SC-08 1~3 | 가져오기 → 열 이름이 변수와 같아 **두 열 자동 연결** → 주 단위·허용 기준 0.05 → 같은 조건으로 시뮬레이션 | 지표 표(U^M·NSE 등)와 겹친 그래프·잔차 그래프, 참값을 모르는 현재 모델은 한 열이 기준 밖, **종합 J 0.0354**, 합격·불합격 표현 없음 |
| SC-08 4 | 극단 조건 → 교란 시험(스텝) → Level 변화 점검 → 구조 점검 → 체크리스트 2개 | 통과 30·주의 10·**실패 0**·정보 2, 반응 요약, 구조 점검 6개 통과와 "확인하지 못한 것", 체크리스트 |
| SC-08 5 | 두 열·공칭 생산성으로 보정(시간 분할 70/30) → 프리셋 저장 → **새 시나리오로 적용** | **3% 잡음에서도 0.13을 5% 안으로 회수**, 진단·검증 구간 J 표시, 경고 없음 |
| 효과 확인 | 대상을 보정 시나리오로 바꿔 다시 비교 | 이전 결과는 "오래됨", 다시 실행하면 **종합 J 0.0354 → 0.0003(약 118배 개선)**, 두 열 모두 기준 안 |
| 다시 점검 | 보정한 시나리오로 구조 점검·극단 조건을 다시 실행 | 대상이 바뀌면 기준에서 돌린 결과는 "오래됨"이 되어 **기록 미리보기에서 빠진다**(앱의 규칙), 다시 실행하면 들어간다 |
| SC-08 6 | 검증 기록 만들기 → 마크다운·CSV 내보내기 | 다섯 영역(데이터 비교·극단 조건·구조 점검·체크리스트·보정 프리셋)과 대상 이름(팀 A 보정), 지표·판정·메모·프리셋 값이 문서와 CSV에 모두 있음 |
| 보존 | 저장 → 새 프로젝트 → 열기 | 파일에 데이터셋·허용 기준·대상(시나리오)·체크리스트·프리셋·기록·시나리오 1개, **재열기 뒤 다시 비교한 종합 J가 같음(결과는 저장하지 않아도 재현)**, 기록·체크리스트 복원, 열기 직후 변경됨 표시 없음 |

SC-08의 완료 기준(순서 1~7): "과거 프로젝트의 실제 시계열을 가져와 변수에 매핑하고 같은 조건으로 시뮬레이션해 겹쳐 보고 오차 지표를 확인한다. 극단 조건과 구조 점검을 실행한다. 파라미터를 보정해 프리셋으로 저장하고 시나리오로 적용한다." → **모두 충족**했다.

## 2. 회귀: 모든 E2E를 새 앱으로 다시 실행

| 스크립트 | 범위 | 점검 수 |
|---|---|---|
| 위험 분석 파일 저장·열기 | 입력·실행·저장·열기·같은 시드 재현·고친 파일 | 28 |
| 위험 분석 비교·민감도·취소 | 비교 대상 복원, 토네이도·스윕·수렴, 취소 | 11 |
| 검증 데이터 비교 | 가져오기·연결·지표·기준·저장·열기·한도 | 37 |
| 극단·교란·Level 변화 | Brooks·통합 모델 전체, 중단, 모델 전환 | 30 |
| 구조 점검·체크리스트·기록 | 점검·체크리스트·기록·내보내기·고친 파일 | 40 |
| 보정·프리셋 | 회수·비유일성·취소·프리셋 내보내기/가져오기·적용 | 39 |
| **SC-08 전체 흐름** | 위 28개 | 28 |
| **합계** | | **213, 실패 0, renderer·main 콘솔 오류 없음** |

회귀에서 3개 스크립트가 각 1건 실패했다. 모두 **이후 단계에서 화면이 의도적으로 바뀐 데 따른 낡은 기대값**이었다(검증 하위 탭 수 2·3 → 4, 파일 `validation`의 키 집합이 체크리스트·프리셋·기록으로 확장, 대상 선택이 공통 머리글로 이동). 앱 결함이 아니므로 스크립트의 기대값을 현재 사양으로 갱신해 다시 돌려 통과했다.

SC-08 작성 중에 발견한 것: 처음에 기록 미리보기가 극단 조건·구조 점검을 "오래되어 넣지 않습니다"로 뺐다. 대상을 시나리오로 바꾸면 기준에서 돌린 결과가 오래된 것이 되는 **의도된 규칙**이고, 사용자는 보정한 시나리오를 다시 점검해야 한다. 앱은 맞게 동작했고 스크립트 쪽에 "다시 점검" 단계를 넣었다.

## 3. 3차 전체 상태

전체 시험: analysis 564, models 189, engine 192, desktop 779 통과(합계 1,724). 타입 검사와 빌드 통과. 구현 문서는 `docs/03.구현/01~21`이다.

| 영역 | 구현 | 문서 |
|---|---|---|
| 위험 분석 | RSK-01~05, 07, 08 완료. RSK-06(실험 설계)은 설계에서 제외. 결과 CSV 내보내기는 이 단계 뒤에 구현([22](22.위험분석-CSV-내보내기.md)) | 10~14, 22 |

검증이 모델에 남긴 변경: 엔진 스키마의 선택 항목 `invariants`와 두 모델의 보존 법칙 선언(모델 `version`은 그대로), JSON·마크다운 내보내기 IPC.
