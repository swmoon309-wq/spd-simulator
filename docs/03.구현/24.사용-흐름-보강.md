## 1. SCN-07 실행 기록을 시나리오로 저장

실험 탭의 실행 표 각 줄에 **시나리오로** 버튼을 두었다(한 방향만, 시나리오 → 실행 기록은 없다).

| 정한 것 | 내용 |
|---|---|
| 무엇을 가져오나 | 실행의 파라미터 중 **지금 기본 설정과 값이 다른 것만** override가 된다(`sanitizeOverrides`). 종료 시각·dt·시드는 시나리오가 아니라 프로젝트에 속하므로 가져오지 않는다. |
| 이름 | 실행 이름의 번호를 뗀 것(`#3 추가 투입 인원 5명` → `추가 투입 인원 5명`). 겹치거나 60자를 넘거나 `기준`이면 `실행 #3`, 그것도 안 되면 `시나리오 N`. 같은 실행을 두 번 저장해도 이름이 겹치지 않는다. |
| 메모 | `실험 탭의 실행 #3에서 저장` |
| 만들지 않는 경우 | 실행이 없음, 12개가 차 있음, **지금 기본 설정과 값이 같음**(비어 있는 시나리오를 만들 이유가 없다). 이유를 알림으로 보인다. |
| 만든 뒤 | 시나리오를 선택하고 "시나리오 '…'(으)로 저장했습니다. 시나리오 탭에서 비교하세요." 알림. 버린 값이 있으면 경고로 바뀐다. |

코드: `stores/slices/scenarioSlice.ts`의 `saveRunAsScenario(runId)`(`{ scenarioId, message }` 반환, 프리셋 적용과 같은 규약), `components/RunTable.tsx`. 시험 4개(`stores/scenarios.test.ts`).

## 2. RES-02 데이터 표

실험 탭 실행 표 아래에 접을 수 있는 **데이터 표**를 두었다. 실행·시간 간격·변수를 골라 시점별 값을 본다.

| 항목 | 내용 |
|---|---|
| 실행 | 실행 기록 중 하나(기본은 가장 최근) |
| 간격 | 1일마다, **1주마다(처음 값)**, 모든 시점(dt). 시작 시각에서 간격의 배수가 되는 시점과 **마지막 시점**의 값을 쓴다. |
| 변수 | 체크박스(모두·해제 버튼). 처음에는 그래프 변수 하나 |
| 값의 뜻 | **그 시각의 값**이다(평균·합계가 아님). Level은 "그 주 끝의 값", Rate는 "그 시점의 비율". 화면에 이렇게 적었다. |
| 크기 | 화면에는 **1,000행까지**. 넘으면 "N행 중 처음 1,000행만 표시"를 보이고, 전체 변수·전체 시점은 실행 표의 CSV로 저장한다. |

계산은 `lib/dataTable.ts`(`buildDataTable`)에 분리했다. 시험 8개(`lib/dataTable.test.ts`: 간격 선택, 마지막 시점, 시작 시각이 0이 아닌 경우, 결과에 없는 변수, 행 상한). 화면은 `components/DataTable.tsx`.

기능 목록의 "주 단위 집계"는 합·평균 같은 집계가 아니라 **주 단위 표본**으로 구현했다. 집계가 필요해지면 따로 정한다.

## 3. SIM-05·RUN-01 일시정지·스텝·리셋

| 버튼 | 동작 |
|---|---|
| 일시정지 / 계속 | 실행 중이면 **다음 청크(전체의 약 1%)가 끝난 뒤** 멈춘다. 계속은 끝까지 이어서 실행한다. |
| 스텝 | **1일**(`STEP_DAYS`, dt 0.25면 4스텝)을 진행하고 멈춘다. 실행 중이 아니면 시각 0에서 멈춘 채 새 실행을 시작해 진행한다. |
| 리셋 | 진행 중인 실행을 버리고 같은 입력으로 **시각 0에서 멈춘 새 실행**을 시작한다(스텝으로 처음부터 따라갈 때). |
| 중단 | 기존대로 실행을 버린다(기록이 남지 않는다). |

멈춰 있는 동안 화면은 "멈춤 · N일"을 보이고 그래프는 그 시점까지 그려진다. 멈춘 실행도 실행 중이므로(`status`는 `running`) 다른 실행(시나리오 일괄·위험 분석 등)은 시작할 수 없고, 새 프로젝트·열기는 멈춘 실행을 취소하고 정리한다.

구현:
- 엔진: `Simulation.reportProgress(hooks)`(진행 간격과 상관없이 지금 상태를 알림). 이미 있던 `advance`·`reset`을 그대로 쓴다. 시험 1개.
- Worker 프로토콜: `RunRequest.startPaused`, `WorkerIn`의 `control`(`pause`·`resume`·`step`). `engine/execute.ts`의 `RunControl`(`paused`, `steps`, `wake`)을 `executeRun`이 청크 사이마다 확인한다. 멈춰 있을 때 취소하면 `wake`로 깨워 그때까지의 결과를 `completed=false`로 돌려준다. `control`이 없으면 이전과 똑같이 멈추지 않는다.
- 스토어: `paused` 상태와 `pause`·`resume`·`step`·`reset`(`experimentSlice`), `engineClient.RunHandle`에 `pause`·`resume`·`step`.
- `advance`는 호출마다 시작 상태(스텝 0)를 다시 알리므로 같은 스텝의 진행 알림은 한 번만 보낸다(그래프에 겹친 점이 없어진다).

시험: `engine/execute.test.ts` 7개(멈춘 채 시작, 스텝 크기, **스텝·계속을 섞어도 한 번에 실행한 결과와 비트 단위로 같음**, 실행 중 일시정지, 멈춰 있을 때 취소, 끝까지 스텝, control 없음), `stores/stepRun.test.ts` 9개(실제 실행 루프를 한 스레드에서 돌리는 모의 클라이언트).

**알아둘 것:** 이 모델들은 한 번 실행에 약 5ms가 걸려 **일시정지 버튼을 눌러 실행 중에 멈추기는 사실상 어렵다**. 이 기능의 쓸모는 `스텝`·`리셋`으로 처음부터 한 걸음씩 따라가는 쪽이다. 일시정지는 종료 시각이나 dt를 크게 바꿔 오래 걸리는 실행에서 의미가 있다.
