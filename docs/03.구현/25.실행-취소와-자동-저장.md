## 1. COM-02 실행 취소/다시 실행

### 1.1 되돌리는 것

**프로젝트 파일에 저장되는 입력**의 편집만 되돌린다: 모델 파라미터, 실행 설정(종료 시각·dt·시드), 시나리오, 채택 계획, 실적, EVM 설정, 계획 개정, 위험 분석 설정, 검증 설정(`history.ts`의 `INPUT_KEYS`).

되돌리지 않는 것: 실행 결과(실행 표, 시나리오 일괄 실행 결과, 위험 분석·검증·보정 결과), 그래프 변수 같은 보기 설정, 시정 조치 후보. 입력이 바뀌면 결과는 이미 "오래됨"으로 표시되므로 되돌린 뒤 다시 실행하면 된다. 실행 기록(#1, #2…)은 입력 편집이 아니라 산출물이다.

### 1.2 방식

`stores/history.ts`가 스토어를 **구독**해(슬라이스는 이 파일을 모른다) 입력 필드의 참조가 바뀔 때 이전 값을 기록한다. 기록 단위는 바뀐 필드의 이전·이후 값이다.

| 규칙 | 내용 |
|---|---|
| 한 번의 동작 = 한 단계 | 같은 동기 구간(마이크로태스크 안)의 여러 `set`은 한 단계다. 예: 프리셋을 시나리오로 적용(만들기·이름·값·메모)은 하나로 되돌아간다. |
| 연속 편집은 합침 | **같은 항목**을 **1초 안에** 거푸 고치면(글자를 치는 중, 값을 올리는 중) 한 단계로 합친다. 파라미터는 항목 이름 단위이므로 다른 파라미터를 번갈아 고치면 합치지 않는다. 합치다가 처음 값으로 돌아오면 단계가 남지 않는다. |
| 같은 값은 무시 | 같은 값을 다시 넣은 것은 기록하지 않는다. |
| 다시 실행 | 되돌린 뒤 새로 편집하면 다시 실행 기록이 사라진다. |
| 한도 | 100단계. 넘으면 오래된 것부터 버린다. |
| 프로젝트를 바꾸면 비움 | 새 프로젝트·열기(`replaceProject`로 감쌌다)는 기록하지 않고 이전 기록을 지운다. 다른 프로젝트로 되돌아갈 수 없다. |
| 실행 중에는 막음 | 시뮬레이션·일괄 실행·재예측·위험 분석·검증·보정이 진행 중이면 "…끝난 뒤에 할 수 있습니다."라고 알린다(진행 중인 결과 갱신과 엇갈리지 않게). |
| 수정됨 표시 | 저장한 상태까지 되돌리면 "수정됨"이 사라진다(저장 시점의 입력과 같은지로 판단하므로 자동). |

되돌린 뒤 어긋나기 쉬운 것은 맞춘다: 선택한 시나리오가 없어지면 선택을 풀고, 검증 탭의 선택 데이터셋이 없어지면 첫 데이터셋으로 바꾸며, **채택 계획·개정·실적·EVM이 바뀌면 재예측과 조치 시험 결과를 지운다**(원래 이 동작들이 하던 정리와 같다).

### 1.3 화면

- 프로젝트 줄에 **실행 취소**·**다시 실행** 버튼. 마우스를 올리면 "실행 취소: 추가 투입 인원 변경"처럼 무엇을 되돌리는지 보이고, 기록이 없으면 비활성이다. 되돌리면 "되돌렸습니다: …" 안내가 잠시 뜬다.
- 편집 메뉴의 실행 취소(Cmd/Ctrl+Z)·다시 실행(Shift+Cmd+Z, Windows·Linux는 Ctrl+Y). 이전의 기본 undo/redo 역할을 대체했다.
- **글자 입력 칸에 초점이 있고 칸 안에 되돌릴 글자 편집이 있으면 그것을 먼저 되돌린다**(`document.execCommand`). 그 밖에는 프로젝트 입력을 되돌린다. 글자를 치다가 바로 Cmd+Z를 누르면 칸 안의 글자 편집이 되돌려지고, 그 글자 변화가 입력 값으로 다시 반영되어 기록에도 남는다.
- 브라우저(개발용)에서는 메뉴가 없어 같은 단축키를 직접 받는다. 데스크톱 앱에서는 메뉴가 보내는 명령만 쓴다(두 번 처리되지 않게).

코드: `stores/history.ts`, `lib/historyActions.ts`(`performHistory`), `components/ProjectBar.tsx`, `main/menu.ts`, `shared/ipc.ts`(`MenuCommand`에 `undo`·`redo`). 시험 16개(`stores/history.test.ts`): 되돌리기·다시 실행, 끝까지 되돌리면 깨끗, 새 편집이 다시 실행을 지움, 합치기(같은 항목·다른 항목·1초 경과·처음 값 복귀), 같은 값 무시, 한 동작 = 한 단계, 시나리오 삭제 되돌리기와 선택 정리, 실행 결과·보기 설정은 기록 안 함, 실행 중 거절, 100단계 한도, 새 프로젝트·열기가 기록을 비움, 채택 되돌리기가 조치 시험을 지움.

## 2. COM-05 자동 저장·복구

### 2.1 규칙

| 항목 | 내용 |
|---|---|
| 목적 | **비정상 종료**(강제 종료, 충돌, 정전)로 저장하지 않은 작업을 잃지 않게 한다. 사용자의 프로젝트 파일은 자동으로 덮어쓰지 않는다(저장은 계속 명시적이다). |
| 어디에 | 앱 데이터 폴더(`userData`) 아래 `recovery/autosave.json` **하나**. 프로젝트 파일 전체와 자동 저장 시각, 원래 파일 이름(경로 아님)을 담는다(`shared/recoveryFile.ts`). |
| 언제 | 20초마다 확인해 **저장하지 않은 변경이 있고 마지막으로 쓴 것과 내용이 다를 때만** 쓴다(수정 시각만 달라도 같은 내용으로 본다). 쓰기는 임시 파일에 쓰고 이름을 바꾸는 방식이라 쓰는 도중 죽어도 이전 자동 저장본이 깨지지 않는다. |
| 쓰기 실패 | 편집을 막지 않는다. 조용히 다음 주기에 다시 시도한다. |
| 언제 지우나 | ① 저장했을 때 ② 저장하지 않은 변경을 버리고 새로 만들거나 열 때 ③ 변경이 없어진 것을 다음 확인에서 알았을 때 ④ **창을 정상적으로 닫을 때**(저장했거나 "저장 안 함"을 고른 경우 포함, 동기로 지운다). 그러므로 자동 저장본이 남아 있다는 것은 정상 종료가 아니었다는 뜻이다. |
| 읽은 내용이 올바르지 않으면 | 지우고 없는 것으로 본다(오래된 프로젝트 버전은 열 때처럼 올려서 읽는다). |

### 2.2 복구 흐름

시작할 때(창이 열린 직후 한 번) 자동 저장본이 있으면 **"저장하지 않고 종료된 작업을 찾았습니다."** 대화상자가 뜬다(`'이름' — 날짜·시각에 자동 저장됨`, 버튼 **복구** / **버리기**, Esc는 복구 쪽이라 실수로 지우지 않는다).

- **복구**: 저장하지 않은 프로젝트로 연다. 파일에 연결되지 않아 저장하면 이름을 묻고, 항상 "수정됨"이며, 안내가 뜬다. 열면서 값이 조정되면 그 경고에 "자동 저장본에서 복구했습니다."가 붙는다. 자동 저장본은 다음 자동 저장·저장 때까지 그대로 둔다(그 사이에 또 죽어도 잃지 않는다).
- **버리기**: 자동 저장본을 지운다.
- 읽지 못하면 경고만 보이고 묻지 않는다. 브라우저(개발용)에서는 자동 저장이 없다.

### 2.5 실제 앱에서 확인한 것과 못 한 것

Electron 앱(빌드 결과)을 임시 사용자 데이터 폴더로 띄우고 CDP로 조작했다.

- 파라미터를 고치고 20여 초 뒤 `recovery/autosave.json`이 생겼다(고친 값 42 포함).
- 되돌려 깨끗해지고 20여 초 뒤 자동 저장본이 지워졌다. 다시 고치면 다시 생겼다.
- 앱을 `kill -9`로 죽인 뒤에도 파일이 남았고, 다시 띄우자 읽기가 `found`(값 42)를 돌려주었다.
- **못 한 것:** 시작 때의 복구 대화상자는 시스템 대화상자라 이 환경에서 누를 수 없었다(화면 제어 권한 없음). 그래서 "복구를 눌러 실제로 열린다"는 단위 시험(`recovery.test.ts`)까지만 확인했고 앱에서의 한 번은 사람이 해 보아야 한다. 방법은 아래 4장.
- 정상 종료 때 지우기(`closed` 이벤트의 동기 삭제)는 종료 뒤 파일이 없는 것을 보았으나, 같은 시각에 20초 주기가 지웠을 가능성을 배제하지 못했다.

## 4. 사람이 확인할 것(앱에서 한 번)

1. 앱을 열고 입력을 고친 뒤 **저장하지 말고** 25초 기다린다.
2. 터미널에서 앱 프로세스를 강제 종료한다(`pkill -9 -f Electron` 등).
3. 앱을 다시 연다 → 복구 대화상자가 뜨고 **복구**를 누르면 고친 값이 돌아오고 "수정됨"이다.
4. 정상적으로 닫기(저장 또는 저장 안 함) 뒤 다시 열면 대화상자가 뜨지 않아야 한다.
