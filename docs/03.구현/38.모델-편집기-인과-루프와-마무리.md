## 1. 구현

### 인과 루프 (EDT-06)

| 영역 | 내용 | 코드 |
|---|---|---|
| 링크 극성(엔진) | 수식에서 **분석한** 읽기 전용 결과. 기준 실행의 여러 시점(기본 10개)에서 입력 변수를 상대 ±1%(값이 0이면 표시 범위에 비례한 작은 값) 바꾸고, **컴파일된 수식을 다시 평가**해 출력의 부호를 본다. 모두 같은 부호면 `+`/`−`, 섞이면 `?`(비단조·상태 의존), 모든 시점에서 변화가 없으면 링크를 표시하지 않는다(센 개수만 알림). `SMOOTH`·`DELAY`는 입력을 통과시켜(초기화 모드) 평가하므로 지연을 거치는 링크도 극성을 얻고 `delayed`로 표시한다. 난수 함수는 같은 난수열로 평가해 차이가 입력에서만 온다. Level의 흐름은 `Rate → Level`을 유입 `+`·유출 `−`로 본다 | `packages/sd-engine/src/cld/causal.ts` |
| 루프 탐색(엔진) | 링크 그래프의 단순 순환. 강한 연결 요소(Tarjan)로 줄이고 **길이를 늘려 가며(반복 심화)** 찾아 상한(기본 200개)에 걸려도 남는 것이 가장 짧은 루프다. **루프 극성 = 링크 극성의 곱**: 음의 링크가 홀수면 균형(B), 짝수면 강화(R), `?`가 있으면 극성 불명. 지연 링크가 있는 루프는 표시 | `findLoops` |
| 화면 | 모델 탭 **인과 루프**(읽기 전용): 한계를 알리는 안내, 링크·루프 수와 종류별 개수, 루프 목록(B1·R2 …, 극성·길이·지연, 종류별 거르기), **선택한 루프 강조와 `a —(+)→ b —(−)→ a` 풀어 쓴 글**, 링크 극성 라벨(`+`·`−`·`?`·`//`)이 있는 그림(React Flow), **링크 표**(근거: 양 N회·음 M회) | `components/model/CausalView.tsx`, `lib/modelEdit/cldView.ts` |
| 배치 재사용 | 다이어그램의 층 배치를 `layeredLayout`으로 분리해 인과 루프 화면이 함께 쓴다 | `lib/modelEdit/layout.ts` |

**한계(화면에도 적었다)**: 극성은 기준 실행 근방의 **수치적 판단**이라 모델 전체에서 성립한다는 보장이 없고 개념 모델의 CLD와 다르다. 지연을 통과시켜 평가하므로 **지연시간 자체의 영향은 링크로 나타나지 않는다**.

### 초안 자동 저장·복구 (설계 9장 "저장", M1에서 남긴 일)

- **초안 저장 서비스**(`main/modelDraftService.ts`): 앱 데이터 폴더의 복구 폴더에 `model-draft.json` 하나(임시 파일 + 이름 바꾸기, 깨진 파일은 지우고 없는 것으로, 1.2 MB 초과 거절). IPC `draft:write·read·clear`와 preload `modelDraft`.
- **자동 저장**(`lib/modelEdit/draft.ts`): 5초마다 **수정됨(적용하지 않은 편집)**이 있고 마지막으로 쓴 것과 다를 때만 쓴다. 적용하거나 닫아 수정됨이 없어지면 지운다. 정상 종료해도 지우지 않는다.
- **복구**: 시작할 때(내 모델 목록을 올린 뒤) 초안이 있으면 **네이티브 대화상자(복구/버리기)**로 묻고, 복구하면 모델 탭에 **수정됨** 상태로 열린다. 초안은 **아직 오류가 있는 상태**일 수 있어 엔진 검증 없이 모양만 확인한다(`lenientModelDoc`).
- **E2E가 잡은 결함을 고침**: 새로 시작한 세션에서 복구한 초안을 적용해도 초안 파일이 지워지지 않았다(자동 저장이 "이번 세션에 쓴 적이 있어야" 지웠다). 디스크에 남은 초안을 알리는 표시(`noteDraftOnDisk`)로 고쳤다.

### 확인 대화상자 통일

`window.confirm`을 네이티브 확인 대화상자(IPC `dialog:confirm`, 버튼 이름을 정함)로 바꿨다(`lib/confirm.ts`): 초안 복구, 내 모델 목록에서 지우기, 편집 중인 모델을 버리고 다른 모델 열기. 브라우저(개발용)에서는 `window.confirm`으로 대신한다.

### 포트 연결 때 단위 맞춤 (E2E가 드러낸 불편)

조정 과정의 목표 포트를 `명` 단위 상수에 연결하자 템플릿의 일반 단위(`단위`)와 어긋나 단위 오류 2건이 생겼다. **포트를 단위 하나짜리 변수에 연결하면 템플릿의 일반 단위를 그 단위로 맞춘다**(`단위/일` → `명/일`). 복합 단위(`태스크/일`)는 분모에서 뜻이 달라질 수 있어 맞추지 않는다. 삽입 결과 안내에 "단위 '단위'를 '명'(으)로 맞춤"이 나온다.

## 2. 설계와 달라진 것·알게 된 것

- 설계 11장의 M5 예시("일정 압박 → 인력 투입 → 교육·소통 오버헤드 → 생산성 → 진척 → 일정 격차의 균형 고리")는 **내장 Brooks 모델에 없다**(이 모델은 인원을 고정 시나리오로 넣고 일정 압박 되먹임이 없다). 대신 Brooks에서는 **균형 고리 2개**(남은 요구사항 → 개발률 → 남은 요구사항, 신입 → 동화율 → 신입)와 책이 말한 Brooks 효과의 **인과 링크**(신입 ↑ → 훈련에 필요한 숙련 인원 ↑ → 생산 능력 ↓, 총 인원 ↑ → 의사소통 오버헤드 ↑ → 개발 능력 ↓)를 찾고, **일정 압박이 든 균형·강화 루프(지연 포함)는 통합 프로젝트 모델**에서 찾는다.
- 루프가 많은 모델(통합 프로젝트는 상한 안에서 끝나지 않는다)은 **상한(기본 200)에서 멈추고 알린다**. 짧은 루프부터 보이지만 긴 루프는 빠질 수 있다.
- 초안은 프로젝트 자동 저장본과 **별도 파일**이다(설계는 "복구 파일에 포함"이라 했으나 프로젝트와 모델 편집은 따로 열고 닫아 분리했다).

## 4. 확인하지 못한 것·남긴 것

- **네이티브 대화상자의 실제 클릭**은 접근성 권한이 없어 자동화하지 못했다. 대화상자 호출의 내용(메시지·버튼 이름)은 스텁으로 기록해 확인했고, 응답 처리는 단위 시험으로 확인했다. 모델 파일 가져오기·내보내기의 시스템 파일 대화상자도 마찬가지다.
- **프로젝트 파일을 직접 저장하고 여는 흐름**(저장 대화상자)은 E2E에서 누르지 못했다. 자동 저장본의 내용(v3·`model.custom`)과 저장·열기 단위 시험([33](33.모델-편집기-기반.md))으로 대신했다.
- 인과 루프의 극성은 **기준 실행 근방**의 판단이다. 입력 값이 크게 달라지는 시나리오에서는 달라질 수 있고, 루프가 상한을 넘는 모델은 긴 루프가 빠진다. 지연시간 자체의 영향은 링크로 나오지 않는다.
- 인과 루프 그림은 읽기 전용이며 선택한 루프의 변수 이름을 눌러 모델 탭의 속성으로 이동할 수 있을 뿐, 그림에서 편집하지 않는다(설계대로).
- 큰 모델의 인과 루프 그림(변수 143개)은 좁은 창에서 작게 보인다(확대·축소·미니맵으로 본다).
- 설계 9장의 **섹터 간 의존 요약**은 M3에서 했고, 위험·시나리오·검증 화면의 "사용자 모델은 보정·검증되지 않았을 수 있다" 상시 안내 문구(설계 8.3)는 보고서에만 있고 **그 화면들에는 아직 없다**(M0에서 남긴 일).
- 같은 id에 해시가 다른 모델이 있을 때 **어느 쪽을 쓸지 묻는 대화상자**(설계 4.1)는 만들지 않았다(파일의 것으로 바꾸고 경고).
