## 2. 설계와 달라진 것(구현 중 확인해 정함)

- **Worker 등록 메시지는 `def`만이 아니라 문서 전체를 싣는다.** 설계 5.1은 `{id, hash, def}`였으나 Monte Carlo가 Worker 안에서 `getEntry(modelId).kpiSpecs`를 쓰므로 `def`만으로는 "알 수 없는 모델"이 된다. 실제 브라우저의 Worker에서 이 오류를 보고 고쳤고, **Worker 쪽 카탈로그가 비어 있는 상태에서 실행·MC가 되는 시험**으로 고정했다(화면 쪽에서 이미 등록해 둔 상태에서는 이 결함이 가려지므로 그렇게 시험한다).
- **내용 해시는 `def`와 `spec`**(설계는 `def`만). 지표·완료 조건(`spec`)도 결과를 바꾸기 때문이다. 설명·화면 정보(`info`, `view`)는 뺀다.
- **선언형 완료일은 "조건을 처음 만족한 기록 시각"**(설계대로, 보간 없음)이라 내장 Brooks의 완료 시계 Level(격자 사이 값, 274.12일)과 **최대 dt만큼 다르다**(사본 274.25일). 실행 결과(시계열)는 비트 단위로 같고 지표만 격자 폭만큼 다르다. 시험이 이 한계를 명시한다.
- 모델 파일 가져오기·내보내기는 **새 IPC 없이 기존 JSON 저장·열기**를 쓴다(내 모델 목록만 새 IPC).
- `MenuState.models` 상한을 50에서 200으로 올렸다(내 모델이 최대 100개이므로).

## 4. 확인하지 못한 것·남긴 것

- **메뉴 항목(모델 파일 가져오기·내보내기 등)의 실제 클릭과 대화상자**는 시험하지 못했다(시스템 UI). 동작은 가짜 `window.spd`로, 메뉴 구성은 단위 시험으로 확인했다.
- **지우기는 현재 모델에만** 쓸 수 있다(메뉴가 "현재 모델" 기준). 모델 목록을 관리하는 화면은 M1의 모델 탭에서 만든다.
- 내장 모델 중 **Brooks만** 지표·완료 조건·진척을 선언형으로 옮겼다. 나머지 6개 사본은 구조·파라미터·변수·프리셋·규모만 옮기고 완료 조건·지표·진척은 비어 있다(채택·통제 비활성). 내장 지표 중에는 파라미터를 읽는 식(계획 대비 지연 등)이 있어 6종 선언형으로 옮길 수 없다. 편집기(M1)에서 사용자가 정의한다.
- 사용자 모델은 **재예측·시정 조치 시험을 지원하지 않는다**(설계대로). 위험 분석·시나리오·검증 화면의 상시 안내 문구 추가(설계 8.3)는 M1에서 모델 화면과 함께 한다. 지금은 보고서에만 있다.
- 같은 id에 해시가 다른 모델이 앱에 있을 때 **어느 쪽을 쓸지 묻는 대화상자**(설계 4.1)는 만들지 않았다: 프로젝트를 열 때 파일의 것으로 바꾸고 경고로 알린다.
