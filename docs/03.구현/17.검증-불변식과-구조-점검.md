# 모델 검증: 엔진 불변식과 구조 점검 S1~S6 (설계 07의 순서 3)

설계: [07.모델검증설계.md](../02.설계/07.모델검증설계.md) 4.3장(VAL-04의 계산 부분), 9장. 화면·수동 체크리스트·검증 기록은 순서 5, 극단 조건·교란은 순서 4.

## 1. 구현한 것

| 영역 | 내용 | 파일 |
|---|---|---|
| 엔진 스키마 | 모델 JSON의 선택 항목 `invariants`: `{ name, label, lhs[{variable, coef}], rhs[...], tolerance }`. 선형 결합 `Σ coef·변수`가 양변에서 같다는 보존 법칙. `coef`의 기본값은 1. 이름 형식, 빈 변, 0 이하 허용 오차는 스키마가 거부한다 | `sd-engine/src/model/schema.ts` |
| 컴파일 검사 | 정의되지 않은 변수, 겹치는 이름, 유한하지 않은 계수는 `ModelError('invariant')`(새 오류 종류). 선언은 결과를 바꾸지 않아 모델 `version`을 올리지 않는다 | `compile.ts`, `errors.ts` |
| 불변식 평가 | `checkInvariants(def, result, params)`: 기록한 모든 시점에서 `|좌변 − 우변|`의 최댓값, 처음 위반 시각, 허용 오차 초과 여부. 상수는 `params`(없으면 기본값), 나머지는 결과 시계열에서 읽는다. 기록하지 않은 변수는 `missing`으로 알리고 위반으로 세지 않는다 | `sd-engine/src/invariants.ts` |
| 두 모델 선언 | Brooks 1개(`requirements + developed_software = initial_requirements`), 통합 모델 4개(개발한 태스크 = QA 단계 3개 + QA 완료, 오류 보존, QA 검출 = 대기 + 수정 완료, 인식 + 미발견 + 반영 대기 = 총 태스크). 2차에서 모델 시험에 코드로 박아 둔 보존 법칙을 데이터로 꺼낸 것 | `models/src/*.json` |
| 구조 점검 | `runStructureChecks`와 점검별 함수 `checkUnits`(S1)·`checkConservation`(S2)·`checkNegativeLevels`(S3)·`checkDtSensitivity`(S4)·`checkStatic`(S5)·`checkNumeric`(S6). 결과는 `{id, title, status(통과·주의·실패·정보), summary, items, checked, notChecked}`이다 | `analysis/src/validation/structure.ts` |

## 2. 점검의 정의(구체화한 것)

| # | 확인하는 것 | 판정 |
|---|---|---|
| S1 | 모든 변수에 단위가 있는지, Level에 연결된 Rate·Auxiliary의 단위가 "Level 단위/일"인지(인원 "명"은 맨데이/일로 봄) | 단위 없음 = 주의, 연결 단위 불일치 = 실패 |
| S2 | 선언된 불변식의 최대 위반 ≤ 허용 오차 | 위반 = 실패, 기록 안 된 변수로 점검 못 함 = 주의, 선언 없음 = 정보 |
| S3 | 대상 시나리오 실행에서 Level이 −허용오차(기본 1e-6) 아래로 내려갔는지 | 있음 = 실패(변수·최솟값·시각을 알림) |
| S4 | dt와 dt/2로 실행한 지표들의 상대 변화(`|a−b|/|b|`) | ≤ 1% 통과, ≤ 5% 주의, 초과 실패. 한쪽만 계산되면 실패 |
| S5 | 쓰이지 않는 상수·보조 변수, 어디에도 이어지지 않는 Rate, 유입·유출이 없는 Level | 있음 = 주의. 출력과 `usedExternally`(화면·지표가 읽는 변수)는 쓰이는 것으로 본다 |
| S6 | 시각 0의 모든 변수가 유한한지, Level 초기값 ≥ 0인지 | 유한하지 않음 = 실패, 음수 초기값 = 주의 |

- **모든 점검이 "확인한 것"(`checked`)과 "확인하지 못한 것"(`notChecked`)을 함께 낸다.** 예: S1은 "수식 안의 항별 단위 일치는 확인하지 못함(4차 EDT-03)", S4는 "가장 작은 시간 상수 대비 dt는 수식에서 읽지 못함", S5는 "쓰이지 않는 변수에만 쓰이는 변수(전이적 사용)는 못 찾음".
- 대상 시나리오 실행이 수치 오류로 멈추면 실행이 필요한 S2·S3·S4·S6은 "시뮬레이션이 중단되어 점검하지 못했습니다"로 **실패**를 내고, 실행이 필요 없는 S1·S5는 그대로 한다(`runError`).
- S5의 `usedExternally`는 순서 5에서 카탈로그의 변수·지표가 읽는 변수를 넘겨 줄 자리이다. 계산 모듈은 카탈로그를 모른다.

## 3. 결과

두 실제 모델의 기본 실행에서 **여섯 점검이 모두 통과**한다(경고 목록 없음). Brooks는 최대 불변식 위반 1.1e-11, dt 0.25와 0.125의 완료일 차이 0.000%이고, 통합 모델은 최대 위반 1.1e-12, dt 차이 0.040%이다. 통합 모델은 인원 상한 1명·초기 인원 0명·총 태스크 1,500 시나리오에서도 중단 없이 점검되고 불변식과 Level 음수 점검을 통과한다.
